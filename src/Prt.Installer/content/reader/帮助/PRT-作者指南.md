# PRT 作者指南

> **这份指南是什么？** 一本**按任务组织**的速查手册——目录里全是「怎么加目录」「怎么加计算」「怎么加按钮」这样的问题，你带着活儿来，翻到对应一节，抄下最小可用的写法就走。它**不按语法体系排列**：想系统学，去读《PRT 教程》（从零教起）；想核对规则的精确条文，去查《PRT 简明标准》（唯一必读规范读本）；本指南只负责「干活时翻」。
>
> **每个任务一节的固定格式：** 最小写法（可直接抄）→ 常用变体 → 常见坑 → 「详见」指向简明标准的章节号。
>
> **适用版本：** PRT v4.0；受限运行后端 PRTA（含交互组件与事件，完整规范见《PRT 标准》第 19–24 章）。标注（进阶）的小节涉及计算功能——默认关闭，需工具启用（如 `--run=allow`）。
>
> **v4.0 的唯一计算原则（必读）：** PRT 文档层**没有**其它计算区——`::: set`、`::: if`、`::: loop` 与 `{{ … }}` 填空**均已废止**。一切计算都写成一段 `::: run` 里的 **PRTA** 小程序：先在正文要显示结果的地方写行内指令 `[[output:ID]]` 声明端口，再由 PRTA 用 `EMIT @ID` 把结果写进去，结果就显示在那个位置。旧写法对照见《PRT 简明标准》15.5。
>
> **名称说明：** 标准与后端历经两次更名：原名 **MDP（Markdown-Plus）**、**MDPA**，其后更名 **PSR（Perisc Standard Richtext）**、**PSRA**，现名为 **PRT（Perisc Rich Text）**、**PRTA**；文中文件后缀 `.prt`、围栏语言名 `prt` / `prta`、`lang="prt"` 均已按当前名书写。旧资料里的旧称指同一套格式。

# 一、写内容

## 1　怎么写出第一份能打开的 PRT 文档

**最小写法：**（第一行固定是 `<DocType=PRT>`；保存为「UTF-8 带 BOM」）

```prt
<DocType=PRT>
::: meta
title: "我的文档"
lang: zh-CN
::: end meta

# 大标题

第一段正文。空一行才分段。

**加粗**、*斜体*、`行内代码`。
```

要点：

- 文件后缀 `.prt`（或 `.md`）；UTF-8 编码；
- `::: meta … ::: end meta` 是文档的「身份证」，放在最前面；`title` 建议必填；
- `#` 到 `######` 六级标题，`#` 后要有空格；
- **空行分段**——没有空行的多行文字是同一段。

**常见坑：** `##标题`（缺空格）、`**加粗*`（星号不配对）、meta 卡片忘了 `::: end meta`。

详见：第 6 章、第 9.1 节。

## 2　怎么搭长文档的骨架（头信息、章节、摘要、目录）

**摘要 + 目录：**

```prt
::: summary
一句话说清这份文档讲什么、给谁看。
::: end summary

[[contents depth=2]]
```

**带自动编号的章节：**

```prt
::: section id="ch-plan" title="计划"
这是 1 号章的内容。
::: section id="sec-risk" title="风险"
这是 1.1 号小节。
::: end section
::: end section
```

要点：

- `section` 开几个就 `::: end section` 关几个；`title=` 是显示标题，`id=` 是留给交叉引用的代号（小写、短横线连接，如 `ch-plan`）；
- `[[contents depth=2]]` 在原地生成目录，只列到二级；`depth` 可省；
- meta 里 `toc: true` 可让工具自动放目录。

**常用 meta 键速查：** `title`、`author`、`date`、`version`、`lang`、`theme`（外观，任务 6）、`strict`（`false` = 宽松模式）、`toc`。

**常见坑：** 开两个 `section` 只关一个（报「未闭合」）；`id` 重复或含空格。

详见：第 9.1–9.3 节。

## 3　怎么在一句话里强调重点

**按想表达的意思选：**

| 想表达 | 写法 | 效果 |
|---|---|---|
| 关键词 | `**重点**` | 加粗 |
| 语气词、书名 | `*轻声*` | 斜体 |
| 删除的内容 | `~~作废~~` | 删除线 |
| 需要留意的词 | `==高亮==` | 荧光笔效果 |
| 要敲的键 | `[[kbd: Ctrl+S]]` | 键帽样式 |
| 上标 / 下标 | `10^4^`、`CO~2~` | 指数 / 化学式 |
| 补充说明 | `文字^[脚注内容]` | 正文上标序号，文末列出 |
| 上色 | `[[color:red]]警告[[/color]]` | 红色文字 |
| 加底色 | `[[bg:yellow]]备忘[[/bg]]` | 黄底 |

要点：

- 颜色**只能用命名色**（`red`、`green`、`blue`、`warning`、`success` 等），不能写 `#FF0000`；
- 这些符号想原样显示时，前面加反斜杠：`\==`、`\^`、`\~`；
- 行内代码（反引号）里的内容**不解析**任何标记，照原样输出。

**常见坑：** 高亮符号是两个等号 `==`（一个不生效）；上标 `^` 和脚注 `^[` 长得像，成对 `^…^` 是上标、`^[` 是脚注。

详见：第 7 章。

## 4　怎么列要点与待办清单

**三种清单：**

```prt
- 无序列表：圆点
- 缩进两个空格是子项
  - 子项

1. 有序列表
2. 数字自动接续

- [ ] 待办（未完成）
- [x] 已办（已完成，渲染成可勾选框）
```

要点：

- `-`、`*`、`+` 都能开无序列表，后面要有空格；
- 任务清单只在列表项开头成立；支持交互的阅读器里可以直接**点击勾选**（勾选状态写回源文件）。

**常见坑：** `-项`（缺空格不是列表）；任务框写成 `-[]`（方括号里要有空格或 x）。

详见：第 8 章、第 11 章。

## 5　怎么放提示、警告、结论这类说明

**按「想说什么」选卡片**（完整选型表见附录 B）：

```prt
::: note
随手补一句，不强调。
::: end note

::: warning
要小心，但不出大事。
::: end warning

::: danger
会出大事！
::: end danger

::: tip
教读者怎么做更好。
::: end tip

::: result
算出来的结论放这里。
::: end result
```

要点：

- 卡片开头 `::: 类型名`、结尾 `::: end 类型名`，**类型名必须一致**；
- 卡片里可以放列表、代码块等，但**不能再套卡片**（想套，用布局块或章节，见任务 6、2）；
- 12 种卡片：`note` `info` `tip` `warning` `danger` `attention` `example` `definition` `quote` `comment` `result` `task`（别名 `todo`）。

**常见坑：** `::: end note` 写成 `::: end not`（拼错）；卡片里套卡片（违规）。

详见：第 8.3 节、第 8.7 节。

## 6　怎么排版面（对齐、颜色、分栏、折叠、选项卡、皮肤）

**一句话的对齐与强调：**

```prt
::: align center
居中的一行。
::: end align

::: text color="danger" size="large" align="center"
大号红字、居中。
::: end text
```

- 字号：档位四档 `small` `normal` `large` `xlarge`，或**直接写磅数**（8–72，如 `size="14"`）——两者可混用。
- 对齐四档：`left`（默认）`center` `right` `justify`；文档级默认由 `::: style` 声明，块级逐块覆盖。
- 字体：`font="思源黑体, sans"`——白名单 + **回退链**（逗号分隔，末项须为 `sans`／`mono`／`serif`），清单见附录 C.2。
- 底纹：`shade="yellow"`（与 `background` 同义；颜色只能用命名色，见 C.1）。

**整篇统一（字体、磅数、底纹、水印）：**

```prt
::: style
align: left
font: 思源黑体, 微软雅黑, sans
size: 11
background: white
watermark: 内部资料 | angle=45 | opacity=0.08 | color=gray | size=48
::: end style
```

放在正文最前面（`meta` 之后），全篇只写一个；块级同名项会覆盖它。水印是呈现效果：不编号、不进目录、不占版面，导出 Markdown 或纯文本时被丢弃。

**分栏、折叠、选项卡：**

```prt
::: columns
左栏内容（分栏内的段落横向并排）
::: end columns

::: collapse title="点开看细节" default-open=false
默认收起，读者点标题展开。
::: end collapse
```

**整篇换皮肤：**

```prt
<DocType=PRT>```prt
::: meta::: meta
theme: "dark"
::: end meta
```

内置主题：`default`、`dark`、`print`（打印友好）、`accessible`（高对比度）。要微调颜色变量，用 `::: theme` 卡片覆盖（如 `--link-color: blue`）。

**心智模型：主题只改外观，不改语义**——「警告」换什么主题都是警告。

**常见坑：** 分栏里塞太多内容（分栏适合短内容）；布局块套娃超过三层。

详见：第 8.4 节、第 12 章。

## 7　怎么做表格（含合并与合计行）

**简单表格直接写：**

```prt
| 季度 | 收入 | 备注 |
| :--- | ---: | :---: |
| Q1   |  100 | 含税 |
| Q2   |  120 | 含税 |
```

第二行的冒号定对齐：`:---` 左、`---:` 右、`:---:` 居中。

**要合并、表头分组、合计行，包一张 `::: table`：**

```prt
::: table id="t-rev" caption="季度收入汇总"
| 地区 | Q1 | Q2 |
| :--- | ---: | ---: |
| 华东 ++ | 100 | 120 |
| 华南   | 80 ^^ | 90 |
|==|
| **合计** | **180** | **210** |
::: end table
```

- 单元格写 `++`：并入**左边**一格（跨列合并）；`++2` 表示再向右跨 2 列；
- 写 `^^`：并入**上面**一格（跨行合并）；
- `|==|` 以下是**表尾**（合计行），渲染更醒目；
- `caption=` 自动编号「表 N」；`id=` 供 `[[ref:t-rev]]` 引用。

**常见坑：** 被合并格自己又去合并别人（禁止链式）；表头合并跨进表体；每行竖线数不一致导致错位。

详见：第 10 章。

## 8　怎么放图片、公式与代码

**图片（要编号与引用时用 figure）：**

```prt
![流程示意](./img/flow.png)

::: figure id="fig-flow" caption="处理流程"
![处理流程](./img/flow.png)
::: end figure
```

- 裸图片语法 `![替代文字](路径)` 随处可用；`figure` 版本带「图 N」编号和 `id`；
- 相对路径以文档所在目录为基准。

**公式（要编号时用 equation）：**

```prt
::: equation id="eq-cost"
总成本 = 单价 × 数量 × (1 + 税率)
::: end equation
```

正文里 `[[ref:eq-cost]]` 可跳转引用。

**代码：**

````prt
行内用反引号：`npm install`

三个反引号起止的是代码块（原样输出）：

```text
若 目标 = 长期质量
则 优先 深度工作
```
````

**常见坑：** 图片路径写反斜杠（用 `/`）；代码块忘了闭合的反引号；代码里有三个反引号时，外层改用四个或 `~~~`。

详见：第 8.5 节、第 9.4 节。

## 9　怎么让文档会跳（交叉引用与术语）

**口诀：先登记，后引用。**

**跳到某章 / 某表 / 某图：**

```prt
::: section id="ch-method" title="方法"
::: end section

方法见 [[ref:ch-method]]。
显示名自定义：[[ref:ch-method|本文方法]]。
```

**给目标起个好念的别名：**

```prt
::: refs
方法: ch-method
::: end refs

正文里写 {方法} 即可显示并跳转。
```

要点：

- `[[ref:id]]` 引用**块的 id**（章节、表格、图、公式）——用它**跳转**；
- `{别名}` 引用 **refs 里登记过的别名**——用它**引词**；
- 把章节 id 直接塞进 `{…}`（如 `{ch-method}`）是误用；
- 目录 `[[contents]]` 会自动收录有 `title` 的章节。

**常见坑：** 引用了没登记的 id（严格模式报错）；别名登记和引用处拼写不一致。

详见：第 9.4 节。

## 10　怎么为导出做准备（降级检查）

一份 PRT 可导出 HTML、PDF、DOCX、EPUB、纯文本、Markdown。核心概念是**自动简化**：某格式放不下某功能时**不丢内容**，转成朴素形式（高亮→普通文字；警告卡片→「[注意] …」；分栏→纵向展开；脚注→文末集中列出）。

**作者的自查清单：**

- 关键信息**不要只靠颜色**表达（纯文本里颜色会消失，改成「重要：」前缀更稳）；
- 分栏、选项卡里的内容要能**竖着读**也通顺；
- 图片给好替代文字 `![说明](路径)`；
- 想原样转 `.md` 的文档，只用基础语法（任务 1–4、7 的简单表格），不掺 PRT 特有块。

详见：第 13 章。

# 二、让文档算起来（进阶）

> 以下功能默认关闭。工具需启用计算（如命令行 `--run=allow`）；没启用时相关代码按普通代码块显示，**不报错**。所有计算跑在沙箱里：不能联网、不能碰文件、不知道现在几点、同一输入永远同一输出。

## 11　怎么在正文里显示一个算出来的值

**唯一写法：先声明端口，再算，结果显示在声明处。**

```prt
总价：[[output:总价]] 元。

::: run lang="prt" id="算总价" sig="()"
LOAD    p0, 12.50        ; 单价（也可经 sig 传入）
LOAD    p1, 3            ; 数量
MUL     r0, p0, p1
EMIT    @总价, r0        ; 写进端口 → 上面那一行就地显示
::: end run
```

要点：

- `[[output:ID]]` 是**行内**指令：不占段落，可与文字同行（「总价：[[output:总价]] 元」）；
- 它的位置就是**显示位置**，也是端口的**声明位置**：写入它的 `::: run` 必须出现在它**之后**（文档顺序）；
- 一个端口只在正文声明**一处**；同一结果要在两处显示，就声明两个端口分别 `EMIT`；
- 带小数的数是**固定两位**的金额式小数：`0.1 + 0.2` 永远得 `0.30`，不会冒出一长串；
- 未启用计算时，该处按占位显示，`::: run` 降级为普通代码块，**不报错**；
- 想在别处复用同一个值：给端口加 `capture="变量名"` 绑定，再用 `[[output:$变量名]]` 呈现（见任务 14）；
- 内置函数以「函数名大写即操作码」调用：`LENGTH r1, r0`、`UPPER r1, r0`、`FORMAT r1, r0, "%,.2f"`，完整清单见简明标准附录 B。

**常见坑：** 端口写在了 `::: run` 之后（方向反了 → `E_OUTPUT`）；`EMIT` 的端口名与 `[[output:ID]]` 不一致；把运行块的 `id` 当成端口名（运行块不再是端口）。

详见：简明标准 11.1.4、11.1.6。

## 12　怎么按条件给出不同的结果

文档层**没有**条件块。条件写在 PRTA 里，用 `EMIT` 决定往端口里写哪个值：

```prt
现在是 [[output:体感]]。

::: run lang="prt" id="判温度" sig="(t)"
LOAD    r1, "太热了，开空调"
LOAD    r2, "很舒适"
LOAD    r3, "有点凉，加件外套"
LOAD    r4, 30
LOAD    r5, 20
IF t, >=, r4
EMIT    @体感, r1
ELSE
IF t, >=, r5
EMIT    @体感, r2
ELSE
EMIT    @体感, r3
ENDIF
ENDIF
::: end run
```

要点：

- `IF a, rel, b` … [`ELSE` …] `ENDIF`，`rel` 六种：`==` `!=` `<` `<=` `>` `>=`；可嵌套；
- 比较两侧都要是**寄存器/形参/名变量**，立即数先 `LOAD` 进寄存器；
- 条件只决定「写进端口的值」，不决定某段正文是否存在——文档结构是静态的。想控制**组件**的显示，就让 PRTA 写一个布尔值到它的 `bind` 目标：值为 `false`／`null` 时工具可隐藏该组件。

**常见坑：** `IF` 忘了 `ENDIF`；在条件里直接写立即数（`IF t, >=, 30` 不合规）；用 `::: if` 包段落（已废止 → `E_LEX`）。

详见：简明标准 11.1.7、11.1.10。

## 13　怎么批量生成重复内容

文档层**没有**循环块：循环只在 PRTA 内部生成**数据**，再一次 `EMIT` 输出。

```prt
[[output:城市清单]]

::: run lang="prt" id="列城市" sig="()"
LIST_NEW r0
LOAD     r1, "北京"
LIST_PUSH r0, r1
LOAD     r1, "上海"
LIST_PUSH r0, r1
LOAD     r1, "广州"
LIST_PUSH r0, r1
EMIT     @城市清单, r0     ; 整个列表一次写出，显示为逐行展开
::: end run
```

要「第 1、第 2…」这种计数，就在循环里把序号与内容拼好再写：

```prt
[[output:编号清单]]

::: run lang="prt" id="编号" sig="()"
VAR i: Integer = 1
VAR s: String = ""
WHILE i, <=, 5
LOAD    r1, i
STR     r2, r1           ; 序号转文本（白名单函数，大写即指令）
CONCAT  s, s, r2         ; 拼上序号
ADD     i, i, 1
ENDWHILE
EMIT    @编号清单, s
::: end run
```

要点：

- `WHILE a, rel, b` … `ENDWHILE`，体内可 `BREAK` / `CONTINUE`；步数预算兜底，不会跑挂（硬上限 1 000 000 步）；
- 循环**不展开文档结构**：想输出 5 段文字，就让 PRTA 把 5 段拼成一个值（或多值端口），由 `[[output:ID]]` 一次显示；
- 字符串拼接、序号格式化走附录 B 的白名单函数（`CONCAT` / `FORMAT` / `STR` 等）。

**常见坑：** 指望 `::: loop` 重复渲染一段正文（已废止 → `E_LEX`）；`WHILE` 忘了 `ENDWHILE`；循环条件用立即数而不是寄存器。

详见：简明标准 11.1.6、11.1.7。

## 14　怎么算出一个结果并在正文引用

**最小可抄模板**——「先声明端口 → PRTA 算 → 写进端口」，多步计算也一样：

```prt
折后总价：[[output:总价]] 元。

::: run lang="prt" id="算折后价" sig="(price,count)"
MUL     r0, p0, p1        ; 单价 × 数量（p0/p1 是两个形参）
LOAD    r1, 0.90
MUL     r2, r0, r1        ; 再打九折
EMIT    @总价, r2
RETURN  r2
::: end run
```

**想把这个值在别处再用一次**：给端口加 `capture="变量名"` 绑定，之后用 `[[output:$变量名]]` 呈现：

```prt
统计：[[output:统计 capture="结果"]]

::: run lang="prt" id="stats" sig="()"
LIST_NEW r0
LOAD     r1, 95
LIST_PUSH r0, r1
LOAD     r1, 90
LIST_PUSH r0, r1
EMIT     @统计, r0
RETURN   r0
::: end run

上面那组数也在这里：[[output:$结果]]
```

要点：

- 每条会产出值的指令都要写明去向：`@端口` 或 `$变量`，前缀不能省、不能混；
- `capture` 是**只读消费**：绑定发生在本块回写之后、拿的是端口的最终值；绑定的变量与块内 `EMIT $` 同名时 `EMIT` 优先；
- 签名 `sig` 可以简化甚至整体省略（推荐只写形参名，如 `sig="(price,count)"`）；形参名在块内可直接按名使用；
- PRTA 像小汇编：`LOAD` 放立即数、`r0`–`r15` 随手可用、`VAR n: Integer = 0` 声明有名变量、判断用 `IF/ELSE/ENDIF`、循环用 `WHILE/ENDWHILE`（没有 `goto`）；
- `RETURN` 的值**不会**显示在文档里（它只交给 `CALL` 的调用者）；要显示就用 `EMIT`；
- 给端口加样式：`[[output:总价 display="align=right; size=18; frame=card"]]`。

**常见坑：** 端口没先声明就 `EMIT @…`（→ `E_OUTPUT`）；跨块写入只能写**文档顺序更早**声明的端口；`capture` 绑了变量却没在正文写 `[[output:$变量]]`（不会自动出现）。

详见：简明标准 11.1.4、11.1.15。

## 15　怎么加按钮

**两步：声明按钮 + 写处理块。最小可抄模板（计数器）：**

```prt
当前计数：[[output:$计数]]

::: run lang="prt" id="init" sig="()"
LOAD    r0, 0
EMIT    $计数, r0        ; 建立初值（变量须先由某次运行建立）
::: end run

::: run lang="prt" type="prtui" id="btn_add"
                  sig="()" ui="button" label="加一"
                  bind="$计数" on="click:on_add"
::: end run

::: run lang="prt" id="on_add" sig="(evt)"
LOADVAR r0, $计数        ; 读当前计数
LOAD    r1, 1
ADD     r2, r0, r1       ; 加一
EMIT    $计数, r2        ; 写回 → 按钮回显与 [[output:$计数]] 一起刷新
RETURN  null
::: end run
```

要点：

- 按钮块 `type="prtui"` 的**块体必须为空**——按钮是声明，不是代码；
- `on="click:处理块id"` 把点击接到一个**普通的 PRTA 运行块**上；
- 组件要回显的变量，得先由某次运行 `EMIT $变量` 建立（上例的 `init` 块）；正文中用 `[[output:$变量]]` 呈现它；
- 读者每点一次，工具带着「事件包」（事件名、组件名、交互值）把处理块**从头独立执行一遍**；处理块用 `EMIT` 写回变量后，按钮回显与正文的 `[[output:$计数]]` 自动刷新；
- 按钮不会「连环炸」：处理块自己不可能再触发事件；每次调用独立计费、排队执行。

**三条铁律**（决定文档行为，写之前先记住）：

1. **变量变了不会自动重算别的块**——回写只刷新显示；想再算，靠读者再点一次或被别的块显式调用；
2. **一次渲染里每个顶层块至多算一遍**，结果会缓存，输入没变不重算；
3. **失败块的产出对外「读不到」**——处理块报错时它的端口与绑定变量不可读，读取会报 `E_OUTPUT`，不是悄悄给空值。

**常见坑：** `on=` 里的处理块名与实际块的 `id` 不一致（点了没反应）；`bind="$计数"` 的变量从没被 `EMIT $` 建立过（没有回显，正文也显示占位）；在按钮块体里写指令（`E_UI`）。

详见：简明标准 11.1.10、11.1.13。

## 16　怎么加输入框、下拉与复选框

**输入框（回车提交）：**

```prt
你好，[[output:$名字]]！

::: run lang="prt" id="init_name" sig="()"
LOAD    r0, ""
EMIT    $名字, r0        ; 先建立初值，输入框才有回显
::: end run

::: run lang="prt" type="prtui" id="in_name"
                  sig="()" ui="input" label="你的名字"
                  value="请在此输入" bind="$名字" on="submit:on_name"
::: end run

::: run lang="prt" id="on_name" sig="(evt)"
MAP_GET r0, p0, "value"  ; 从事件包取出读者输入的文字
EMIT    $名字, r0
RETURN  null
::: end run
```

**下拉与复选框：**

```prt
::: run lang="prt" type="prtui" id="sel_level" sig="()" ui="select"
                  label="等级" options="低|中|高" on="change:on_level"
::: end run

::: run lang="prt" type="prtui" id="ck_agree" sig="()" ui="checkbox"
                  label="我已阅读须知" on="change:on_agree"
::: end run
```

要点：

- 事件与组件对号：`click` 只属于按钮；`input`/`select`/`checkbox` 用 `change`；输入框另有 `submit`（回车）；
- **框里的两种字要分清**：绑定的变量若有值，输入框**一开始显示它**（回显）；读者开始打字后，框里就是读者自己的输入。事件包里的 `value` 取**读者打出来的字**，要不要写回变量由处理块用 `EMIT` 决定——框不会自己写；
- `value` 属性只是**占位提示**，不是默认值；
- 多个组件绑同一个变量：变量一变大家的回显一起刷新，但各自输入互不干扰；
- 组件**不能**放在条件块里（文档层没有条件块）：想控制它显示与否，就让 PRTA 给它的 `bind` 目标写 `false`／`null`，工具可据此隐藏；被隐藏时绑定仍然有效。

**常见坑：** 下拉忘了 `options`（竖线分隔选项）；给复选框绑 `click`（事件与组件不匹配 → `E_UI`）；处理块签名形参不是恰好 1 个（→ `E_SIGNATURE`）。

详见：简明标准 11.1.10、11.1.13。

## 17　怎么理解「什么时候算、什么时候刷」

一份带计算的文档渲染时走三步：①**搭结构**——建立章节、跳转、术语表与全部 `[[output:ID]]` 端口；②**执行**——按下面的时机跑各运行块；③**回写并刷新**——把结果写进端口，刷新受影响的显示。

**什么时候执行？** 只有三种触发，此外没有别的：

| 触发 | 谁会被执行 |
|---|---|
| **文档加载** | 所有顶层 `::: run` 块按文档顺序各算一遍（按钮组件不算；不安全块永不执行） |
| **显式调用** | 被别的块 `CALL @id` 调用 |
| **事件调用** | 读者点了按钮、改了输入框 |

**作者需要记住的规则：**

- 端口必须在**写入它的块之前**声明——这是唯一计算原则下最容易踩的一条；
- 每个块看到的输入，是「**它开跑那一刻**」的状态（事件调用则取「事件发生那一刻」）；
- 加载执行是**幂等**的：反复打开文档不会越算越多，结果有缓存；
- **变量变了只刷新显示，不自动重算**依赖它的块（见任务 15 铁律 1）；
- 某块失败不连累别的块：它在对应 `[[output:ID]]` 处显示 `[错误] E_XXX: 原因`，后续块照常执行。

详见：简明标准 11.1.13。

# 三、出问题时

## 18　怎么看懂报错

报错格式是「行:列 + 描述」，如 `3:14 未知块类型`。先去那一行找问题。最常见的几种：

| 症状 | 原因 | 改法 |
|---|---|---|
| 未闭合的围栏 | 写了 `::: note` 没写 `::: end note` | 补结尾，类型名一致 |
| 加粗没生效 | 星号不配对 | 补成 `**文字**` |
| 标题没变大 | `##标题` 缺空格 | `## 标题` |
| 符号被吃掉 | 保留符号没转义 | 前面加 `\` |
| 引用报错 | `[[ref:id]]` 的 id 没登记 | 先给目标 `id=` 或先写 `refs` |
| `E_UI` | 组件绑定错误（事件名、bind 目标、处理块不存在等） | 对照附录 C 检查属性 |
| `E_OUTPUT` | 读取了不存在的去向，或读了失败块的产出 | 检查 `EMIT` 目标与块是否执行成功 |
| `E_RESOURCE` | 计算超预算 | 精简计算，或与实现者确认限额 |
| `E_LEX` | 写了已废止的构造（`::: set` / `::: if` / `::: loop` / `{{ … }}`），或 PRTA 指令、控制块写错 | 改成 `::: run` + `[[output:ID]]`；核对指令与 `IF`/`WHILE` 配对 |
| `E_SIGNATURE` | 签名与调用不符；端口重复声明；运行块上写了 `type="prtopt"` / `capture` / `display` | 核对形参个数；端口只声明一处；样式与绑定改写在 `[[output:ID]]` 上 |
| `E_OUTPUT` | 写入未声明的端口；端口声明晚于写入它的块；读了失败块的产出 | 把 `[[output:ID]]` 移到写入块之前；核对端口名 |

详见：简明标准 14.4、11.1.12。

## 19　怎么排查一段不生效的内容

**三步法：**

1. **看行号**——报错的 `行:列` 直接定位；
2. **二分注释**——把后半段整段行首加 `//`（行注释），看前半段是否正常；正常则问题在后半段，继续对半砍，几轮就锁定；
3. **逐个还原**——锁定小范围后，把最近改的一两行先注释或改回，看问题是否消失。

另有一条对计算文档特别有效：**先确认计算功能开了没有**（`--run=allow`）。没开时，`::: run` 按普通代码块显示、`[[output:ID]]` 按占位显示——那不是坏了，是「省心模式」。

还有一条 v4.0 特有的：如果文档是旧版写的，`::: set` / `::: if` / `::: loop` / `{{ … }}` 会直接报 `E_LEX`。改法只有一种——把它们改写成 `::: run` 里的 PRTA，并给结果显示位补上 `[[output:ID]]`（对照《PRT 简明标准》15.5 的迁移表）。

# 附录 C　组件与事件速查表

**组件属性：**

| 属性 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 组件名，唯一，也是事件包里的 `source` |
| `sig` | 形参必须为空 | `sig="()"` 或省略 |
| `ui` | 是 | `button` / `input` / `select` / `checkbox` |
| `label` | 否 | 显示文本 |
| `bind` | 否 | 回显值来源：`$变量` 或 `@端口` |
| `options` | select 必填 | 竖线分隔：`options="低\|中\|高"` |
| `value` | 否 | 输入框的占位提示（不是默认值） |
| `on` | 否 | 事件绑定 |

**事件：**

| 事件 | 组件 | 触发 | 事件包里的 `value` |
|---|---|---|---|
| `click` | button | 点击 | `null` |
| `change` | input / select / checkbox | 值提交变更 | 文本 / 选中项 / 布尔 |
| `submit` | input | 回车确认 | 文本 |

**绑定规则：** `on="事件:处理块id"`，多对用逗号分隔；一个事件只接一个处理块；处理块是普通 PRTA 运行块，形参恰好 1 个（事件包）。
