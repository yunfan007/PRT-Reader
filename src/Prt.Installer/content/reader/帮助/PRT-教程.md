# PRT 教程：从零开始的自学手册

> **这本册子是什么？** 一本**写给完全没接触过 PRT 的人的自学教材**。你不需要任何基础——不用懂编程，不用会用什么专业软件，只要会用记事本打字、会保存文件，就能跟着这本册子一路学下去。
>
> **它不是标准。** 它只管「怎么用、怎么练」，不管「什么算合规」。规定类的内容在《PRT 简明标准》（通俗版规范）和《PRT 标准》（正式规范）里；三本书怎么配合，见册末附录 C。一句话：**这本册子教你走路，标准负责画边界。**
>
> **怎么自学（三遍法）：** 每一课都按「① 读讲解 → ② 跟着例子亲手敲一遍 → ③ 做『动手做』小练习、再对答案」的节奏来。学完一课，用课末的「本课三句话」自查；每周回头做一次综合练习。**敲一遍比读三遍有用。**
>
> **名称说明：** 这套格式历经两次更名：原名 **MDP（Markdown-Plus）**，其后改名 **PSR（Perisc Standard Richtext）**，现名 **PRT（Perisc Rich Text）**——文件后缀是 `.prt`，示例里的语言名是 `prt`，讲「小块程序」时提到的汇编后端叫 **PRTA**。旧资料里的「MDP」「.mdp」「PSR」「.psr」指的都是同一套东西，照着这本册子写新名即可。

> **适用版本：** 本教程对应 **PRT v4.0**。v4.0 起 PRT 里只有一种计算：写 `::: run` 块、块里写 PRTA，再用 `[[output:ID]]` 在正文里指定显示位置；旧版的 `::: set`、`::: if`、`::: loop` 与 `{{ }}` 已全部废止——第 11 课开头会先讲清楚这条总纲。

约定：例子框里写的就是你在文件里输入的原文；「动手做」是练习题，「答案」紧跟其后——**先自己做，再看答案**。正文里偶尔用「必须 / 建议 / 可以」告诉你做法的轻重：必须 = 照做才不会出错；建议 = 照做更好；可以 = 随你喜欢。

# 第 1 课　准备：文件、工具与第一份文档

**学完这一课，你能做的事：**

- 新建一个 `.prt` 文件，并看到它排版后的样子；
- 用 `#` 写标题、用 `**…**` 加粗；
- 明白「空一行」为什么重要。

## 一、先说清楚：PRT 文件是什么

它就是一个**普通的文本文件**——和你用记事本写的 `日记.txt` 没有本质区别，只是后缀名换成 `.md` 或 `.prt`。你在文件里打字、加一些约定的符号（比如 `#`、`**`），**阅读工具会把这些符号变成漂亮的排版**：`#` 变成大标题，`**…**` 变成粗体。

所以写 PRT 的过程是：**用记事本式的方式打字 → 保存 → 用阅读工具打开看效果**。就这么简单。

先记住三条最基本的规律：

- `#` 开头是**一级标题**（`#` 到 `######` 一共六级，级别越小字越大）；
- `**文字**` 表示**加粗**；
- **空一行**表示「这里分段」——没有空行的多行文字会连成一段。

这三条是 PRT 最小的骨架，往后每一课都在上面加东西。

## 二、用什么工具写、怎么看排版效果

写：任何能保存纯文本的编辑器都行（Windows 记事本、VS Code 等）；看效果：需要一个支持 PRT 的阅读/预览工具。下面是通用指引，具体下载请在官方渠道查找：

> **推荐工具（2026 年）：**
> - **编辑器 + 预览**：VS Code（装 PRT/Markdown 预览扩展），或 Typora 这类所见即所得编辑器；
> - **命令行渲染工具**：`prt-cli`（用于导出 HTML/PDF 等）；
> - **在线练习**：PRT Playground（浏览器里即写即看，适合前几课练手）。
> - 若你拿到本教程时附带了一份官方工具包，以包内 README 为准。

**跟着做（Windows 示例；其他系统命令类似）：**

1. 打开命令行（PowerShell 或终端），确认渲染工具装好了：

```bash
prt --version
```

看到类似 `PRT CLI 1.1.0` 的版本号就说明装好了；若提示「找不到命令」，先去官方下载页装好再回来。

2. 新建一个 `hello.prt`，输入：

```prt
<DocType=PRT>
# 你好，PRT

这是我的第一份 PRT 文档。**这段话是加粗的。**
```

> **第一行永远是 `<DocType=PRT>`。** 这一行是文件的「身份证」——半角书写、区分大小写、单独占一行，前后不能有空行。忘了写、写错大小写或位置，工具会直接报 `E_DOCHEAD` 拒绝打开。它属于声明，不会出现在排版结果里，读者看不到。
>
> **保存时选「UTF-8（带 BOM）」。** 记事本保存时把编码选成「UTF-8」、VS Code 在右下角选「UTF-8 with BOM」。漏了 BOM 一般还能打开，但工具会提示一条 `W_ENCODING` 提醒你补上；存成 UTF-16 或 GBK 则会直接报 `E_ENCODING`。

3. 用编辑器打开并预览（VS Code 里通常按 `Ctrl+Shift+V`）。你会看到 `# 你好，PRT` 变成大标题、`**这段话是加粗的。**` 变粗。

**动手做：** 把下面这份补全——加一个二级标题 `##`，并把「春天」加粗：

```prt
<DocType=PRT>
# 我的小花园

我想记录我种的花。
```

**答案：**

```prt
<DocType=PRT>
# 我的小花园

我想记录我种的花。

## 我最喜欢的花

**春天** 开的郁金香最鲜艳。
```

**为什么这样写：** `#` 是整篇的大标题（文档标题），`##` 是它下面的一节，二者形成「章—节」的层级；`**春天**` 让这个词突出。内容不必和答案一字不差，语法用对即可。

**新手常见坑：**

- 把 `## 标题` 写成 `##标题`——`#` 后面**必须有一个空格**，否则不当作标题；
- 把 `**加粗**` 写成 `**加粗*`——符号没配对，就不会有加粗效果（有的工具还会报错）；
- 段落之间忘了空行——两行字会被连成一段。

**本课三句话：** ① PRT 文件就是普通文本文件；② `#` 标题、`**加粗**`、空行分段是三条铁律；③ 写完用工具预览，看到效果才叫学会。

**下一课：** 我们给文档加列表、引用和分隔线，把一段文字变成有结构的一页。

# 第 2 课　整理内容：列表、引用、分隔线

**学完这一课，你能做的事：**

- 写无序、有序列表和任务清单；
- 引用一段别人的话；
- 用分隔线把两块内容隔开。

## 一、列表

```prt
- 无序列表：行首写短横线加一个空格
- 每行一个点
- 缩进可以做出子项

1. 有序列表：写数字加一个点
2. 第二项

- [ ] 买牛奶
- [x] 交周报
```

- `- ` 开头是无序列表（圆点）；`数字. ` 是有序列表，编号会自动接续；
- `- [ ]`（没完成）与 `- [x]`（已完成）是**任务清单**，它只在列表项开头成立，不会被误认成别的东西。

## 二、引用块与分隔线

```prt
> 这一整段行首带 '> '，会被左缩进并加一条竖线，表示「这是引文」。

---
```

`>` 开头的行是引用块；单独一行三个短横线 `---` 是一条水平分隔线，用来隔开两块不相关的内容。

**动手做：** 造一段「会议纪要」，包含一条无序列表（两件事，其中一件带加粗）、一句 `> ` 引用，中间用一条 `---` 隔开。

**答案：**

```prt
- 评审了原型
- **整理**了反馈清单

---
> 用户的直觉，往往是产品最好的验收官。
```

**为什么这样写：** 列表把多条同类信息排整齐，`---` 把「记录」和「一句引语」两个板块分开，`**…**` 让需要读者第一眼看到的关键词冒出来。

**新手常见坑：** 把 `- 项` 写成 `-项`——`-` 后必须跟空格才算列表；有序列表写 `1. 2. 3.` 最好按顺序写，乱写编号可能导致显示错乱。

> PRT 特有的提醒：它**不支持**旧式 Markdown 的「标题下一行加 `===`」写法。标题一律用 `#`。`=` 另有用途（第 3 课的 `==高亮==`），`---` 是分隔线。

**本课三句话：** ① 列表行首 `- ` 或 `数字. `，符号后带空格；② `- [ ]`/`- [x]` 是可勾选的任务清单；③ `> ` 引用、`---` 分隔，内容分区一目了然。

**下一课：** 给文字画更多花样——斜体、删除线、行内代码、高亮、上下标和脚注。

# 第 3 课　给文字画效果：斜体、删除线、代码、高亮、上下标、脚注

**学完这一课，你能做的事：**

- 用斜体、删除线、行内代码做常见的文字强调；
- 用高亮画重点，用上下标写单位和化学式；
- 用脚注给正文加「从正文挪出去」的说明。

## 一、基础强调：斜体、删除线、行内代码

```prt
*斜体* 或 _斜体_
~~这条已经作废~~
在终端运行 `prt --run=allow`
```

- `*…*`（或 `_…_`）→ 斜体；`~~…~~` → 删除线；
- 一对反引号里的内容**完全不解析**，按等宽字原样显示。

## 二、高亮、上下标、脚注

```prt
这条是最 ==重要== 的结论。
水温为 25^°C^ 时口感最佳。水的化学式是 H~2~O。
详见总结^[来自第 3 课。]
```

- `==…==` → **高亮**，只是加淡黄背景，**不是**加粗；
- `X^上标^` / `X~下标~` → 上标 / 下标（单位、化学式常用）；
- `字^[脚注文字]` → 生成一个**脚注**：正文里出现上标序号，脚注内容在文末集中列出，还能点回引用位置。

**一个常见的坑：** `^` 有两种用途——成对 `^…^` 是上标，`^[` 开头是脚注。脚注里**不能再套脚注**。

**动手做：** 写三个短句，分别用「上标表示平方米（㎡）」、「高亮一句话」、「给一句话加脚注『来自第 5 课』」各一次。

**答案：**

```prt
这个房间面积是 20 m^2^。

==电费本月涨幅较大。==

详见总结^[来自第 5 课。]。
```

**为什么这样写：** `^2^` 用上标让单位更专业，`==…==` 提示这是读者要注意的事实，`^[…]` 把一句「出处说明」从正文挪到文末，不影响正文阅读的连贯性。

**常见错误：**

- 上标写 `25^°C`（少了收尾 `^`）——不成对，`^` 会被当普通符号；
- 高亮写 `==重要==` 后忘了另一头也能闭合——必须 `==…==` 成对。

**本课三句话：** ① `*…*` 斜体、`~~…~~` 删除线、反引号里原样显示；② `==…==` 是高亮底色不是加粗，`^…^` 与 `~…~` 管上下标；③ `字^[说明]` 生成文末脚注，脚注里不能再套脚注。

**下一课：** 你已经有几个 Markdown 功底了，我们来一节「从 Markdown 来的人」专属的迁移指南，看看哪些能直接用、哪些要注意。

# ＋ 第 3 课后　综合练习一（第 1–3 课）

**说明：** 每一组综合练习把前面几课的知识串起来用一次；答案在最后。

**题目：** 写一小段「周末小记」，至少用到：一个 `#` 标题、一个 `##` 小节、一段含 `**加粗**` 的正文、一行 `- ` 无序列表、一句 `==高亮==`，以及一条 `^[脚注]`。

**参考答案：**

```prt
# 周末小记

## 周六

去公园放了风筝。==蓝天难得。== 回来的路上买了草莓。^[周末市集买。]

- 公园
- 市集
```

**为什么这样写：** 第 1 课的标题层级 + 第 2 课的列表 + 第 3 课的高亮与脚注，刚好拼出一篇「有结构、有强调、有补充说明」的小文档——它用的都是最基础的写法，任何 Markdown 工具也能直接读（第 4 课会讲）。

# 第 4 课　用过 Markdown 的朋友看这里

**学完这一课，你能做的事：**

- 判断自己已有的 `.md` 文件能否直接转成 PRT；
- 知道给旧文档加 PRT 特性时该从哪个功能下手；
- 知道哪些 Markdown 写法在 PRT 里不适用、要注意什么。

## 一、我的 `.md` 能直接用吗

PRT 是 **Markdown 的超集**：凡合法的标准 Markdown，同时也是合法的 PRT。所以：

- 直接把 `.md` 改后缀为 `.prt`，**不改任何内容**通常就能用；
- 想加 PRT 特性，建议从**最容易上手**的开始：`::: note` 和 `::: warning` 两个卡片（第 5 课）。

## 二、哪些 Markdown 写法在 PRT 里不适用 / 要留意

| 旧 Markdown 习惯 | PRT 里的情况 |
|---|---|
| 标题下一行加 `===` | **不支持**，请改用 `#` |
| `_斜体_` | 支持，是 `*斜体*` 的等价写法 |
| 行内下划线 | PRT 里 `+文字+` 是下划线，成对才成立 |
| 表格合并 | PRT 用 `++`/`^^`/`|==|`，不是 HTML 的 `colspan`（第 10 课） |

## 三、几个新增的「特殊符号」要转义

PRT 新增了几个 Markdown 没有的标记符号：`==`（高亮）、`^`（上标）、`~`（下标）、`++`（表格合并）、`:::`（卡片）。如果你在正文里真的想显示这些字面符号，就在前面加一个反斜杠 `\`「打掩护」，例如 `\==` 显示出正文的 `==`。

- 要显示一个字面反斜杠，写 `\\`；
- 反引号（行内代码）里的内容不解析转义，照原样输出。

> **延伸阅读（选读）：** 关于「同一串字符到底按哪种意思理解」的精确判定规则，见《PRT 简明标准》第 6.4 节。

**本课三句话：** ① `.md` 改后缀即用，PRT 全兼容 Markdown；② 新符号（`==` `^` `~` `++` `:::`）想原样显示就前面加 `\`；③ 标题只认 `#`，不认下一行加 `===` 的老写法。

**下一课：** 真正让 PRT 区别于 Markdown 的东西登场了——「卡片」。

# 第 5 课　卡片登场：给内容「贴标签」

**学完这一课，你能做的事：**

- 明白「卡片」在 PRT 里是干什么的；
- 会写一张卡片的开头与结尾；
- 在文档里插入三种最常见的卡片（提示、警告、建议）。

## 为什么卡片是 PRT 的招牌（先说设计意图）

在讲语法前，先交代为什么这一课放在文档骨架（第 8 课）之前：**Markdown 只会改变字的样子，PRT还能给一段内容「贴角色标签」**——这一段是补充说明、那一段是危险警告。贴了标签的内容，阅读工具会把它渲染成样式固定、一眼可辨的卡片。这是 PRT 相对 Markdown 最核心的差异化能力，所以先让你看到它。

## 一、卡片的写法：开头一句、结尾一句

一张卡片有**开头**也有**结尾**：

```prt
::: 种类名
这里放内容……
::: end 种类名
```

- 开头 `::: 种类名` 告诉工具「这段内容是什么角色」；
- 结尾 `::: end 种类名` 告诉它「到这儿结束」；
- 结尾的种类名必须和开头**一字不差**。

类比：`:::` 就像给一段内容「盖了个章」，`::: end` 表示「章盖完了」。

## 二、最常用的三种卡片

这一课只学三种，先不贪多：

```prt
::: note
这是一句补充说明，不强调。
::: end note

::: tip
建议：优先用变量而不是硬编码的数字。
::: end tip

::: warning
该操作会清空全部缓存，请先备份。
::: end warning
```

- `note`：随手补充一句；
- `tip`：教你怎么做更好；
- `warning`：小心，但不致命。

**动手做：** 写一个 3 行的文档：一个 `warning`（提醒「下班前记得锁门」）、一个 `tip`（提示「锁门后顺手检查信箱」）。

**答案：**

```prt
::: warning
下班前记得锁门。
::: end warning

::: tip
锁门后顺手检查一下信箱。
::: end tip
```

**为什么这样写：** `warning` 传达「有风险要留神」，`tip` 传达「这样做更好」，各司其职；选种类的准则是「这段内容是干嘛的」，而不是看哪种颜色好看。

**新手常见坑：**

- 忘了写 `::: end note`——卡片没闭合，报「未闭合」错误；
- 开了两张卡片只关一张——结尾 `::: end` 的个数要和开头 `:::` 对应；
- 把 `::: end note` 写成了 `::: end not`——种类名不一致，也报错。

> 有点好奇的话：PRT 一共支持 12 种卡片，除了这 3 种，其余 9 种我们放到第 7 课一口气学，节奏和本课一致，不会掉队。

**本课三句话：** ① `::: 种类名` 开头、`::: end 种类名` 结尾，一对配一张卡片；② 卡片给内容「贴角色标签」，渲染成样式固定的卡片；③ 最常用的是 `note`（补充）、`tip`（建议）、`warning`（警告）。

**下一课：** 写卡片最可能遇到的就是「报错了看不懂」。下一课专门学怎么看懂报错、怎么缩小问题范围。

# 第 6 课　出错别慌（怎么读报错、排查三步法）

**学完这一课，你能做的事：**

- 看懂 PRT 最常见的报错长什么样；
- 认识五种最常见的错、知道原因和改法；
- 分得清「严格模式」和「宽松模式」，知道怎么切换；
- 拿到一个看不懂的错，会用「排查三步法」缩小范围。

## 一、报错长什么样

所有提示都是同一副面孔，一行说完：

```
<文件>:<行>:<列>: <严重度> <代码>: <消息>
```

例如：

```
小花园.prt:3:14: 错误 E_LEX: 未知卡片种类 note2
小花园.prt:6:1: 错误 E_LEX: 未闭合的卡片（缺少 ::: end note）
小花园.prt:9:2: 警告 W_ENCODING: 文件缺少 UTF-8 BOM，建议以 UTF-8 附 BOM 重新保存
```

- 最前面依次是**文件、行号、列号**（都从 1 开始数，列按字符算）；
- 接着是**严重度**，只有三种写法：`错误`、`警告`、`提示`；
- 然后是**错误码**（如 `E_LEX`、`E_NUM`；警告以 `W_` 开头）与一句中文说明。

一次报多条时，工具会先给一行总览（`小花园.prt（共 20 行）：错误 2，警告 1`），诊断按「行 → 列 → 代码」的顺序排列，末尾再汇总一行（`合计 2 项错误、1 项警告`）。看到不认识的错误码，去《PRT 简明标准》第 14 章对号入座。

**最常见的头一条错：第一行。** 文件第一行不是 `<DocType=PRT>`（漏写、大小写不对、前面多了空行）会直接报 `E_DOCHEAD`，工具拒绝打开——先检查第一行，再查别的。

## 二、五种最常见的错误

| 症状 | 原因 | 修正 |
|---|---|---|
| 「未闭合的卡片」 | 写了 `::: note` 但没写 `::: end note` | 补上结尾 |
| 某个 `**` 没生效 | 加粗符号没配对 `**文字*` | 补成 `**文字**` |
| 标题没变大 | `##标题` 缺空格 | 写成 `## 标题` |
| 卡片种类名对不上 | `::: end note` 拼错成 `::: end not` | 结尾与开头一字不差 |
|某符号该原样却变了 | 遇到 `==`、`^` 等特殊符号没转义 | 前面加 `\` |

## 三、严格模式与宽松模式

- **严格模式（默认）**：一旦有错就停下并报告位置；适合你想确保万无一失时。
- **宽松模式**：出错不停下，把有问题的部分「自动简化」成还能读的样子（比如把写坏的卡片按普通文字显示），并给出警告。

想用更宽容的方式处理，可在文档头信息里声明（头信息的写法第 8 课细讲）：

```prt
::: meta
strict: false
::: end meta
```

（`strict: true` 则是严格模式。）草稿阶段用宽松模式很省心；正式交付前，请切回严格模式核对一遍。

## 四、排查三步法

一份长文档出错了，怎么定位到那一行？

1. **看行号**：报错会告诉你 `行:列`，先看那一行。
2. **二分注释**：把后半段整段暂时删掉或注释掉（行首加 `//`，第 8 课细讲），看前半段是否正常；恢复了，错就在后半段，再对后半段二分。每次排除一半，飞快。
3. **逐个还原**：锁定小范围后，把最近新加或改过的一两行先还原，看问题是否消失——多半就是它。

**动手做：** 下面这段有一处错，找出并修好：

```prt
::: warning
发布前请先备份。
::: end warn
```

**答案：** 结尾写成了 `::: end warn`，少了一个 `ing`。改成 `::: end warning`。

**为什么这样写：** 工具要求开头与结尾的种类名严格一致，才知道卡片在哪里结束。

**新手常见坑：** 在宽松模式看到「已按普通文字显示」就以为没事——那是在替你兜底。交付前定位到那一行修掉，输出才干净。

**本课三句话：** ① 报错格式是「行:列 + 描述」，顺着行号找；② 严格模式有错即停，宽松模式自动简化并给警告；③ 长文档用「二分法」缩小范围，改哪里试哪里。

**下一课：** 我们回过头把剩下的九种卡片补齐，给你的工具箱填满。

**题目：** 把一个旧的 Markdown 片段升级成带卡片、且报错会被正确处理的版本：给一段正文加一个 `::: tip`（提示用变量代替写死的数字），并把一处 `==` 高亮按「正文里真的显示 `==`」转义掉。

在配置里用到 `==` 字样时，记得转义成 `\==`。

# 第 7 课　更多卡片：其余九种

**学完这一课，你能做的事：**

- 认出并正确选用 PRT 全部 12 种卡片；
- 用 `task` 卡片做可勾选清单。

## 一、剩下的九种

第 5 课学了 `note`、`tip`、`warning`，今天把余下九种补齐：

| 想表达 | 用 |
|---|---|
| 中性地陈述一个事实 | `info` |
| 会出大事 | `danger` |
| 只是提醒注意一下 | `attention` |
| 举个例子 | `example` |
| 下定义 | `definition` |
| 引用别人的话 | `quote` |
| 自己看的批注 | `comment` |
| 计算得出的结果 | `result` |
| 可勾选清单 | `task`（别名 `todo`） |

## 二、`task` 卡片还能打勾

```prt
::: task
- [ ] 复核预算
- [x] 通过审核
::: end task
```

- `task` 和 `todo` 是同一种卡片的两名字，写哪个都行；
- 卡片里**不能再套另一张卡片**（比如 `::: note` 里再放 `::: warning` 不合法）；完整的嵌套规则见第 8 课末尾的小注。

**动手做：** 补上第 5 课欠下的尾巴——写一个 `danger`（如「生产环境不要直接删数据库」）、一个 `task` 清单（未完成 + 已完成各一项），并用 `result` 写一句「平均单价约 25.50 元」的计算结论。

**答案：**

```prt
::: danger
生产环境不要直接删数据库！
::: end danger

::: result
平均单价约为 25.50 元。
::: end result

::: task
- [ ] 复核预算
- [x] 通过审核
::: end task
```

**为什么这样写：** `danger` 强调「会出大事」、`result` 明确「这是算出来的结论」、`task` 把清单变成可勾选——三种角色，三种「它是什么」。

**新手常见坑：** 在卡片里又套一张卡片，会违反嵌套规则、报错或被自动简化；想组合，得用第 8 课的章节骨架。完整规则可翻《PRT 简明标准》第 8.7 节。

**本课三句话：** ① 九种新卡片按「想表达什么」对号入座；② `task`/`todo` 卡片配 `- [ ]`/`- [x]` 就是待办清单；③ 卡片里不能套卡片。

**下一课：** 现在是时候搭文档的骨架了——基本信息 `meta`、章节 `section`、摘要 `summary`。

# 第 8 课　文档的骨架：基本信息、章节、摘要

**学完这一课，你能做的事：**

- 用 `meta` 给文档登记「身份证」；
- 用 `section` 搭出自动编号的章节层级；
- 用 `summary` 写一段摘要。

## 一、meta：文档的身份证

`meta` 通常放在文档开头，登记整篇文档的属性。它们大多不直接显示在正文，但会被工具当作文档信息（标题、语言、外观等）来用：

```prt
::: meta
title: "三季度项目报告"
version: "1.0.0"
lang: zh-CN
theme: default
toc: true
::: end meta
```

先认识这几个键就够用：

| 键 | 填什么 |
|---|---|
| `title` | 标题（建议填） |
| `version` | 版本号 |
| `date` | 文档日期，**只写 `2026-09-13` 这种「四位年-两位月-两位日」**；不要写 `2026/9/12`、`2026年9月12日`，也不要带时刻 |
| `lang` | 语言，如 `zh-CN` |
| `theme` | 外观主题（第 12 课） |
| `strict` | `true/false`，错误模式（第 6 课） |
| `toc` | 是否自动生成目录 |

文档里凡是写日期，都用这一种「固定位数」写法：`2026-09-13`，带时刻就再接 `T10:30` 或 `T10:30:00`（如 `@2026-09-13T10:30`）。位数不够（`2026-9-1`）、用了别的分隔符（`2026/9/1`）都不算日期，工具会按第 6 课的方式提醒你。

## 二、section：自动编号的章节

`section` 可以**套娃**（章节里再套章节），工具会自动编号成 `1 / 1.1` 这样的层级，编号不用你手写、顺序调整后还会自动更新：

```prt
::: section id="ch-about" title="关于我"
这是我的自我介绍。
::: section id="sec-hobby" title="爱好"
喜欢烘焙和骑行。
::: end section
::: end section
```

- 结尾 `::: end section` 的个数要和开头 `:::` 对应：开了两个，就得关两个；
- `title=` 是这一章的标题，`id=` 是给这一章起一个「代号」（只用字母数字和短横线，如 `ch-about`），供第 9 课的「跳转」使用。

## 三、summary：摘要

```prt
::: summary
本报告总结三季度的进展、风险与下一步计划。
::: end summary
```

`summary` 渲染成一段独立的摘要，放在文档靠前的位置（通常紧跟开头）。

**动手做：** 新建 `profile.prt`，包含：一个 `meta`（至少 `title` 和 `lang`）、一个 `summary`、一个一级 `section`（带 `id` 和 `title`），里面再套一个二级 `section`。

**答案：**

```prt
::: meta
title: "我的个人资料"
lang: zh-CN
::: end meta

::: summary
这里是我的基本介绍。
::: end summary

::: section id="ch-about" title="关于我"
这是我的自我介绍。
::: section id="sec-hobby" title="爱好"
喜欢烘焙和骑行。
::: end section
::: end section
```

**为什么这样写：** `meta` 是「身份证」，`summary` 是「简介」，`section` 是「骨架」——三者把一篇普通文字变成有身份、有摘要、有层级的文档。自查重点：`meta` 有 `title`/`lang`、摘要一个、两级 `section`、`::: end section` 配对齐全。

**新手常见坑：** 开两个 `section` 只关一个，造成「未闭合」；`id` 用了重名或含空格（建议用 `ch-`、`sec-` 前缀加简短小写词）。

**本课三句话：** ① `meta` 登记文档信息，不进正文；② `section` 自动编号、可套娃、`id=` 供跳转；③ `summary` 放开头当摘要。

**下一课：** 有了骨架，就能让文档「会跳」——目录与跳转。

# ＋ 第 8 课　（接学）「什么能装什么」小注

读到这里，补一条第 5 课、第 7 课都提到的嵌套规则（完整版见《PRT 简明标准》第 8.7 节）：

- **普通内容**（标题、列表、引用、表格……）不用卡片，直接写；
- **卡片**里可以装普通内容，但**不能再套卡片**，也不能装 `section` 章节；
- **章节（`section`）** 里可以装任何东西——它是文档的骨架；
- **计算块**（第 11 课的 `if`/`loop`）也能装各类内容。

现在只要记住一句：**「卡片里别再套卡片；想组合，用章节」**。用得上时再回来查。

# 第 9 课　让文档会跳：目录与跳转

**学完这一课，你能做的事：**

- 用 `[[contents]]` 生成目录；
- 用 `[[ref:…]]` 让文字可点击跳转到文档其他位置；
- 用 `refs` 给目标起别名，用 `{…}` 引用词条。

## 一、目录

在想要的位置插入一行指令，工具会在原地生成目录：

```prt
[[contents depth=2]]
```

`depth=2` 表示只列到二级标题；不写 `depth` 则显示完整层级。

## 二、跳转：先登记，后引用

**先登记**：给要跳转的目标起一个 `id`（第 8 课）。例如：

```prt
::: section id="ch-progress" title="本季度进展"
这里是第一章的内容。
::: end section
```

**后引用**：在正文里用 `[[ref:该id]]` 指向它：

```prt
请先阅读 [[ref:ch-progress]] 一节。
```

渲染后会自动显示成该章的编号（如「1」），并且可以点击跳转。想自定义显示文字，写 `[[ref:ch-progress|本季度进展]]`。

## 三、另一种登记方式：refs 卡片（给目标起别名）

除了给块写 `id=`，还可以用一张 `::: refs` 卡片登记别名：

```prt
::: refs
回顾: ch-progress
::: end refs
```

之后写 `{回顾}` 就能显示并跳转到 `ch-progress`；也可以写 `[[ref:回顾]]`，效果相同。

注意两种引用的分工（**避免误用**）：

- `[[ref:…]]` 引用的是「某个块的 id」（章节、表格等目标）——**用它跳转**；
- `{…}` 引用的是「refs 里登记过的别名或词条」——**用它引词**；
- 把章节 `id` 直接塞进 `{…}`（如 `{ch-progress}`）是**误用**——它不是登记过的别名，显示和跳转都不对。想跳章节就用 `[[ref:ch-progress]]`。

**动手做：** 写一篇两章的小文（用 `section`，各带 `id`），放一个 `[[contents depth=1]]`，在第二章里用 `[[ref:…]]` 跳回第一章；再用 `refs` 给第一章起一个别名，并在正文里用 `{别名}` 引一次。

**答案：**

```prt
::: section id="ch-a" title="第一章"
这里是第一章的内容。
::: end section

::: refs
开篇: ch-a
::: end refs

::: section id="ch-b" title="第二章"
回顾请见 [[ref:ch-a]]，也常被称作 {开篇}。
::: end section
```

**为什么这样写：** `[[ref:ch-a]]` 让「第一章」在二章里可点、显示自动编号；`{开篇}` 通过 `refs` 别名以词条的方式又引了一次。两种方式分工清晰，这就是「先登记、后引用」的好处。

**新手常见坑：**

- 引用一个没登记的 id——严格模式报错，宽松模式显示 id 本身。养成习惯：先给 `id`（或先写 `refs`），再引用；
- 把章节 id 直接放进 `{…}`（见上「避免误用」）；
- 大小写、下划线拼错，导致登记和引用对不上。

> **延伸阅读（选读）：** 跳转与别名的完整规则（显示名覆盖、自动编号、`figure`/`equation` 等可引用目标）见《PRT 简明标准》第 9.4 节。

**本课三句话：** ① `[[contents depth=2]]` 生成目录；② 跳转口诀是「先登记 `id`，后 `[[ref:id]]`」；③ `{…}` 只引用 `refs` 里登记过的别名，不直接装块的 id。

**下一课：** 给文档加表格——从简简单单的竖线表格，到能合并、加合计的进阶表格。

# 第 10 课　表格：从简单到能合并

**学完这一课，你能做的事：**

- 写简单的竖线表格；
- 用 `::: table` 做合并单元格、加合计行、自动编号。

## 一、简单表格直接写（竖线表格）

```prt
| 季度 | 收入 | 备注 |
| :--- | ---: | :---: |
| Q1   |  100 | 含税 |
| Q2   |  120 | 含税 |
```

第一行是表头；第二行用短横线分隔，冒号决定对齐：`:---` 左对齐、`---:` 右对齐、`:---:` 居中。竖线把格子隔开，就像用尺子画表格。这种表格是 Markdown 基础写法，任何 Markdown 工具也能读。

## 二、要合并、合计、编号，包一张 `::: table` 卡片

```prt
::: table id="t-rev" caption="季度收入汇总"
| 季度 | 收入 | 毛利率 |
| :--- | ---: | ----: |
| Q1   |  100 |  25%  |
| Q2   |  120 |  26%  |
|==|
| **合计** | **220** | **25.5%** |
::: end table
```

三个新记号：

- 单元格写 `++`：**跨列合并**（并入左边那一格）；`++2` 表示向右跨 2 列；
- 单元格写 `^^`：**跨行合并**（并入上面那一格）；
- `|==|`：把**合计行（表尾）**和普通数据行分开，表尾渲染得更醒目。

`caption=` 自动给表编「表 N」号，`id=` 供第 9 课的跳转使用。

**动手做：** 写一个 `table`：三列（商品、数量、单价），两行数据，表尾用 `|==|` 加一行合计，`caption` 取「购物小计」。

**答案：**

```prt
::: table id="t-buy" caption="购物小计"
| 商品 | 数量 | 单价 |
| :--- | ---: | ---: |
| 牛奶 | 2 | 8.00 |
| 面包 | 1 | 12.00 |
|==|
| **合计** | 3 件 | — |
::: end table
```

**为什么这样写：** `|==|` 把「合计」行和普通数据分开、`**合计**` 加粗让它第一眼可见，`caption` 让表格有自动编号、`id` 让它可以被 `[[ref:t-buy]]` 引用。

**新手常见坑：**

- 合并时「主格」又用了被合并的格（连环合并）——规范禁止，会报错或被自动简化；
- 表格每行的格子数不一致，导致错位；
- 导出纯文本时合并会显示成 `(合并)` 占位（第 13 课），属正常现象。

**本课三句话：** ① 竖线表格两行起步：表头行 + 分隔行；② `++` 跨列、`^^` 跨行、`|==|` 分出合计行；③ `caption=` 自动编号、`id=` 可跳转。

**下一课：** 让文档「算起来」——PRTA 计算与安全小程序。

# ＋ 第 10 课　（接学）表格合并的边界规则小注

学合并时，记住几条（完整版见《PRT 简明标准》第 10.3 节）：

- 主格不能再是被合并的格（禁止连环合并）；
- 表头里的合并不能跨到表体；
- 表尾（`|==|` 之后）不参与跨行合并；
- 违反以上任一条，严格模式报错、宽松模式把合并展开成独立格子。

新手记住「别连环合并、别让合并越界」就够。

# 第 11 课　让文档自己算：PRTA 计算与安全小程序

**学完这一课，你能做的事：**

- 用 `::: run` 写一段 PRTA，让文档自己算；
- 用 `[[output:ID]]` 在正文里指定「算出来的值显示在这里」；
- 用 `IF` 判断、`WHILE` 循环，把分支和重复逻辑写进同一个块；
- 知道怎么开启计算功能，以及为什么它叫「安全」小程序。

**先记住这一课的总纲：PRT 里只有一种计算，叫 PRTA。** 正文里没有「填空题」、没有 `if` 卡片、没有 `loop` 卡片——`::: set`、`::: if`、`::: loop` 和 `{{ }}` 这类写法在现在的 PRT 里**都不存在**（照旧写会报 `E_LEX`）。**凡是想算，就写一个 `::: run` 块，块里写 PRTA，再用 `EMIT` 把结果送到正文里 `[[output:ID]]` 声明的位置。**

先有一个心理准备（重要）：**自动计算默认是关着的**。你的工具要打开计算功能才能看到效果（例如命令行加 `--run=allow`）。没开时，相关代码会按「普通代码块」显示出来，**不报错**——这是有意设计：文档作者要主动声明「本文档要计算」，工具才执行。

为什么叫「安全」的小程序？因为它被关在一个隔离的环境里：**不能联网、不能读写你电脑上的文件、不知道现在几点、也没有随机数**，能用的只有工具内置的一小批函数，能算多久也有额度上限。好处是：同一份文档在任何工具上算出的结果完全一致，也不用担心文档「乱来」。

## 一、在正文里显示算出来的值

```prt
总价：[[output:总价]] 元。

::: run lang="prt" id="算总价"
LOAD    r0, 12.50
LOAD    r1, 3
MUL     r2, r0, r1
EMIT    @总价, r2
::: end run
```

上面这段会显示「总价：37.50 元」。拆开看两件事：

- `[[output:总价]]` 是一个**行内指令**：它写在正文里、可以和文字挤在同一行，意思是「这里有一个叫『总价』的输出端口，算出来的值就显示在这个位置」；
- `::: run` 块里是 **PRTA**：`LOAD` 把数装进寄存器（`r0` 装单价、`r1` 装数量），`MUL` 相乘，`EMIT @总价, r2` 把结果送进那个端口。

三条关于端口的规矩，先记住：

- **先声明，后写入**：`[[output:总价]]` 必须写在写入它的 `::: run` 块**之前**——先定好位置，再算出来填进去。顺序反了报 `E_OUTPUT`；
- **一个端口只声明一处**：同一篇文档里端口名唯一，重复声明报 `E_SIGNATURE`；往一个没声明过的端口写，也报 `E_OUTPUT`；
- **写几次显示什么**：一次没写是空的，写 1 次就是那一个值，写 2 次及以上按写入顺序排成一个列表。

## 二、条件：按情况给出不同的结果

```prt
温度评价：[[output:评价]]

::: run lang="prt" id="评温度"
LOAD    r0, 28
LOAD    r1, 30
IF      r0, >=, r1
LOAD    r2, "太热了，开空调。"
EMIT    @评价, r2
ELSE
LOAD    r3, "还行。"
EMIT    @评价, r3
ENDIF
::: end run
```

`IF a, 关系, b` 比较两个值：成立就走 `IF` 与 `ELSE` 之间的一段，不成立就走 `ELSE` 与 `ENDIF` 之间的一段。关系只有六种：`==` `!=` `<` `<=` `>` `>=`。想「否则如果」就再嵌一层 `IF`，`ELSE` 可以省略。

注意：参与比较的数字也要先 `LOAD` 进寄存器（直接写 `IF r0, >=, 30` 不允许）。

## 三、循环：重复的内容写一遍

```prt
前三行：[[output:行]]

::: run lang="prt" id="列三行"
VAR i: Integer = 0
VAR 三: Integer = 3
WHILE i, <, 三
ADD    i, i, 1
EMIT   @行, i
ENDWHILE
::: end run
```

- `WHILE a, 关系, b` 反复执行到条件不成立为止；`ENDWHILE` 收尾；
- 上面这个端口被写了 3 次，所以显示成一个列表 `[1, 2, 3]`；
- 想中途跳出用 `BREAK`、跳过本轮剩下的部分用 `CONTINUE`；
- 循环不能「跑不完」——超过步数额度会被掐断（限额见《PRT 简明标准》11.1.11 节）。

## 四、安全小程序与内置函数

```prt
结果：[[output:加二 display="align=center; frame=card"]]

::: run lang="prt" id="加二"
LOAD    r0, 40
LOAD    r1, 2
ADD     r2, r0, r1
EMIT    @加二, r2
::: end run
```

`::: run` 让文档自己算一段。**结果不显示在块原地**，而是显示在正文里 `[[output:加二]]` 那一行所在的位置。**块里只能写 PRTA**——一种「小汇编」（`LOAD`、`ADD`、`EMIT` 这样的指令），**不能**写 `let`、`print` 这类脚本写法，写了会直接报错。几个小约定先记住：

- **签名只写形参名**：`sig="(a,b)"`；没有参数就整个省略 `sig`；
- **返回值默认不显示**：`RETURN` 只是把值交回调用它的块；想让读者看到，就用 `EMIT @ID` 写进 `[[output:ID]]` 声明的端口（旧版的 `::: return` 已经废止）；
- **代码默认折叠**：块在原地显示成一行块头（`run` + 名字 + 状态）和两个按钮——点「运行」执行、点「展开源码」才看到代码；结果始终显示在 `[[output:…]]` 那一行。
- **出错不一定停**（v6.0 起）：块里某一行运行时出错（除零、类型不对、索引越界……），工具会**记下错误码 → 跳过这一行 → 继续往下跑**；被跳过的行什么也不做。碰上「超预算 / 超时 / 超内存」以及不安全能力越权这类红线错误，仍然立刻停。想恢复「错了就停」，给块加 `on-error="halt"`。
- **想知道错在哪，读 `$error`**：每个块/函数都有一个小格子存最后一次运行时错误的代码，用只读的名字 `$error` 读出来即可（例如 `LOADVAR r3, $error` 得到 `"E_NUM"`）。
- **常量先装进寄存器**（v6.0 起）：`ADD r1, r0, 5` 这样直接写数字不再允许——先 `LOAD r2, 5`，再 `ADD r1, r0, r2`。`IF n, <, 2` 同理，先 `LOAD r1, 2` 再 `IF n, <, r1`。`VAR x: Integer = 5` 这种声明不是指令，不受影响。
- **逻辑从左往右算**：`AND` 与 `OR` 没有优先级，`a OR b AND c` 就是 `(a OR b) AND c`；要别的顺序请加括号。

上面这段还顺手给结果加了样式：`display="align=center; frame=card"`（居中 + 卡片外框）。**样式写在 `[[output:…]]` 上，不是写在 `::: run` 块上**——块上再写 `display`、`capture`、`type="prtopt"` 都会报 `E_SIGNATURE`。可用的样式键见《PRT 简明标准》11.1.15。

更多时候，直接用工具内置的现成函数更方便：

```prt
格式化结果：[[output:数字]]

::: run lang="prt" id="格式化"
LOAD    r0, 1234.5
FORMAT  r1, r0, "%,.2f"
EMIT    @数字, r1
::: end run
```

`FORMAT`（就是内置函数 `format`）把 `1234.5` 变成 `1,234.50`（千分位 + 两位小数）。**内置函数写成「函数名大写当操作码」的指令**，和 `ADD`、`MUL` 一个写法，比如 `UPPER r1, r0`。完整清单见《PRT 简明标准》附录 B——它们是仅有的可用函数，不能自己再造。

**三条「数字铁规矩」，帮你提前避开坑：**

1. 带小数的数是「金额式小数」：固定两位小数、按整数规则算——所以 `0.1 + 0.2` **永远是** `0.30`，不会出现 `0.30000000000000004` 这种诡异结果；
2. 给日期「加一个月」时，不存在的日子会收尾到当月最后一天：`dateAdd(@2026-01-31, 1, "month")` → `2026-02-28`（不是 2 月 31 日）；
3. 日期字面量**只能**写 `@` + 固定位数：`@2026-09-13`，要带时刻就 `@2026-09-13T10:30` 或 `@2026-09-13T10:30:00`。位数不够（`@2026-9-1`）、换分隔符（`@2026/09/13`）都会原样显示、不当成日期；形态像日期但日子不存在（`@2023-02-29`）会直接报错。

> **延伸阅读（选读）：** 为什么这样算、还有哪些内置函数，见《PRT 简明标准》第 11 章与附录 B。

**动手做：** 算「单价 12.50 × 数量 3」的总价，用 `[[output:总价]]` 显示在正文里；再写一个块，用 `IF` 判断 85 分是否及格（≥ 60 写「及格」，否则写「不及格」），结果写进 `[[output:结论]]`。

**答案：**

```prt
总价：[[output:总价]] 元。

::: run lang="prt" id="算总价"
LOAD    r0, 12.50
LOAD    r1, 3
MUL     r2, r0, r1
EMIT    @总价, r2
::: end run
```

```prt
结论：[[output:结论]]

::: run lang="prt" id="判及格"
LOAD    r0, 85
LOAD    r1, 60
IF      r0, >=, r1
LOAD    r2, "及格"
EMIT    @结论, r2
ELSE
LOAD    r3, "不及格"
EMIT    @结论, r3
ENDIF
::: end run
```

**为什么这样写：** 位置归正文、计算归块——`[[output:ID]]` 只负责「显示在哪一行」，`::: run` 只负责「怎么算」，两件事分开写；条件与循环是 PRTA 里的 `IF`／`WHILE`，不是文档层的卡片。记得：没开计算功能时这些会按代码块显示，是「省心」而非报错。

**新手常见坑：**

- 照旧写 `::: set 分数 = 85` 或 `{{ 分数 }}`——v4.0 起没有这两种写法（报 `E_LEX`）；值要么用 `LOAD` 装进寄存器，要么用 `EMIT $名, …` 写进计算变量；
- `[[output:X]]` 写在了 `EMIT @X` 那个块的**后面**——顺序反了，报 `E_OUTPUT`；
- 块里 `EMIT @X` 的 `X` 在正文里压根没声明——同样报 `E_OUTPUT`；
- 同一个端口名在文档里声明了两处——报 `E_SIGNATURE`；
- 计算没生效时，先检查工具有没有开启计算功能（`--run=allow`）。

**本课三句话：** ① PRT 只有一种计算：写 `::: run` 块，块里写 PRTA；② `[[output:ID]]` 声明「结果显示在哪一行」，`EMIT @ID` 把值送过去，声明必须写在块之前；③ 计算功能默认关闭、需显式开启，且被关在「不能联网、不能碰文件」的安全环境里。

**下一课（进阶选修）：** 给文档加按钮和输入框——让读者「点一下」就能改变文档里的数。不需要任何编程基础也能照抄出效果。

# ＋ 第 11 课（进阶选修）　给文档加按钮：让读者点一下就动

这一课是**选修**：学到这里你已经能写出漂亮的 PRT 文档了；这一课往前多走一步，让文档「动起来」——放一个按钮，读者点一下，文档里的数字就加一；放一个输入框，读者填个名字，文档就跟他打招呼。

不用任何编程基础：下面的例子**照抄结构、替换文字**就能用。看不懂的写法先不追问，跟着注释理解每行「在干什么」即可。

先做两件事：

1. 确认工具已开启计算功能（`--run=allow`，见第 11 课开头）；
2. 用一个运行块把计数器**建立**起来——变量不能凭空出现，得先 `EMIT $名` 写一次（没有 `::: set` 这种写法）。

## 一、最小例子：点一下，数字加一

```prt
::: run lang="prt" id="init" sig="()"
LOAD    r0, 0
EMIT    $计数, r0        ; 建立变量「计数」的初值
::: end run

::: run lang="prt" type="prtui" id="btn_add"
                  sig="()" ui="button" label="加一"
                  bind="$计数" on="click:on_add"
::: end run

当前计数：[[output:$计数]]

::: run lang="prt" id="on_add" sig="(evt)"
LOADVAR r0, $计数        ; 读出「计数」现在的值
LOAD    r1, 1
ADD     r2, r0, r1       ; 加一
EMIT    $计数, r2        ; 把结果写回「计数」
RETURN  null
::: end run
```

逐块拆开看：

- **第一块是「初值」**：变量得先被写一次才存在，`EMIT $计数, r0` 就是「建立变量『计数』、初值 0」（0 要先 `LOAD` 进寄存器）。
- **第二块是「按钮」**。`ui="button"` 表示按钮；`label="加一"` 是按钮上的文字；`bind="$计数"` 表示按钮旁回显变量「计数」的值；`on="click:on_add"` 表示「被点击时，去执行名叫 `on_add` 的处理块」。
- **第三块是「处理块」**，就是一个普通的 `::: run` 块。读者每点一次按钮，它就被完整执行一次：读出「计数」、加一、写回去。
- 写回之后，按钮的回显和正文的 `[[output:$计数]]` 会**自动刷新**——你不用做任何额外的事。正文里要显示一个计算变量，就写 `[[output:$变量名]]`。

## 二、再来一个：输入框 + 回车问好

```prt
::: run lang="prt" type="prtui" id="in_name"
                  ui="input" label="你的名字"
                  bind="$名字" on="submit:on_name"
::: end run

::: run lang="prt" id="on_name" sig="(evt)"
MAP_GET r0, evt, "value"   ; 从「事件包」里取出读者输入的文字
EMIT    $名字, r0          ; 把它存进变量「名字」
RETURN  null
::: end run

你好，[[output:$名字]]！
```

- `ui="input"` 是输入框；`submit` 表示「读者在框里回车确认」时触发；
- 读者按回车后，输入的文字装在一个「事件包」里交给处理块：处理块**恰好有一个参数**，这里叫 `evt`，就是这个包；`MAP_GET …, "value"` 从包里取出文字。

## 三、四种组件与三种事件（对号入座）

| 组件（`ui=`） | 长什么样 | 能触发的事件 |
|---|---|---|
| `button` | 按钮 | `click`（点击） |
| `input` | 输入框 | `change`（内容变更）、`submit`（回车确认） |
| `select` | 下拉选择 | `change`（改选某项） |
| `checkbox` | 复选框 | `change`（勾选切换） |

给组件绑事件时（`on=`），事件必须和组件对得上：`click` 只属于按钮，复选框只有 `change`。

## 四、背后发生了什么（理解一次就够了）

读者每次点击或输入，工具都会：① 生成一个「事件包」（里面有事件名、组件名、交互值）；② 把事件包当作参数，**从头到尾独立执行一遍**处理块；③ 处理块改过的变量和卡片回显随之刷新。每次执行都有自己的时长与额度限制、排队依次进行；处理块自己不可能再触发别的事件——所以按钮再多也不会「连环炸」。还有一条要记住：**变量变了只会刷新显示，不会自动重算别的块**——某个块想用到新值，要么被别的块显式调用，要么等读者再点一次；哪个块执行失败了，它的产出对外「读不到」（读取会报错），而不是悄悄给个空值。

**新手常见坑：**

- 事件和组件对不上（给复选框绑 `click`）——报错，按第 6 课排查；
- `on=` 里写的处理块名，和下面那个 `::: run` 块的 `id` 不一致——点了没反应；
- `bind="$计数"` 里的变量没有先用 `EMIT $计数` 建立（v4.0 起没有 `::: set`）——组件没有回显。

> **延伸阅读（选读）：** 组件的更多属性（`options` 下拉选项、`value` 占位提示）、事件载荷的完整键位与全部规则，见《PRT 简明标准》第 11.1.10 节；完整的组件与事件规范见《PRT 标准》第 19–24 章。

**本课三句话：** ① 组件块（`type="prtui"`）只负责「放控件」，处理块（普通 `::: run`）负责「被调用时做什么」；② 事件只有 `click`/`change`/`submit` 三种，和组件类型对号入座；③ 点一下 = 工具带着「事件包」把处理块独立执行一遍，改过变量后回显自动刷新。

# ＋ 第 11 课（进阶选修二）　不安全块：跑 Python、放开能力

**学完本节，你能做的事：**

- 知道「不安全块」是什么、和普通计算块差在哪；
- 会声明一个不安全块，并说清它什么时候会跑、什么时候要弹窗；
- 会用不安全函数读写「文档旁边的文件」，并发起网络请求、读时钟、取随机数、读环境变量。

## 一、给块「开闸」：两个新开关

普通计算块被关在安全笼子里：有步数上限、跑不完会被掐断、碰不到文件。想让块真正「图灵完备」（能写任何算法逻辑），有两个开关，写在块起始行上：

| 开关 | 效果 |
|---|---|
| `budget="unlimited"` | 解除这个块的全部限额——循环可以跑到自然结束、递归可以任意深。块还是翻译成安全环境执行 |
| `unsafe="true"` | 这个块改**编译成 Python** 执行：同样无限额，还多出一整组**不安全函数**（文件、网络、时钟、随机数、环境变量）；代价是它成了「不安全块」，受到下面第二节的严格约束 |

两个开关都只管**自己这一个块**；不写就一切照旧。工具可以在设置里禁用它们（禁用后块按普通限额跑、或显示说明），但不会悄悄失效。

## 二、不安全块的三条铁律

1. **打开文档永不自动执行。** 不安全块不参与文档加载——你打开一份带不安全块的文档，它只是静静躺在那里；它对应的 `[[output:…]]` 保持空（未执行）。
2. **每跑一次，弹窗一次。** 不安全块只有两种跑法：读者对这个块的**手动运行**，或按钮事件绑定了它时读者的交互。**每一次**执行前，工具都会弹出确认框（写明块名和「不安全代码」警示）；点确认才编译执行，点取消就什么都不发生。确认**不会被记住**——再跑一次，还要再问一次。
3. **别的块不能暗中调它。** `CALL` 指向不安全块会被直接拒绝（`E_UNSAFE`）——不让任何代码在读者不知情时绕过弹窗。

## 三、能多做什么、不能多做什么

**多的**：本地文件（六个函数，只能碰**文档所在目录（含子目录）**里的文本文件）、**网络访问**（HTTP 请求）、**系统时钟**（读当前时刻）、**随机数**、**环境变量**读取——

```prt
访问计数：[[output:log_visit]]

::: run lang="prt" id="log_visit" unsafe="true" sig="()"
LOADVAR r0, $访问次数
LOAD    r9, 1
ADD     r1, r0, r9
FILEWRITE r2, "visit-count.txt", r1
CLOCKNOW  r3
EMIT    @log_visit, r1
::: end run
```

文件函数：`fileRead` / `fileWrite` / `fileAppend` / `fileExists` / `fileList` / `fileDelete`。路径跑出文档目录、文档还没保存过，都会报 `E_UNSAFE`。

注意写法：**白名单函数和普通指令长得一样**——函数名大写后直接当操作码（`FILEWRITE r2, "a.txt", r1`、`CLOCKNOW r3`、`UPPER r1, r0`），不必也不该写别的前缀。

**绝不能做的**（两条硬红线）：**启动别的程序**（进程生成）与**动态代码执行**（不求值你现拼出来的代码字符串、反射调用）——这两样在任何块里都拿不到，工具也不会绕道标准库提供。安全块的其余规矩（输出去向、签名、写法）也全部照旧。

**新手常见坑：**

- 忘了弹窗是「每次都有」的——不是第一次问完就放行，跑十次问十次，这是设计不是毛病；
- 用 `CALL` 去调不安全块——直接报 `E_UNSAFE`，想跑就请读者手动运行；
- `fileWrite` 写了绝对路径（如 `C:\…`）——只能写文档旁边，相对路径即可。

**本节三句话：** ① `budget="unlimited"` 解除限额变图灵完备，`unsafe="true"` 再换 Python 跑道；② 不安全块打开文档永不自动跑，每跑一次弹窗一次；③ 多出来的是文件、网络、时钟、随机数与环境变量，唯独没有「启动程序」和「把文本当代码跑」。

> **延伸阅读（选读）：** 不安全块的完整规范（Python 转译基准、不安全函数表、`E_UNSAFE`）见《PRT 简明标准》第 11.1.14 节；预算解除的条款见第 11.1.11 节。

# ＋ 第 11 课（进阶选修三）　让结果好看、把逻辑复用

**学完本节，你能做的事：**

- 给运行结果显示的样子配样式；
- 把重复的逻辑写成自己的函数，随取随用。

## 一、给结果配样式：`display`

运行块算出来的值默认按主题样式显示。想让它更醒目，加 `display` 属性：

```prt
计算结果：[[output:汇总 display="align=center; size=18; weight=bold; frame=card"]]

::: run lang="prt" id="汇总" sig="()"
LOAD    r0, 1234
EMIT    @汇总, r0
::: end run
```

`display` 写在 `[[output:…]]` 上，和它在正文里的位置是同一处——**样式归端口，不归块**（块上写 `display` 会报 `E_SIGNATURE`）。

可用的键只有这七个：

| 键 | 取值 | 作用 |
|---|---|---|
| `align` | `left` / `center` / `right` | 对齐 |
| `color` / `background` / `shade` | 命名色（C.1）；`shade` 与 `background` 同义 | 文字颜色 / **底纹** |
| `size` | 正整数（磅） | 字号 |
| `font` | `sans` / `mono` / `serif` | 字族 |
| `weight` | `normal` / `bold` | 字重 |
| `frame` | `none` / `card` / `badge` / `quote` | 外框样式 |

写错键名或取值（比如 `shadow=1`、`align=middle`）会报 `E_LEX`；样式**只改外观**，不改任何计算结果。

## 二、把逻辑复用起来：`::: func`

一段逻辑要在好几个地方用？自己写个函数——它和运行块**平级**，放在块外面：

```prt
::: func 平方和(n)
VAR i: Integer = 1
VAR s: Integer = 0
VAR q: Integer = 0
WHILE i, <=, n
MUL  q, i, i
ADD  s, s, q
ADD  i, i, 1
ENDWHILE
RETURN s
::: end func

计算结果：[[output:汇总 display="frame=card"]]

::: run lang="prt" id="汇总" sig="(n)"
CALL  @平方和, r0, n
EMIT  @汇总, r0
RETURN r0
::: end run
```

- 调用方式和调用别的块一模一样：`CALL @名字, 目的, 实参…`；
- 名字全文档唯一，**不能**和任何块的 `id` 重名；函数**不能**嵌套定义；
- 函数**不随文档打开执行**，只在被调用时运行；
- 函数体里照样是 PRTA 指令：沙箱、内置函数、确定性一个不少。

**新手常见坑：**

- 把 `::: func` 写在 `::: run` 里面——不行，它俩平级；
- 函数名和块 id 撞车——报 `E_SIGNATURE`，改个名就好；
- 以为写了 `RETURN` 读者就能看到值——看不到；`RETURN` 只把值交回调用方，要显示得用 `EMIT @端口` 写进 `[[output:端口]]`（`::: return` 已废止）。

**本节三句话：** ① `display` 只改外观、不改值；② `::: func` 是「与运行块平级」的自编写函数，用 `CALL @名字` 调用；③ 函数只在被调用时执行，不随文档打开运行。

> **延伸阅读（选读）：** 完整条款见《PRT 简明标准》第 11.1.15 节；样式键与命名色的取值见第 12.1 节与附录 C。

# 第 12 课　换外观：颜色与主题

**学完这一课，你能做的事：**

- 给一段文字上色、设字号与对齐；
- 给整篇文档换主题，并做个性化微调。

## 一、给一段文字上样式

颜色**只能用「现成名字」**（如 `red`、`blue`），不能写 `#FF0000` 这类十六进制色号——这样所有工具渲染出来的颜色才一致：

| 类别 | 颜色 |
|---|---|
| 中性 | `black` `white` `gray` `navy` |
| 彩色 | `red` `orange` `yellow` `green` `teal` `blue` `purple` `cyan` `magenta` `brown` `olive` `maroon` |
| 按用途 | `danger`（危险）`warning`（警告）`info`（信息）`success`（成功） |

配上字号（`small` `normal` `large` `xlarge`）和对齐（`left` `center` `right` `justify`），用一张 `text` 卡片：

```prt
::: text color="danger" size="large" align="center"
发布前必读：先备份再发布。
::: end text
```

也可以只用对齐的简写：`::: align center … ::: end align`（`left`／`center`／`right`／`justify` 四个方向都能用）。

## 三、整篇统一：字体、磅数、底纹、水印（v2.1）

单块的外观用 `::: text` 管，**整篇**的外观用 `::: style` 管。写在正文之前、`meta` 之后，全篇只写一个：

```prt
::: style
align: left
font: 思源黑体, 微软雅黑, sans
size: 11
background: white
watermark: 内部资料 | angle=45 | opacity=0.08 | color=gray | size=48
::: end style
```

- **对齐**：`left`（默认）、`center`、`right`；哪一块想单独换方向，就在那一块的 `::: align` 或 `::: text align="…"` 里写。
- **字体**：写「白名单 + 回退链」，如 `font: 思源黑体, 微软雅黑, sans`——从左往右挑第一个本机装了的，最后一定退到 `sans`／`mono`／`serif` 之一，所以不会出现「字体缺失就打不开」。
- **磅数**：`size: 11` 直接写磅数（8–72）；块里也可以继续用档位（`small`／`normal`／`large`／`xlarge`），两种写法能混用——档位随主题缩放，磅数跨主题固定。
- **底纹**：`background: white`（写 `shade: white` 也一样）铺整篇底色；单块的底纹写在该块的 `shade=` 上。
- **水印**：`watermark:` 后先写文字，再用 `|` 接角度、透明度、颜色、字号。水印不编号、不进目录、不占版面；导出 Markdown 或纯文本时会被丢掉（不报错）。

**新手常见坑：** ① `::: style` 写了两处 → 报错；② 颜色只能用命名色（`white`、`gray`、`danger`…），写 `#fafafa` 会报错；③ 字体名不在白名单里（例如随手写「汉仪宋体」）→ 报错，换成白名单里的名字或通用族即可。

## 二、给整篇换主题

在 `meta` 里选：

```prt
::: meta
theme: "dark"
::: end meta
```

内置主题：`default`（默认）、`dark`（深色）、`print`（适合打印）、`accessible`（无障碍、高对比度）。想微调，用一张 `theme` 卡片覆盖预设的样式变量：

```prt
::: theme name="brand" base="default"
--link-color: blue
--page-bg: white
::: end theme
```

**重要的心智模型：主题只改外观，不动内容。** 写了一张「警告」，换什么主题它都还是警告，只是颜色变。

**动手做：** 用 `text` 卡片包一句红色、居中、大字的话；并在 `meta` 里把主题设成 `print`。

**答案：**

```prt
::: meta
theme: "print"
::: end meta

::: text color="danger" size="xlarge" align="center"
请先在低峰期执行。
::: end text
```

**为什么这样写：** `danger` 色与「要留神」的用途一致、`xlarge` 大字让读者一眼看到、`center` 居中适合这种「标语式」提示；主题 `print` 适合要打印/导出的场合。

**新手常见坑：**

- 写十六进制 `#FF0000`——不支持，只认现成颜色名；
- `text` 卡片忘了 `::: end text`（第 6 课的老毛病）；
- 以为换主题会改变内容含义——主题只改外观（见上）。

**本课三句话：** ① 颜色只用现成名字，四种「按用途」的颜色（danger/warning/info/success）最常用；② `text` 卡片管局部、`meta.theme` 管整篇、`theme` 卡片做微调；③ 主题只改外观，不改内容含义。

**下一课：** 一切就绪，最后一课把文档送出去——一份文件导出多种格式、理解「自动简化」。

# ＋ 第 12 课后　综合练习四（第 10–12 课）

**题目：** 写一小段销售汇总：用一个 `::: table`（含 `|==|` 合计行和 `caption=`）、一个 `::: run` 块算出件数并用 `[[output:件数]]` 显示在正文里、再用 `::: text` 给「重要」的结论句上一个警告色。

**参考答案：**

::: table id="t-s" caption="购物小计"

# 第 13 课　出口：一份文件，多种格式

**学完这一课，你能做的事：**

- 知道一份 PRT 能导出到哪些格式；
- 理解「自动简化」——某格式放不下某功能时，怎么不丢内容地呈现；
- 知道哪些文档能原样存成 Markdown。

## 一、能导出哪些格式

一份 PRT 文件可以导出：**HTML（网页）、PDF、DOCX（Word）、EPUB（电子书）、纯文本、Markdown**。用你的命令行工具，例如：

```bash
prt hello.prt                 # 默认（通常是网页）
prt hello.prt --out pdf
prt hello.prt --out plain
prt hello.prt --out markdown --run=allow
```

（具体参数以你所用工具的帮助为准，可 `prt --help`查看。）

## 二、理解「自动简化」

核心概念：某个格式放不下某个功能时，**不丢内容**，而是转成仍能读的朴素形式。几个常见例子：

| 功能 | 在装不下的格式里变成 |
|---|---|
| 高亮 / 上下标 | 去掉标记的普通文字 |
| 键盘按键 | `[Ctrl]` |
| 卡片（如 warning） | 前缀「[注意] …」 |
| 分栏 / 折叠 / 选项卡 | 按顺序纵向展开成连续块 |
| 脚注 | 正文留序号，文末集中列出 |
| 按钮 / 输入框 | 显示按钮文字本身 |

一句话记忆：**网页最全能；纯文本最朴素，但啥都不丢。**

## 三、可以原样存成 .md 的部分

如果你的文档只用「基础 Markdown」来写（第 1、2、3 课的基础语法 + 竖线表格，没有卡片、计算这些 PRT 特有东西），它就能**原样存成 `.md`** 交给任何 Markdown 工具使用——这叫「兼容写法」。

**动手做：** 把第 8 课的 `profile.prt` 导出成 HTML 试一次（用导出按钮或 `--out html`）。然后回答：导出后，文档里的 `::: warning` 在网页里还是带颜色的提示条吗？

**答案：** 是的。HTML 完整支持卡片，`warning` 会渲染成带颜色的提示条，这就是「网页最全能」的体现。如果导出的结果不是提示条，通常是那个工具没完整实现 PRT，可换支持 PRT 的阅读工具再试。

**本课三句话：** ① 一份源文件可导出网页/PDF/Word/电子书/纯文本/Markdown；② 放不下的功能会自动简化、内容不丢；③ 只用基础写法的文档可以原样存成 `.md`。

**下一课（收尾）：** 把这一路学到的串成一份正式文档——结课实战。

# 结课实战　把一份随手笔记变成正式文档

**学完这一课，你能做的事：** 独立把一堆「随手记录」组织成一份结构清晰、可发布、带一点计算的正式 PRT 文档。

下面是一份「需求清单」，请**独立完成**（尽量别缺项，缺了就回头查对应课）：

1. 有 `meta`，含 `title`、`version`、`lang`、`theme`；
2. 有一个 `summary` 摘要；
3. 至少两个一级 `section`，每个都有 `id` 和 `title`，其中一个含一个二级 `section`；
4. 正文里有一处高亮、一处脚注；
5. 有一到两个卡片（`warning` 或 `tip`）和一个小 `table` 表格；
6. 放一个 `[[contents depth=2]]` 目录；
7. 在某个 `section` 里用 `[[ref:…]]` 跳转到另一个 `section`，并用 `refs` 给其中一个章节起别名、用 `{别名}` 引一次；
8. 用一个 `::: run` 块算一个值（块里用 `IF` 判断），并用 `[[output:ID]]` 显示在正文里（数值随意）。

下面是**参考答案**（给你一个目标；你的写法不必逐字相同，语法正确、覆盖要求的项即可）：

```prt
::: meta
title: "一次周记的正式化"
version: "1.0.0"
lang: zh-CN
theme: "default"
::: end meta

::: summary
把随手记录的周记，整理成带章节、可引用、有计算的小文档。
::: end summary

[[contents depth=2]]

::: refs
回顾: ch-review
::: end refs

::: section id="ch-plan" title="本周计划"
- 周一移动端联调
- ==周三前== 提交设计稿
本计划的背景见 {回顾} 一篇。
::: end section

::: section id="ch-review" title="本周回顾"
进展顺利。^[结课回顾：记得补周报。]

::: warning
发布前请先跑一遍回归。
::: end warning

::: section id="sec-numbers" title="数字小结"
本周评价：[[output:评价]]

::: run lang="prt" id="评达标" sig="()"
LOAD    r0, 88
LOAD    r1, 60
IF      r0, >=, r1
LOAD    r2, "本周达标"
EMIT    @评价, r2
ELSE
LOAD    r3, "需要加油"
EMIT    @评价, r3
ENDIF
::: end run
::: end section
::: end section

::: section id="ch-data" title="数据附表"
::: table id="t-data" caption="一周打卡"
| 天 | 状态 |
| :-- | :-: |
| 周一 | 完成 |
| 周二 | 缺勤 |
|==|
| **共** | 2 天 |
::: end table
见下文 [[ref:ch-review|回顾]] 的说明。
::: end section
```

**为什么这样写：** 把「需求清单」逐条落到具体语法——`meta`/`summary`/`section` 搭骨架，`==高亮==`/`^[脚注]` 做强调与出处，`warning`/`table` 放风险与数据，`contents`/`refs`/`[[ref:…]]`/`{…}` 让文档可跳转，`::: run`＋`[[output:…]]` 加一点计算（条件判断写在块里的 `IF`）。它把教程拆散的零件，重新拼成一件成品。

**自查清单（对照你的版本）：**

- `meta` 里的分隔 `:::` 可留可删；
- 每个开头的 `:::` 都有配对的 `::: end`，开几个关几个；
- `refs` 别名的键和你 `id` 一致；
- 表格用了 `|==|` 表尾；
- 计算用的是 `::: run`＋`[[output:ID]]` 的正确写法（不是 `::: set`＋`{{ }}`，那两种写法已废止）。

**交作业：** 把这份结课实战文档导出成 HTML 和纯文本各一份，对比「自动简化」的表现——尤其那条 `::: warning` 在两种格式里的差异。

到这里，教程的「课内学习」就结束了。想看更精确的条条框框，去《PRT 标准》；想看通俗解释和类比，去《PRT 简明标准》；下一步该怎么走，看附录 C。

# 附录 C（资料性）　结课后去哪：定位、进阶路径与反馈

## 一、三本书的分工（别忘了定位）

| 册 | 是什么 | 给谁 | 特点 |
|---|---|---|---|
| 这本《PRT 教程》 | 教你怎么用 | 初学者 | 先给终点、先给工具、先给错误、先给路径；练得多 |
| 《PRT 简明标准》 | 条款体规范（通俗表述） | 想精确理解的人 | 覆盖完整、条条带约束词 |
| 《PRT 标准》 | 正式规范 | 实现者、审核者 | 严谨，符 ISO 风格，含符合性判定 |

一句话：**教程教你走路，简明标准给你通俗的边界，正式标准给你精确的边界。**

## 二、如果你还想继续深入（进阶路径）

- **想把文档写得更有条理** → 重读《PRT 简明标准》第 8 章（卡片与嵌套规则）、第 9 章（章节与跳转的完整规则）；
- **想把计算玩得更熟** → 读《PRT 简明标准》第 11 章与附录 B（内置函数全清单），把 `::: run`、`EMIT` 与 `[[output:ID]]` 用得游刃有余；
- **想搞懂按钮背后的机制** → 读《PRT 简明标准》第 11.1 节（后端语言 PRTA 的完整规范：存储、指令、事件模型）；
- **想知道「哪些是必须的」**（必须/建议/可选择的规范说法：应/宜/可/不得）→ 读《PRT 简明标准》第 14 章（合规）与第 4.1 节（措辞强弱）；
- **想实现自己的 PRT 工具** → 读《PRT 标准》第 14 章（符合性要求）与附录 B（内置函数），并对照附录 D（测试用例）逐步实现；
- **想参与 PRT 标准制定** → 通过 Perisc俱乐部标准化委员会指定的反馈渠道提交意见（勘误、修订建议），做法见《PRT 标准》「维护与反馈」一章。

## 三、从「写完」到「交付」的四个好习惯

1. **先登记再引用**：要引用就先给 `id`（或写 `refs`），否则严格模式会报错。
2. **能用鼠标解释的就别硬背**：`==` 高亮、`^` 上标脚注、`++` 表格合并，遇到不确定就查《PRT 简明标准》速查与索引。
3. **别往文档里写「现在几点」**：PRT 没有运行时时钟，要日期就在 `::: run` 里用 `LOADMETA rd, "page.date"` 读出来、再 `EMIT @ID` 写进 `[[output:ID]]`，文档才不会「过期」。
4. **交付前切严格模式跑一遍**：让工具把所有「兜底」的告警都揪出来，再正式对外。
