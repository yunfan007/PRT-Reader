# PRT 阅读器 系统适配说明

> 编写：软体程式部　　评议通过：专家委员会

本文档记录 PRT 阅读器在不同平台上的行为一致性、依赖关系与限制条件，并单列
**跨平台限制**专节，供部署风险评估与后续迁移参考。

---

## 一、支持平台列表

| 组件 | 平台 | 版本范围 | 验证情况 |
| --- | --- | --- | --- |
| `Perisc.Safety.SafeGuard`（宿主启动器） | Windows x64 | Windows 10（1607+）、Windows 11、Windows Server 2016+ | 已在 Windows x64 + .NET 8.0.x 完成编译与端到端验证（含哈希不一致拒启、双击无参推断启动与图形启动界面） |
| `Prt.App`（桌面应用，DLL 形态） | Windows x64 | Windows 10（1607+）、Windows 11、Windows Server 2016+ | 已在 Windows x64 + .NET 8.0.x 完成编译、自检与功能验证 |
| `Prt.App`（桌面应用） | Windows ARM64 | 同上（需 ARM64 版 .NET Desktop Runtime） | 未验证；理论上可用，未做兼容性测试 |
| `Prt.Core`（类库） | Windows / Linux / macOS | 任意支持 .NET 8 的平台 | 已在 Windows x64 完成编译与自检验证；代码不调用任何 OS 专有 API |

**目标框架**：类库 `net8.0`；桌面应用与宿主启动器 `net8.0-windows`（WPF）。
`Perisc.Safety`（安全模块一/二/四）目标框架为 `net8.0`，但内含 Windows 平台特定实现（见 4.6 节）；
`Perisc.Safety.SafeGuard`（模块三）为 `net8.0-windows`——双击启动时它要显示「安全系统启动中」的
图形界面（原生 WPF），且本来就依赖 Windows 作业对象，目标框架如实反映其平台限定；
从命令行启动时不建该窗口，WPF 只在那条路径上被用到。

**结论**：解析与导出能力（`Prt.Core`）是平台无关的；图形界面（`Prt.App`）与安全接入
（`Perisc.Safety` 的收口层、`SafeGuard` 启动器）为 Windows 专有实现。

| 文件对话框 | `src/Prt.App/Views/MainWindow.xaml.cs` | `Microsoft.Win32.OpenFileDialog` / `SaveFileDialog` |

### 4.2 所依赖的系统特性

| 依赖 | 具体内容 |
| --- | --- |
| 目标框架限定 | 界面层与宿主启动器 `net8.0-windows`；两者都使用 `UseWPF=true`，引入 `PresentationFramework`、`PresentationCore`、`WindowsBase` |
| 运行时组件 | `Microsoft.WindowsDesktop.App`（Windows Desktop Runtime），界面层与宿主启动器需要（启动器只在显示启动界面时用到 WPF，不装则启动器根本无法运行） |
| 桌面窗口系统 | Win32 窗口、消息循环、DPI 感知 |
| 系统文件对话框 | Windows 通用对话框（`Microsoft.Win32` 命名空间） |
| 系统字体 | `Microsoft YaHei UI`、`Segoe UI`、`Consolas` |
| 图像编解码 | Windows Imaging Component（WIC），经 `BitmapImage` 使用 |
| 命名管道 | 子进程（主程序）↔ 父进程（宿主启动器）的本地 IPC（`System.IO.Pipes`） |

**Windows 专有 API 清单**（可移植性评估据此逐项判断，详见 4.6 节）：

| 位置 | 用到什么 | 缺失时的行为 |
| --- | --- | --- |
| `Theming/DarkTitleBar.cs` | `dwmapi.dll!DwmSetWindowAttribute` | 静默忽略；标题栏保持系统配色 |
| `Perisc.Safety/SafeRuntime.Data.cs` | 剪贴板的 `user32.dll` / `kernel32.dll` P/Invoke（`OpenClipboard` / `GetClipboardData` / `SetClipboardData` / `GlobalAlloc` 等），实现 `DEV-04` / `DEV-05` | 调用失败即按 `PssCode.Internal` 返回（不执行成功、不静默成功） |
| `Perisc.Safety/SafeRuntime.File.cs` | 用户目录枚举（`Environment.SpecialFolder`：文档 / 图片 / 音乐 / 视频 / 桌面 / 下载），用于判定写入落点 | 缺失的目录被跳过，落点判定退化为「非用户目录」，行为仍 fail-closed |
| `Perisc.Safety/SafeRuntime.Process.cs` | `HKCU` 注册表（`CFG-01`、`PROC-07` 开机自启）、文件关联（`CFG-02`）、`schtasks.exe`（`PROC-06`） | 按执行失败返回（`PssCode.Internal`） |
| `Perisc.Safety.SafeGuard/*` | 进程树追踪的**作业对象**（`kernel32!CreateJobObject` / `AssignProcessToJobObject` / `TerminateJobObject` / `QueryInformationJobObject`） | 守护的终止能力不可用——这是**接入模式 A 成立的前提之一** |
| `Perisc.Safety.SafeGuard/GuardStore.cs` | `%LOCALAPPDATA%` 下的存储目录（仅当前用户可写） | 启动器打印「存储初始化失败」并退出 |
| `Perisc.Safety.SafeGuard/GuardConsole.cs` | 控制台的附加与标准流重接（`kernel32!AttachConsole` / `GetConsoleProcessList` / `GetStdHandle` / `SetStdHandle` / `CreateFileW`），以及启动失败时的 `user32!MessageBoxW` | 非 Windows 上该文件不参与编译；启动器是 GUI 子系统进程、本就不建控制台，故命令行输出无处可去（双击时改弹窗），不影响任何安全行为 |

### 4.2.1 全工程 P/Invoke 与 COM 互操作清单

仅以下文件含 P/Invoke；**没有** COM 互操作、**没有** GDI+ 直接调用：

| 文件 | 声明 | 用途 |
| --- | --- | --- |
| `Prt.App/Theming/DarkTitleBar.cs` | `dwmapi.dll!DwmSetWindowAttribute` | 深色标题栏（调用失败静默忽略） |
| `Perisc.Safety/SafeRuntime.Data.cs` | `user32.dll` / `kernel32.dll` 的剪贴板 API | SRT 的 `DEV-04` / `DEV-05` 收口实现 |
| `Perisc.Safety.SafeGuard/GuardJob.cs` | `kernel32.dll` 的作业对象 API | 进程树追踪与彻底终止（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`） |
| `Perisc.Safety.SafeGuard/GuardConsole.cs` | `kernel32.dll`（`AttachConsole` / `GetConsoleProcessList` / `GetStdHandle` / `SetStdHandle` / `CreateFileW`）、`user32.dll`（`MessageBoxW`） | 命令行启动时附加父控制台并把标准流重接过去（**先记后接**：附加会把"继承来的"句柄顶成父控制台的，故附加前记下、附加后把调用方给的装回）；无控制台时以弹窗报告启动失败。**只影响窗口与输出的去处，不参与任何安全裁决** |

四处都已按平台标注（`SupportedOSPlatform("windows")`）或用 `DefaultDllImportSearchPaths(SafeDirectories)`
收敛搜索路径（防 CA5392）。移植到非 Windows 平台时删除对应文件即可；除上述四处外无其他耦合。

其中 `GuardConsole` 的每次调用都包在 `try/catch` 里，且判定取**保守侧**：任何异常都按「没有控制台」
处理（退回图形路径——那条路上失败有弹窗兜底），绝不把「拒绝启动」变成一句没人看得见的 stderr；
接管失败与弹窗失败都不向上抛（它们只关系窗口与输出的去处，不该影响启动结果）。

### 4.3 非支持平台上的行为表现

| 平台 | 行为 |
| --- | --- |
| Linux / macOS 上运行 `Prt.App` | **无法运行**。该程序集目标框架为 `net8.0-windows`，在这些平台上无法加载；发布阶段即会因缺少 Windows Desktop 运行时目标而失败 |
| Linux / macOS 上运行 `Perisc.Safety.SafeGuard` | **无法运行**。该程序集目标框架为 `net8.0-windows`（启动界面为原生 WPF），在这些平台上无法加载；即便绕开加载限制，进程树追踪依赖 Windows 作业对象（`kernel32`），缺失时守护的终止能力也不可用——而这是接入模式 A 成立的前提 |
| Linux / macOS 上使用 `Prt.Core` | **完全可用**。`dotnet build src/Prt.Core/Prt.Core.csproj` 可在这些平台执行，产物可被任意 .NET 8 宿主引用 |
| 无桌面环境的 Windows（如 Server Core 无 GUI 会话） | 无法显示窗口；但 `--selftest` 模式**不创建窗口**，可用于无头环境下的解析与导出验证 |

### 4.4 替代方案与模拟策略

若需在非 Windows 平台提供图形界面，建议按「保留 Core、替换宿主」的方式实施，改动范围可控：

1. **复用解析与导出层（零改动）**
   `Prt.Core` 不引用任何 WPF 类型，可在任意 .NET 8 平台直接引用；
   `PrtParser.Parse` 与 `HtmlRenderer` / `MarkdownRenderer` / `PlainTextRenderer`
   提供完整能力。

2. **替换界面宿主（推荐方向）**
   将 `Prt.App` 的界面层替换为跨平台 UI 框架，例如 **Avalonia UI**（XAML 语法与 WPF 相近，
   迁移成本最低）。需重写的部分集中在本节 4.1 表格所列文件；`Prt.Core` 无需改动。

3. **降级为 Web 呈现（备选）**
   利用 `HtmlRenderer` 输出 HTML，在任意平台的浏览器中查看。该方式放弃了原生编辑体验
   （本工具当前架构下不使用 WebView），但可作为只读分发渠道。

4. **模拟策略：无头服务化**
   在服务器（含 Linux）上以 `Prt.Core` 为基础，配合 `--selftest` 式的批处理入口，
   实现「PRT → HTML / Markdown / 纯文本」的批量转换服务；已有的 `SelfTest` 代码给出了
   完整的调用示例。

### 4.5 编码与地区适配

| 项目 | 处理方式 |
| --- | --- |
| 文件编码 | 统一 UTF-8（读取剥离 BOM、写入不写 BOM） |
| 行尾 | 解析前统一规范化为 LF；输出统一使用 LF |
| 数字与日期格式 | 内部一律使用 `CultureInfo.InvariantCulture`，不受系统区域设置影响 |

### 4.6 安全接入（PSS）的跨平台限制

> 这一节单列，是因为它和 4.1 ~ 4.5 的性质不同：前几节的限制来自**图形界面**，
> 换掉 UI 框架就能绕开；这一节的限制来自**操作系统的安全设施**，绕不开。

PSS 的四层安全模块里，模块一 / 二 / 四（`Perisc.Safety` 的进程内库）是纯托管实现，
但**模块四 SRT 的实现体**与**模块三宿主启动器**都含 Windows 专有依赖：

| 能力 | 依赖 | 非 Windows 上的后果 |
| --- | --- | --- |
| 进程树追踪与彻底终止（6.2.4） | Win32 作业对象（`CreateJobObject` / `AssignProcessToJobObject` / `TerminateJobObject`） | 无法保证「终止含全部后代进程」，守护能力不成立 |
| 剪贴板读写（`DEV-04` / `DEV-05`） | `user32.dll` / `kernel32.dll` P/Invoke | 返回 `PssCode.Internal`（不执行成功、不静默成功） |
| 注册表配置（`CFG-01`）、开机自启（`PROC-07`） | `Microsoft.Win32.Registry`（`HKCU`） | 按执行失败返回 |
| 计划任务（`PROC-06`） | `schtasks.exe` | 命令不存在，按执行失败返回 |
| 文件关联（`CFG-02`） | `HKCU\Software\Classes` | 按执行失败返回 |
| 宿主启动器存储（6.2.1） | `%LOCALAPPDATA%` 下仅当前用户可写的目录 | 存储初始化失败，启动器退出 |
| 宿主启动器的启动界面（双击时的「安全系统启动中」窗口） | `Microsoft.WindowsDesktop.App`（WPF）与桌面窗口系统 | 无法显示；且启动器程序集本身目标框架为 `net8.0-windows`，在非 Windows 上连加载都不成立 |

**结论**：把阅读器搬到非 Windows 平台，不只是「换个 UI 框架」——接入模式 A 所需的
模块三（宿主启动器）与模块四（SRT 的 Windows 侧实现）都要重做。若目标平台不是 Windows，
按 3.7 的正确路径是**模式 B（桥接全接入）**：由 Windows 侧的 SafeGuard 启动桥接宿主，
非 Windows 侧经线协议（7.2）接入；本仓库未提供桥接宿主实现。

**界面层的可移植性不受本节影响**：`Prt.Core` 完全平台无关，4.4 的替代方案依然成立；
但替换后的宿主若仍要接入 PSS，必须先解决上表所列的 Windows 依赖。

## 五、已知限制

### 5.1 功能范围限制

| 限制 | 说明 | 依据 |
| --- | --- | --- |
| 不支持 COMP 等级 | 无变量求值、条件、循环、受限运行与附录 B 白名单函数；`{{ }}` 输出原文，计算块输出源码 | 本实现声明符合等级为 EXT |
| 无 PDF / DOCX / EPUB 输出 | 标准第 13 章中的这些输出目标未实现 | `PrtCapabilities.ComplianceStatement` |
| 无公式排版引擎 | 公式块按降级方式以等宽源码呈现 | 标准 9.4 的降级路径 |
| 不加载远程图片 | `http://` / `https://` 图片仅显示占位符，不联网 | 离线一致性与安全策略 |
| 不支持正则搜索 | 查找替换为纯文本匹配（可区分大小写） | 交互设计选择 |
| 程序自带无网络功能 | 无更新检查、无遥测、无远程资源加载（PSS 9.1 离线优先） | 安全设计选择 |
| 每次敏感行为默认要用户答复 | 4.6 的行为项默认裁决为 `deny`（须显式申报）；界面首次触碰某对象时会弹授权窗，选「本次会话内允许」可减少询问 | PSS 4.4 默认拒绝 |
| 授权弹窗有申报超时 | 2 分钟不答复按 `Deny + Timeout` 处理，该次操作不执行 | PSS 4.3 第 3 条 |
| 不能双击主程序 | 主程序是 DLL，接入模式 A 下唯一入口是宿主启动器；**双击启动器即可**，不需要参数（它在同目录内推断主程序） | PSS 3.4 / 7.1 |
| 双击启动时看不到输出 | 启动器是 GUI 子系统程序，双击时**没有控制台**（这正是"不挂黑框"的做法：不产生，而不是产生了再藏）；同一批信息记入 `%LOCALAPPDATA%\Perisc\SafeGuard\events\`，启动失败则以弹窗告知。从命令行启动时输出照常（含 `2> 日志.txt` 这类重定向） | 交互设计选择（见[行为清单](行为清单.md)「启动方式」） |
| 「安全系统启动中」界面只在双击时出现 | 从命令行启动、或经启动器跑自检时都不显示该界面；它是观感增强，缺失不改变任何安全行为 | 交互设计选择（见[设计取舍](设计取舍.md)第 11 条） |
| 「安全系统启动中」界面显示多久 | **至少 800 ms**：启动器把界面显示满 800 ms 之后**才**启动主程序，故这 800 ms 内屏幕上没有第二个窗口能盖住它（2026-09-26 实测、对发布产物：界面 0.61 s 首次可见、2.20 s 最后可见，阅读器启动画面 2.32 s 才出现，间隔 1.71 s ≥ 0.80 s）。界面刻意不置顶，主程序的窗口一出现即自然接上 | 同上 |
| 程序目录必须可写 | 本程序自己的配置与会话只落程序目录、不设 `%APPDATA%` 回退（见[设计取舍](设计取舍.md)第 13 条）。装到只读目录（如 `Program Files`）时保存设置与激活会明确报错提示，**不会**静默写到别处；把整目录复制到可写位置即可 | 绿色免安装的便携策略 |
| 首次启动会迁移旧位置配置 | 只针对历史版本写在 `%APPDATA%\{PRT 阅读器, PRT 工具, PSR 工具, MDP 工具}\` 的 `settings.json` / `session.json` / `resources\`，迁移一次后不再读写 `%APPDATA%`；旧目录中的授权凭据不读取、不删除 | 便携化改造的一次性过渡 |
| 安全模块数据仍在 `%LOCALAPPDATA%` | 审计、误报白名单、宿主启动器的白名单/事件/运行期基准快照**不**随程序目录存放：前者的落点由 PSS 6.1.6、后者由 6.2.1 规定（6.2.1 且要求该目录不得放宽为全机可写）。唯一例外是 `Safe.data`——它是**发布物**（由 `build.ps1` 生成、随包分发，与 `keys\` 同类），不是运行期数据，故在程序目录 | PSS 6.1.6 / 6.2.1（规范性） |

### 5.2 呈现层限制

| 限制 | 说明 |
| --- | --- |
| 预览与 HTML 导出非像素级一致 | 预览由 WPF 排版引擎渲染，HTML 由浏览器渲染，个别间距、断行位置可能存在细微差异；两者语义与内容一致 |
| 深色界面下的菜单下拉 | 菜单栏随界面配色变化，但下拉弹出菜单沿用系统配色（浅色底/深色字），在深色界面下外观不一致 |
| 无语法高亮 | 源码编辑区以等宽字体呈现，不做着色 |
| 超宽表格 | 表格以等宽比例列渲染，列数上限 128（超出部分截断并产生 `PRT0014`）；表内不提供独立横向滚动条 |
| 缩放为整体缩放 | 预览按 `LayoutTransform` 缩放，非整数倍时文字可能有轻微抗锯齿模糊 |
| 滚动同步为比例同步 | 两栏按滚动比例同步（近似的行对齐），非按段落锚点精确对齐 |

### 5.3 交互与状态限制

| 限制 | 说明 |
| --- | --- |
| 无会话恢复 | 退出后不记忆已打开的文档与滚动位置；无近期文件列表 |
| 无自动保存 | 仅在显式保存 / 导出时写盘；异常退出可能丢失未保存修改（有确认与兜底提示） |
| 单实例运行 | 重复启动会各自成为独立进程，不做单实例合并（仅避免同一文件重复标签） |
| 预览刷新防抖 | 编辑后约 280 毫秒方刷新；超大文档（超过 6 万字符）自动拉长防抖间隔 |
| 撤销深度 | 500 步 |
| 授权按副本隔离 | `license.key` 与 `activations.json` 只写在启动器与主程序所在目录，需该目录可写；只读目录下激活无法留存（窗口会提示写入失败）。相对地，本机多份副本的授权互不影响 |
| 授权不联网 | 签名验证只依赖内嵌公钥，激活次数也只记本副本，不做任何联网统计或上传 |
| 安全数据按用户走 | 审计、误报白名单、启动器事件与运行期基准快照落在 `%LOCALAPPDATA%\Perisc\`；换用户登录后是另一份（属用户数据，不与程序副本绑定）。**启动校验用的 `Safe.data` 不在此列**——它是发布物，随发布包走 |
| 升级要整对替换 | 运行体基准写在发布目录的 `Safe.data` 里：只换 `Prt.App.dll` 会被判 `HASH-MISMATCH`，漏掉 `Safe.data` 会被判 `BASELINE-MISSING`，两者都拒绝启动（见[部署文档 4.3](部署文档.md)） |

### 5.4 规模与性能特征

| 场景 | 表现 |
| --- | --- |
| 常规文档（数百行至数千行） | 编辑响应与预览刷新无可感知延迟 |
| 大型文档（约 1 万行） | 预览刷新约百毫秒量级 |
| 超大文档（数万行） | 进入渐进渲染：解析在后台线程执行，预览构建分批进行并显示进度条，全部就绪后一次性上屏，期间界面保持可交互 |
| 超大文档侧边栏大纲 | 数千条目走虚拟化列表（只实例化可见行），超过 300 条默认仅展开前两级，其余点击展开 |
| 防护上限 | 围栏嵌套深度 64（`MaxFenceDepth`）；表格列数 128（`MaxTableColumns`），用于抵御异常输入导致的资源失控 |

## 六、兼容性回归验证方法

平台或运行时升级后，建议按以下顺序验证：

1. `.\build.ps1 -Task 'lint,selftest,score'`——严格编译（0 警告）＋六条硬门禁＋自检＋自评，
   任一项不达标即非零退出码中止。自检等价于运行
   `dotnet exec src\Prt.App\bin\Release\net8.0-windows\Prt.App.dll --selftest 报告.txt`
   （接入模式 A 下主程序是 DLL，用 dotnet 宿主加载），应得到「通过 54 项，失败 0 项」。
2. 宿主启动器的两个用例（[部署文档 6.2.1](部署文档.md)）：正常启动应退出码 0；
   `--hash` 声明一个不匹配的哈希应退出码 3 且**不**启动主程序。
3. 按[部署文档 6.3 节](部署文档.md)的功能验收清单执行人工抽查。
4. 若升级涉及 .NET 运行时或 RID 变更，另核对：剪贴板读写、`HKCU` 注册表读写、
   作业对象终止（可临时观察启动器退出时子进程是否被一并收走）三项 Windows 专有路径。
