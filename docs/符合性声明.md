# 第一部分　PRT 规范符合性

## 一、符合等级

> **本渲染器符合 PRT v2.1 EXT 等级。**
> 已实现：全部 CORE 与 EXT 项。
> 未实现：COMP（受限计算）——变量求值、条件、循环、受限运行（run）、
> 附录 B 白名单函数、定点数运算与沙箱。
> 已知限制：COMP 结构按标准第 13 章降级处理（插值输出原文、计算块输出源码）；
> 不支持 PDF / DOCX / EPUB 输出目标。
> 符合性测试套件：《PRT 标准》附录 D（D.1 / D.4 / D.5 的 CORE 与 EXT 用例）。

该文本由 `PrtCapabilities.ComplianceStatement` 在代码中给出，可在程序内通过
菜单「帮助 → 符合性声明」查看，二者保持一致。

代码级硬性标注：

```csharp
public static class PrtCapabilities
{
    public const PrtConformanceLevel Level = PrtConformanceLevel.Ext;   // 声明等级
    public const bool SupportsComputation = false;                       // COMP 恒为 false
    public const string SpecificationVersion = "2.1";
}
```

所有涉及 COMP 的代码分支均以显式中文注释标注「【COMP 不支持】」。

> **⚠ 已知滞后（待办，不是已认可状态）**：仓库内当前发布的《PRT 标准》为 **v4.0**
> （2026-09-25，PRTA 语言规范已整体并入），本实现声明的基准版本为 **v2.1**。
> 两者在计算部分有实质差异：v4.0 采「唯一计算原则」——文档层不再有其它计算区，
> 一切计算＝一次 `::: run`（PRTA），并废止 `::: set` / `::: if` / `::: loop` / `{{ }}` /
> `::: return`，输出端口改由行内指令 `[[output:ID]]` 声明，元信息唯一通道为 `LOADMETA`。
> 因此本声明**尚未**按 v4.0 重新核定；在完成逐项对照（CORE / EXT 项集是否变动、
> COMP 降级行为是否需重写、第 14 章与附录 D 的编号是否移位）之前，**不得**把本声明的
> 版本号改写为 v4.0。此项已列入[部署文档第十节](部署文档.md)的遗留事项。

## 四、明确不支持的 COMP 项及其降级行为

本实现**不解析 COMP 的内部语义、不执行任何求值**，全部按标准第 13 章降级，
**不丢失内容**，并在诊断中给出 `PRT0009` 提示（非致命）。

| COMP 结构 | 本实现行为 |
| --- | --- |
| 内联插值 `{{ 表达式 }}` | 原样输出 `{{ 表达式 }}`（含原有空白），不求值 |
| 日期字面量 `@YYYY-MM-DD[…]` | 按词法回退为字面文本输出，不构造日期值 |
| 变量声明 `::: set 名称 = 表达式` | 捕获源码，不建立变量、不求值 |
| 条件 `::: if` / `elif` / `else` | 捕获全部分支源码，不判定条件、不选择分支 |
| 循环 `::: loop` | 捕获源码，不迭代 |
| 受限运行 `::: run` | 捕获源码，不执行 |
| 附录 B 白名单函数 | 全部不实现 |
| 定点数运算与沙箱 | 不实现 |
| `PrtOptions.EnableComputation` | **恒被忽略**：无论设为 `true` 或 `false`，均不产生任何求值行为 |

> 上表是本实现**当前**的降级行为（按 v2.1 的构造集）。对照 v4.0 的构造集（见第一节的已知滞后）
> 需重新核定后更新——v4.0 已废止 `::: set` / `::: if` / `::: loop` / `{{ }}` / `::: return`，
> 并新增行内指令 `[[output:ID]]` 与元信息通道 `LOADMETA`。

## 六、验证方式

### 6.1 启动自检（覆盖 54 项）

自检模式不显示窗口，覆盖「解析 → WPF 原生预览渲染 → 三格式导出 → 安全模块链路」整条链路，
可由构建脚本一键触发：

```powershell
.\build.ps1 -Task build,selftest
```

或直接调用（接入模式 A 下主程序是 DLL，用 dotnet 宿主直接加载）：

```powershell
dotnet exec src\Prt.App\bin\Release\net8.0-windows\Prt.App.dll --selftest 报告.txt
```

经宿主启动器（发布形态下的正常路径）：

```powershell
Perisc.Safety.SafeGuard.exe -- --selftest 报告.txt
```

覆盖 **54 项**检查：示例文档严格模式解析、四个内置主题的原生渲染、文档内主题叠加解析、
语义块渲染（12 种类型均呈现为带底色与侧边线的提示框）、相对路径图片解析、
三格式导出、COMP 降级行为、许可证签发与校验全链路、授权存储便携性、
**界面设置与会话的便携落点（只认程序目录，不写 `%APPDATA%`）**、
**旧位置配置的一次性迁移（写入并校验一致才删旧文件；已有同名文件则跳过且不删；启动图按字节比对）**、
**落点不可写时给出可读原因且不改写别处**、
**配置类数据（设置 / 会话 / 启动图 / 授权 / 异常日志）的读写不经安全模块申报（启动期无人答复时仍可用）**、
**预览就地编辑（滚动锁定式）的提交写回与取消、滚动锁定随编辑态启停**、
时钟回拨不延长许可、审计落盘/损坏行/并发/降级/接管、申报异步与超时语义、
界面挂钩按客户端隔离、运行时与守护客户端的释放契约。
退出码 `0` 表示全部通过（`1` 存在失败项；`2` 报告写入失败）。
详见[部署文档 6.2 节](部署文档.md)。

### 6.2 宿主启动器的反绕过验证

| 用例 | 期望 |
| --- | --- |
| 首次经启动器运行（发布包完整） | 按同目录的 `Safe.data` 核对运行体通过，正常启动主程序，退出码 0；**不写任何本机基准** |
| 删掉同目录的 `Safe.data` 后再启动 | **拒绝启动**、stderr 打印 `BASELINE-MISSING` 与事件号、退出码 3，主程序**未**启动 |
| 启动器运行期间从外部写 / 删 `Safe.data` | **失败**（句柄独占持有：`FileShare.Read`，写入与删除都要额外的共享许可） |
| 运行体被改动后再启动（`--hash` 声明不一致） | **拒绝启动**、stderr 打印 `HASH-MISMATCH` 与事件号、证据摘要为 `sha256:…`，退出码 3，主程序**未**启动 |
| 主程序 DLL 缺失或路径错误 | 拒绝启动并给出原因，退出码 2 |

> 双击时另会显示一个「安全系统启动中」观感界面（原生 WPF，见《设计取舍》第 11 条）。
> 它**不参与**上表任一判据：校验、作业对象、命名管道与终止规则一律照旧；界面自身失败只会
> 静默退场，不会让原本应当启动的进程失败。该界面至少显示 800 ms——启动器显示满 800 ms 之后
> **才**启动主程序，故这段时间内没有别的窗口能压住它。

## 七、解读本实现时的补充约定

《PRT 标准》在个别细节上未给出唯一确定的规定，本实现在实现时作出了如下选择，
在此明确声明，以便符合性判定时对照：

| 事项 | 本实现的选择 | 依据 / 理由 |
| --- | --- | --- |
| 命名色的具体 RGB 值 | 标准未规定；本实现定义了一套确定性调色板（20 色），并允许 `::: theme` 按附录 C 变量逐项覆盖 | 保证渲染可复现 |
| 表格 `++N` / `^^N` | `++` 表示左侧主格向右多跨 1 列，`++N` 表示再多跨 N 列；`^^` 同理向下 | 与「独立标记即最小合并单位」的自然读法一致 |
| `meta.glossary` 写法 | 取值为 `<术语>=<定义>`，多条以 `;` / `；` 分隔 | 与 `meta` 的「键: 值」行语法兼容 |
| 隐式标题编号 | 未包裹于 `section` 的基础标题参与编号与目录 | 遵循标准 9.2 的规范性说明 |
| 计数器划分 | 表、图、公式各自独立计数；章节与隐式标题共用层级计数器 | 使编号与常见排版惯例一致 |
| 主题作用范围 | 主题仅覆盖附录 C 所列样式变量，不接受任意样式规则；主题只改外观、不改语义 | 标准 12.2 |
| 诊断排序去重 | 按行号、列号升序；同一「位置 + 代码 + 内容」合并为一条 | 标准 14.4 |
| 严格模式优先级 | 渲染器显式配置优先于文档内 `strict` 声明；均未指定时按严格处理 | 标准 14.4 |
| 围栏与表格上限 | 围栏嵌套深度 64、表格列数 128，超出即截断并报诊断 | 标准 16.2 的资源防护要求 |
