# 质量检查表

> **本文件的角色**：把「怎么验」写死。机器能判的给命令与期望值；只能人判的给判据与打勾栏；口径存两解或证据表述有偏差的，登记到「三、已知例外」。
>
> 配合文件：《分析器门禁》（规则与基线）、《设计取舍》（为什么这样做）、《自评报告》（`selfscore.py` 生成的可复算结果）、《行为清单》（申报范围）、《符合性声明》（对外结论）。
>
> 依据：**PSS（CSRO-CRS-26001）v2.0** 9.6 / 12.1 / 12.4；**PRT 标准** CSRO-GTS-26001。

## 一、机器可判项（复核命令 + 期望值）

一条命令跑完全部机器可判项：

```powershell
.\build.ps1 -Task 'lint,selftest,score'
```

| # | 检查项 | 命令 | 期望值 | 失败即代表 |
| --- | --- | --- | --- | --- |
| 1 | 严格编译 | `.\build.ps1 -Task build` | **0 错误 / 0 警告**（`-warnaserror`，有警告即失败） | 新增代码引入了分析器告警或编译错误 |
| 2 | 6 条硬门禁 | `.\build.ps1 -Task lint` | D-09 / D-22 / D-14 / D-07 / D-17 / D-20 全部 ≤ 0 | 出现空 catch、非事件处理器 `async void`、UI 阻塞、公开可写静态字段、区域敏感比较、直接读系统时间 |
| 3 | 启动自检 | `dotnet exec src\Prt.App\bin\Release\net8.0-windows\Prt.App.dll --selftest 报告.txt` | 退出码 **0**，报告末行「通过 **52** 项，失败 0 项。」 | 解析 / 渲染 / 三格式导出 / 激活 / 设置 / 便携落点 / 安全链路有功能回归 |
| 4 | 可维护性维度 | `.\build.ps1 -Task score` | ≥ **B-**（`r_maint` 棘轮基线，见《分析器门禁》五） | 新增代码让 A 组或 B 组扣分上升 |
| 5 | 分析器 `error` 档 | 同上（门禁脚本独立复核） | 9 条规则命中数均为 **0** | 见《分析器门禁》「三」 |
| 6 | 发布产物 | `.\build.ps1 -Task publish` | 唯一入口 `Perisc.Safety.SafeGuard.exe` ＋ 主程序 `Prt.App.dll` 同目录；另出激活码签发端与密钥（**俱乐部侧流转，不进安装包**） | 发布形态偏离接入模式 A（主程序必须是 DLL、无 apphost） |

> **自检也可经启动器跑**：`publish\framework-dependent\阅读器\Perisc.Safety.SafeGuard.exe -- Prt.App.dll --selftest 报告.txt`。标准启动方式**只有**启动器这一条（见《部署文档》6.1）；从源码直接运行属「未经启动器启动」，**不得**用于评估或认证。

## 三、已知例外

**口径分歧或证据表述有偏差的项，登记在这里。** 登记不等于豁免——它要求复核者知道「这里有第二种读法」或「证据在哪」。

### 例外 1：D-06 两种读法（计数口径分歧）

| 项 | 内容 |
| --- | --- |
| 规则 | D-06 一文件多类 / 超长方法 / region 滥用（建议，权重 1） |
| 口径 A（脚本采用） | **字面读法**：分母 = 多类型文件 53 个 + 超 60 行方法 62 个 + `#region` 0 处 = **115**，得分 **3** |
| 口径 B（另一种读法） | **只算承接行为的类型**：其中 4 个是「纯类型聚合文件」（整份文件只有 record / enum / 小类型声明，不承接行为，如 `Blocks.cs` 的 25 个块类型、`Types.cs` 的 26 个数据结构），多类型文件降为 **49** 个 |
| 处理 | 脚本**按字面读法计分**，并在证据里同时列出另一读法的计数，**供复核者按任一口径复算** |
| 影响 | `build.ps1` 注释已言明：可维护性从 B- 起算的差额**全部来自 D-06**；若改按口径 B，结论会变，因此**口径需人工确认** |
| 出处 | `build.ps1` 棘轮注释、`tools/selfscore.py` 的 `measure_d06`、《自评报告》D-06 段 |

### 例外 2：D-03b 目标语言惯例（命名口径分歧）

| 项 | 内容 |
| --- | --- |
| 规则 | D-03b 公共常量非全大写 / 命名不规范（建议，权重 1） |
| 冲突 | 9.6.4 的 D-03b 字面写「公共常量非全大写」，但同一行的「正确处理」是「遵循**目标语言通行命名规范**」——C# / .NET 的通行规范对公共常量是 **PascalCase**，不是 `SCREAMING_CASE` |
| 差额 | 字面读法 **127** 处 → 判 3；按目标语言惯例（C# 为 PascalCase）约 0 处 → 判 0。**具体数字以最近一次《自评报告》D-03b 段为准**（它随代码变动） |
| 处理 | 脚本取**交集**计分：只统计两种读法下**都**违规的（名字首字母小写），并在证据里给出字面读法的计数 |
| 出处 | `tools/selfscore.py` 的 `measure_d03b` |

### 例外 3：D-21 的 1 分档（合规放行，非缺陷）

| 项 | 内容 |
| --- | --- |
| 规则 | D-21 未启用 NRT / 忽略警告（重要，权重 2，封顶 B-） |
| 现状 | 判 **1** 分档：「已启用，但存在**已附理由**的规则放行」 |
| 说明 | 14 条 `none` 档规则**每条都已逐条附理由**（见《分析器门禁》四）。要降到 0 分档须把 14 条全部改为默认级别，那会推翻那些理由所指的既有决定，**不做** |
| 出处 | `tools/selfscore.py` 的 `measure_d21`、《分析器门禁》五 |

| 项 | 内容 |
| --- | --- |

## 四、改造验收门

任何**结构性改造**（拆分超大文件、重构调用链、替换依赖）都要过这道门。判据是**行为等价**——而「看起来等价」不算证据。

### 4.1 等价性证据怎么产生

自检的**结构指纹**是这条链路上最完整、最便宜的可比对产物：

| 产物 | 内容 | 生成方式 |
| --- | --- | --- |
| 三格式导出文本 | HTML / Markdown（兼容子集无损 + 显式降级）/ 纯文本 | 自检的解析与导出用例 |
| 预览渲染树指纹 | 块类型 / 行内类型序列 / 纯文本（逐块递归） + `anchors` 数 | 自检的预览用例 |

两者在设置环境变量后写入同一目录：

```powershell
# 改造前
$env:PRT_SELFTEST_SNAPSHOT = 'D:\tmp\snap-before'
dotnet exec src\Prt.App\bin\Release\net8.0-windows\Prt.App.dll --selftest before.txt

# 改造后
$env:PRT_SELFTEST_SNAPSHOT = 'D:\tmp\snap-after'
dotnet exec src\Prt.App\bin\Release\net8.0-windows\Prt.App.dll --selftest after.txt
```

**验收判据**：两次运行的三格式导出文本与预览指纹**逐字节一致**。

> 不设 `PRT_SELFTEST_SNAPSHOT` 时快照步骤**不做任何事**——它只服务改造验收，不参与日常自检，也不影响 54 项的结果。

### 4.2 改造前的基线采集

| # | 步骤 | 打勾 |
| --- | --- | --- |
| 1 | 改造前跑一次自检，**留存报告全文**（用例顺序决定报告行顺序，历次报告即比对基准） | ☐ |
| 2 | 改造前采集结构指纹到 `snap-before` | ☐ |
| 3 | 记录改造涉及的模块；若**未触碰** `Prt.Core` 的解析 / 匹配 / 编号与数据结构，需在改造说明里写明 | ☐ |
| 4 | 改造后重跑自检 + 采集 `snap-after` | ☐ |
| 5 | 两份报告项数与结果一致（**49/49**）；两份快照逐字节一致 | ☐ |
| 6 | 跑 `.\build.ps1 -Task 'lint,score'`，与基线逐项比对（不允许任何一项扣分上升） | ☐ |
