# PRT 阅读器 部署文档

> 编写：软体程式部　　评议通过：专家委员会

本文档说明 PRT 阅读器的运行环境要求、构建与发布方式、启动验证方法与运维要点。

---

## 一、环境依赖清单

### 1.1 操作系统

| 用途 | 要求 |
| --- | --- |
| 运行阅读器（`Perisc.Safety.SafeGuard` ＋ `Prt.App`） | Windows 10 版本 1607（内部版本 14393）或更高；Windows 11；Windows Server 2016 或更高 |
| 运行类库（`Prt.Core`） | 任意支持 .NET 8 的平台（Windows / Linux / macOS） |

> 桌面应用与宿主启动器均基于 WPF（`net8.0-windows`），**仅能在 Windows 上运行**；
> 类库 `Prt.Core` 与安全模块库 `Perisc.Safety` 不依赖 WPF，可在其它平台用于解析与导出。
> 详见[系统适配说明](系统适配说明.md)。
>
> **启动入口只有宿主启动器**：按 PSS 3.4 / 7.1 的接入模式 A，主程序 `Prt.App` 编译为 **DLL**，
> 不自带用户可直接双击的可执行入口；用户**双击 `Perisc.Safety.SafeGuard.exe`**（无需参数），
> 由它在校验运行体哈希后加载主程序。两个文件**必须放在同一目录**——启动器不带参数时
> 只在同目录内推断主程序。

### 1.2 运行时与开发工具

| 组件 | 版本要求 | 说明 |
| --- | --- | --- |
| .NET SDK | 8.0.x（LTS） | 构建与发布所需 |
| .NET Desktop Runtime | 8.0.x（x64），含 `Microsoft.WindowsDesktop.App` | 仅「框架依赖」方式运行桌面应用时需要 |
| .NET Runtime | 8.0.x | 仅「框架依赖」方式运行控制台/类库宿主时需要 |

验证安装：

```bash
dotnet --info
dotnet --list-runtimes | findstr WindowsDesktop
```

应能看到 `Microsoft.WindowsDesktop.App 8.0.x`。若缺失，安装
「.NET Desktop Runtime 8.0（x64）」。

### 1.3 第三方依赖

| 工程 | 第三方依赖 |
| --- | --- |
| `Prt.Core` | **无**（仅 .NET 基类库） |
| `Prt.App` | **无**（仅 WPF / .NET 基类库） |
| `Perisc.Safety` | **无**（PSS 安全模块一/二/四，本仓库自带源码） |
| `Perisc.Safety.SafeGuard` | **无**（PSS 模块三，本仓库自带源码） |

`Prt.Core`、`Prt.App` 与两个安全模块工程均不含任何第三方依赖，因此发布产物无需附带额外程序集；
首次构建仅需 .NET SDK 自带组件，不依赖 NuGet 源可达性。仓库根的 `nuget.config`
已清空全部包源（`<clear />`），`dotnet restore / build` 不会发起任何网络请求，
任何装了 VS（.NET 桌面开发工作负载）的环境均可**完全离线编译**；确需第三方库时
改为 vendor DLL（`libs\` + `HintPath`），不要加回远程包源。

### 1.4 硬件要求

| 项目 | 最低 | 建议 |
| --- | --- | --- |
| CPU | 1.6 GHz 双核 | 2.0 GHz 四核及以上 |
| 内存 | 2 GB | 4 GB 及以上 |
| 磁盘 | 200 MB（框架依赖）| 300 MB（自包含发布） |
| 显示 | 1024×768 | 1440×900 及以上 |
| 硬件加速 | 不要求 | 支持 DirectX 9 的显卡以获得更流畅的滚动 |

无外设依赖（不涉及串口、GPU 计算、专用驱动）。

## 三、构建步骤

### 3.1 使用构建脚本（推荐）

在解决方案目录（含 `Prt.sln` 与 `build.ps1`）下执行：

```powershell
# 全流程：清理 → 还原 → 严格编译+门禁 → 自检 → 自评 → 发布
.\build.ps1

# 常用变体
.\build.ps1 -Configuration Debug -Task build,selftest   # 仅编译并自检
.\build.ps1 -Task lint,score                            # 仅跑门禁与 CRS 9.6 自评
.\build.ps1 -PublishMode self-contained                 # 自包含发布
.\build.ps1 -PublishMode single-file                    # 单文件发布
.\build.ps1 -Task installer -InstallerRuntime portable  # 自研 WPF 安装器（自带便携运行时）
.\build.ps1 -Task installer -InstallerRuntime none      # 安装器（不携带运行时）
.\build.ps1 -Runtime win-arm64                          # 指定目标平台
.\build.ps1 -Task clean                                 # 仅清理中间产物（保留 publish）
.\build.ps1 -NoRestore                                  # 跳过还原以加速
```

脚本参数一览：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `-Configuration` | `Debug` / `Release` | 构建配置，默认 `Release` |
| `-Task` | `all` / `clean` / `restore` / `build` / `lint` / `test` / `selftest` / `score` / `publish` | 要执行的环节，可多选，默认 `all`（`all` 里用 `lint` 取代 `build`——`lint` 内部已含严格编译；`test` 恒跳过，测试能力并入启动自检） |
| `-PublishMode` | `framework-dependent` / `self-contained` / `single-file` | 发布形态，默认前者 |
| `-Runtime` | `win-x64` / `win-arm64` 等 | 目标运行时，默认 `win-x64` |
| `-OutputDir` | 路径 | 发布输出目录，默认 `publish\<形态>` |
| `-NoRestore` | 开关 | 跳过依赖还原 |
| `-NoCleanup` | 开关 | 流程结束后**不**清理编译中间产物（需要保留 `bin` / `obj` 做增量编译或排查问题时用） |

**产物保留策略**：`publish\` 属于成品，**任何环节都不会删除它**；各项目的
`bin` / `obj`、`artifacts`、`TestResults`、`.vs` 等中间目录在流程结束前统一清理
（`-NoCleanup` 可关闭）。因此脚本跑完后磁盘上只剩源码与 `publish\` 里的成品。
自检报告写在 `publish\selftest-report.txt`，随 `publish\` 一起保留。
`lint` / `score` 环节若失败会以非零退出码中止流程；`score` 产出的 CRS 9.6 自评报告写在
`docs\自评报告.md`（源码树内，便于随版本迭代比对）。

> `clean` 环节只删中间产物，**不删 `publish\`**；要重新发布请用 `-Task publish`，
> 或直接删除 `publish\<形态>` 后重跑。

`build.cmd` 为等价入口，供 `cmd.exe` 或双击使用。

> 脚本中的「测试」环节仅在存在 `tests/**/*.csproj` 时执行；当前交付不含独立测试
> 工程，该环节会自动跳过，其余环节不受影响。

### 3.2 使用 dotnet 命令

```powershell
dotnet restore Prt.sln                 # 还原依赖（一般可省略）
dotnet build Prt.sln                   # 编译（Debug）
dotnet build Prt.sln -c Release        # 编译（Release）
```

预期结果：编译无警告、无错误。

产物位置：

| 工程 | 输出 |
| --- | --- |
| `Prt.Core` | `src/Prt.Core/bin/<配置>/net8.0/Prt.Core.dll` |
| `Prt.App` | `src/Prt.App/bin/<配置>/net8.0-windows/Prt.App.dll`（**DLL，无 apphost**，接入模式 A 要求） |
| `Perisc.Safety.SafeGuard` | `src/Perisc.Safety.SafeGuard/bin/<配置>/net8.0-windows/Perisc.Safety.SafeGuard.exe`（带 exe 图标） |

> 源码树里没有 `Prt.App.exe`——按 PSS 7.1，主程序不自带用户可直接启动的可执行入口。
> 想跑程序请运行宿主启动器（见 4.3 与 6.1）。构建脚本的 `publish` 环节还会删掉
> 发布目录里遗留的 `Prt.App.exe`（旧版本的残留），避免出现第二个可双击入口。

## 四、发布与安装

> 本节各命令也可由构建脚本的 `publish` 环节代劳（`.\build.ps1 -PublishMode <形态>`），
> 参数见 3.1 节。

### 4.0 发布目录布局

构建脚本的 `publish` 环节产出下列内容（`publish\<形态>\`，任何环节都不会删除该目录）：

```
publish/framework-dependent/
├─ 阅读器/            ← 唯一入口 Perisc.Safety.SafeGuard.exe（宿主启动器，模块三）
│                        ＋ 主程序 Prt.App.dll（DLL，无 apphost）＋ samples\ 示例文档
├─ 激活码生成器/      ← Prt.Tools.LicenseGen（离线激活码签发端；含密钥副本）
├─ 密钥/              ← license.private.xml、license.public.xml
│                       （以上两项目**仅俱乐部内部流转**，不进安装包）
└─（上一级）selftest-report.txt   ← 启动自检报告

publish/installer/
└─ PRT-Installer.exe  ← 自研 WPF 安装器（自包含**单文件**，自带便携运行时；约 140 MB）
                        卸载器随它内嵌，故目录里只有这一个 exe——校验见 build.ps1 的
                        Assert-InstallerSingleFile
```

`installer\` 是唯一"目录里只能有一个文件"的输出目录，故 build.ps1 每次都先对它清场：
除 `PRT-Installer.exe` 之外的残留条目一律删掉（早先手工 `dotnet publish` 到这里的
`uninstall.exe` 就是这么清掉的——留着它会让下一轮构建在单文件校验上炸掉）。
`publish\` 全局口径是**永不删除**，仅此一处例外。

- **发布目录只放阅读器、激活码签发端与许可证密钥**三类成品；
- **`阅读器\` 目录里只有启动器可以双击**：`Prt.App.dll` 是 DLL，双击无效（Windows 也不会给它图标）；
  **双击 `Perisc.Safety.SafeGuard.exe` 就是启动本程序**，不需要任何参数。
  两个文件**必须同目录**——启动器校验的「运行体哈希」是同目录下的 `Prt.App.dll`，
  不带参数启动时它也只是在**同目录内**推断主程序。把 `Prt.App.dll` 单独拷到别处不会得到
  一个能运行的程序；
- PRTA 代码编译器（`Prt.Prta`）**不进入发布目录**（不是本程序的运行依赖），
  需要时单独发布：`dotnet publish src/Prt.Prta -c Release -r win-x64 -o <目录>`；
- `密钥\` 中的 `license.public.xml` 供核对，`license.private.xml` 供激活码签发端签发；
  发布属于受限分发物，请按分发范围自行控制传递。**绝不可放进安装包**——阅读器验签只认
  内嵌公钥，包里一旦出现私钥，任何人都能自签 `Professional / PERPETUAL` 码且离线验签通过。
  `build.ps1` 收尾的私钥门禁会在出现 `*private*.xml` 时直接终止构建。
- **安装器的素材区只有 `reader\`、`uninstaller\`、`runtime.zip` 三项**（`src\Prt.Installer\content\`）。
  激活码签发端是刻意不放进去的：程序"无码即 Free"，包内再放签发端，它唯一的新增能力就是
  签付费码。详见《设计取舍》第 18 条。

### 4.1 框架依赖发布（体积小，需目标机安装 .NET Desktop Runtime 8.0）

```bash
dotnet publish src/Perisc.Safety.SafeGuard/Perisc.Safety.SafeGuard.csproj -c Release -r win-x64 --self-contained false -o publish/framework-dependent/阅读器
dotnet publish src/Prt.App/Prt.App.csproj -c Release -r win-x64 --self-contained false -o publish/framework-dependent/阅读器
```

> **两条命令的落点必须是同一个目录**，且顺序无关。分到两个目录就等于把启动器与它要校验的
> 运行体拆开了，启动时会以「主程序 DLL 不存在」拒绝启动。

### 4.2 自包含发布（免运行时，体积较大）

同上两条命令，把 `--self-contained false` 换成 `--self-contained true`，输出目录相同。

如需单文件产物：

```bash
dotnet publish src/Prt.App/Prt.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o publish/single-file/阅读器
```

> 单文件发布只对**主程序**有意义（它本来就是被动态加载的那一个）；宿主启动器只有几 MB，
> 保持普通发布即可。

### 4.3 安装方式

本工具有**两种分发形态**，任选其一、互不依赖：

| | 绿色免安装（本节的默认口径） | 安装器 |
| --- | --- | --- |
| 产物 | 一个目录（`publish\framework-dependent\阅读器\`） | 单个 exe（`publish\installer\PRT-Installer.exe`） |
| 是否需要管理员 | 否 | **否**（HKCU + `%LOCALAPPDATA%`，见 [安装说明](安装说明.md)） |
| 写注册表 | 否 | 是（文件关联与卸载登记，均在 HKCU） |
| 自带卸载 | 否（手工删目录） | 是（`<安装目录>\uninstall.exe` 常驻） |
| 自带运行时 | 否 | 可选（`-InstallerRuntime portable` 时随装，并写用户级 `DOTNET_ROOT`） |

**推荐给普通用户与批量部署的是安装器**：一步装好、自带卸载、能绑文件关联。
安装器自身的口径、图形向导、静默参数与卸载回滚全部记在
[docs/安装说明.md](安装说明.md)，本节不再重复。

下面这一段讲的是绿色免安装形态：

1. 将发布目录中的 `阅读器\` 整体复制到目标位置（例如 `D:\Tools\Prt\`）。
2. 确认目录内**同时存在** `Perisc.Safety.SafeGuard.exe`、`Prt.App.dll` 与 `samples\` 子目录。
3. **双击 `Perisc.Safety.SafeGuard.exe`** 即可运行。不带参数启动时启动器会自动启用同目录的
   `Prt.App.dll`，双击时**不会出现控制台窗口**（启动器是 GUI 子系统程序），并显示一个
   「安全系统启动中」的图形启动界面——界面上是真实阶段（校验运行体完整性 → 启动主程序 →
   等待主程序接入），主程序接入后淡出，由阅读器自己的启动画面接上；若启动失败（例如哈希不一致），
   改用系统弹窗给出原因，不会一闪而过。该界面只在双击时出现，从命令行启动时不显示。
   `Perisc.Safety.SafeGuard.exe` 带品牌图标（与阅读器同源），在资源管理器与任务栏中可辨认。

可选：为 `Perisc.Safety.SafeGuard.exe` 建立桌面快捷方式；或将 `.prt` 文件关联到该程序
（`HKEY_CURRENT_USER\Software\Classes` 下的用户级关联，不需要管理员权限）。
**不要**把文件关联指向 `Prt.App.dll`——它无法被直接启动。

> 这一条对两种形态同样成立：文件关联、开始菜单与桌面快捷方式一律指向
> `Perisc.Safety.SafeGuard.exe`，不指向 `Prt.App.dll`。

> 注意：`samples\` 目录用于「打开示例文档」功能。若删除，该功能会退化为打开内置示例内容。

> 注意：安装位置需**可写**。激活码（`license.key`）与本副本激活计数（`activations.json`）
> 写在**启动器所在目录**（主程序与启动器同目录），且只认该目录（详见 5.1 节）。
> 装在只读目录下时程序仍可运行，但激活无法留存，每次启动都会回到未激活状态。

> 注意：启动前会核对 `Prt.App.dll` 的 SHA-256，基准取自同目录下的 `Safe.data`
> （**随发布包分发的出厂声明**，由 `build.ps1` 在发布时生成；启动器打开后独占持有它，
> 运行期间改不动、也删不掉）。因此升级时请**整对替换整套发布文件**——`Safe.data` 必须与
> `Prt.App.dll` 同批。若只换 DLL，会因基准对不上被拒绝启动
> （stderr 打印 `HASH-MISMATCH` 与事件号，退出码 3）；若连 `Safe.data` 都没有，
> 则打印 `BASELINE-MISSING` 并以同样方式拒绝启动。

## 五、配置说明

### 5.1 配置文件

本工具**不使用外部配置文件**（无 `appsettings.json`、无 `.env`），也无需人工编辑任何配置：
界面上的选项改动由程序自身落盘，运行产生的数据文件均放在**程序目录**
（＝启动器与主程序所在的那个目录），**不写用户配置目录**。

| 文件 | 内容 | 程序目录只读时 |
| --- | --- | --- |
| `settings.json` | 界面配色、预览主题、视图模式、语言、缩放、启动界面图等界面选项 | **报错并提示**，见下 |
| `session.json` | 上次打开的文档路径与当前标签序号 | **报错并提示**，见下 |
| `resources\splash.*` | 自定义启动界面图片 | **报错并提示**，见下 |
| `prt-app-exception.log` | 未处理异常的诊断日志（不写临时目录） | 静默降级为内存计数 |
| `license.key` | 离线激活码原文（签名验证通过后才写入） | **报错并提示**，见下 |
| `activations.json` | 本副本的激活次数计数 | **报错并提示**，见下 |

**程序目录必须可写**：本程序为绿色免安装，全部自身数据只认程序目录，不设任何 `%APPDATA%` 回退。
装到只读目录（如 `Program Files`）时，设置保存会**明确弹窗告知**「程序所在文件夹不可写」，
授权激活也会在激活窗口说明写入失败——都不会静默换地方写。把整目录复制到可写位置即可。

**旧位置一次性迁移**：历史版本的配置曾写在 `%APPDATA%\PRT 阅读器`（更早为 `PRT 工具`、
`PSR 工具`、`MDP 工具`）。首次启动时，程序把其中的 `settings.json`、`session.json` 与
`resources\` 搬进程序目录——**先把内容写进程序目录并读回校验一致，才删除旧文件**；任一环节失败
都保留旧文件并把原因写进迁移记录。迁移只做一次；程序目录已有同名文件时按「跳过」处理，
既不覆盖也不删除旧文件。旧目录中的 `license.key` / `activations.json` 自始不被读取，
**不在**迁移范围内、也**不**删除——它们是用户手上可能唯一的授权实物。

**安全模块的数据不在程序目录**（见[行为清单第七节](行为清单.md)）：审计、误报白名单与守护数据
属**用户数据 / 规范落点**。审计按 PSS 6.1.6 落在 `%LOCALAPPDATA%\Perisc\Safety\audit\`；
宿主启动器的白名单、事件、运行期基准快照落在 `%LOCALAPPDATA%\Perisc\SafeGuard\`——6.2.1 要求该目录
**仅当前用户可写、可读，不得放宽为全机可写**，因此**不**随程序目录存放。

只有一处例外，而且它不是运行期数据：程序目录下的 `Safe.data`（运行体完整性基准）是**发布物**，
与 `keys\` 同类，由 `build.ps1` 生成、随包分发。它必须在程序目录——校验基准要与同批发布的运行体
同源。详见[设计取舍](设计取舍.md)第 14 条。

## 六、启动与验证

### 6.1 标准启动

程序**只有宿主启动器这一个入口**（PSS 3.4 / 7.1）。启动器会先核对 `Prt.App.dll` 的运行体哈希，
不一致即拒绝启动。主程序的参数放在 `--` 之后，与启动器自己的参数分开：

```bash
# 常用形态：双击 Perisc.Safety.SafeGuard.exe。它等价于下面这一行——
# --program 可省略，省略时启动器在同目录内推断主程序（双击与命令行都不会出现控制台窗口：
# 启动器是 GUI 子系统程序，命令行启动时它附加父控制台，输出照旧落在你的终端里）。

# 从发布目录显式启动（工作目录设为 阅读器\ 所在位置）
Perisc.Safety.SafeGuard.exe

# 启动并打开指定文档
Perisc.Safety.SafeGuard.exe -- "D:\Docs\文档.prt"

# 指定管道名与并发上限（一般不需要）
Perisc.Safety.SafeGuard.exe --instances 8 --pipe Perisc.Safety.Guard.v1
```

> `--program-id` 通常不必给：**程序标识由启动器注入子进程**（未指定时取主程序文件名 `Prt.App`），
> 守护事件、审计记录与误报白名单都用同一个值。若两侧各自取名，双击（命令行没有参数可传）
> 就会与命令行产生两套身份、把同一次启动拆到两个审计分组里。只有需要把同一台机器上的多次
> 部署分组时，才显式指定 `--program-id`。

从源码直接运行（跳过启动器，仅供开发调试；**这种运行方式属 PSS 3.6 的「未经宿主启动器启动」，
不得用于评估或认证**）：

```bash
dotnet run --project src/Prt.App
```

启动器启动后控制台会打印启动事件号与存储位置、运行体基准的核对结果、已启动的主程序 pid；
主程序退出即视为本次监护结束，启动器随之退出（`Ctrl+C` 也可退出）。

这些输出**只在命令行启动时可见**：双击（不带参数）时控制台窗口被隐藏，同一批信息已随之记入
`%LOCALAPPDATA%\Perisc\SafeGuard\events\`（6.2.1 的存储），需要时从那里查，不必依赖窗口。

### 6.2 健康检查（启动自检）

自检模式不显示窗口，验证「解析 → WPF 原生预览渲染 → 三格式导出 → 安全模块链路」整条链路。
接入模式 A 下主程序是 DLL，用 dotnet 宿主直接加载：

```bash
dotnet exec <发布目录>\阅读器\Prt.App.dll --selftest D:\temp\prt-selftest.txt
echo %ERRORLEVEL%
```

也可经启动器跑（与正常启动同一条路径）：

```bash
Perisc.Safety.SafeGuard.exe -- --selftest D:\temp\prt-selftest.txt
```

> 经启动器跑自检时会先过一遍哈希校验：若只换了 `Prt.App.dll` 而 `Safe.data` 还是旧批（或反过来），
> 会被 `HASH-MISMATCH` 拒绝；`Safe.data` 缺失则被 `BASELINE-MISSING` 拒绝
> （都是设计，不是故障）。处理方式见 9 节「关于运行体完整性基准」。

> **自检不经过启动器**是刻意的：哈希校验与父子进程监护属「运行形态」的验证，
> 与「程序自身正确性」的自检是两件事；把它们混在一起，任何一项失败都分不清是谁的问题。
> 启动形态的验证见 6.2.1。

退出码：`0` 全部通过；`1` 存在失败项；`2` 报告写入失败。

**自检覆盖 53 项**，报告以「结果：通过 53 项，失败 0 项。」收尾，节选：

```
PRT 阅读器 启动自检报告
编写：软体程式部　评议通过：专家委员会
符合性：本渲染器符合 PRT v2.1 EXT 等级。 …
[通过] 解析示例文档（严格模式） —— 错误 0，警告 1，目录 14 项，脚注 1 条，引用目标 9 个
[通过] 渲染预览（主题 default） —— 主题 default，顶层块 46 个，锚点 52 个
[通过] 语义块渲染（12 类） —— 13 个提示框均带底色、侧边线与正文
[通过] 导出 HTML —— 14133 字符
[通过] COMP 降级（不执行求值） —— 插值输出原文，计算块保留源码
…（略：许可证、授权便携性、时钟回拨、审计落盘/损坏行/并发/降级/接管、
   申报异步与超时、界面挂钩隔离、运行时与守护客户端的释放契约、便携落点与旧位置迁移等共 53 项）
结果：通过 53 项，失败 0 项。
```

验收判据：报告中「失败 0 项」，且「解析示例文档」一项的错误数为 0。

### 6.2.1 宿主启动器（模块三）的验收

| 用例 | 期望结果 |
| --- | --- |
| **双击 `Perisc.Safety.SafeGuard.exe`（无参数）** | 正常推断出同目录主程序并加载，出现阅读器窗口；**全程不出现控制台 / 终端窗口**（含 Windows Terminal 的标签页）；`events-YYYYMMDD.jsonl` 里 `STARTED` 与 `CONNECTED` 两行的 `programId` 相同（默认为 `Prt.App`），即两侧身份一致 |

## 八、卸载

装过安装器的机器优先走安装器自带的卸载器（开始菜单「卸载 PRT 阅读器」或安装目录下的
`uninstall.exe`），它的口径见[安装说明](安装说明.md)第六节——会连带回滚自己写进
HKCU 的文件关联与右键菜单。绿色免安装形态手工卸：

1. 关闭程序（宿主启动器会随主程序退出而退出）。
2. 删除发布目录（例如 `D:\Tools\Prt\`）。
3. 若曾建立快捷方式或文件关联，一并删除；用户级文件关联位于
   `HKEY_CURRENT_USER\Software\Classes\.prt`。
4. 如需一并清除安全侧的数据（**可选**）：删除 `%LOCALAPPDATA%\Perisc\Safety\`
   （审计、许可白名单）与 `%LOCALAPPDATA%\Perisc\SafeGuard\`（启动器事件、运行期基准快照）。
   不删也不影响重装。注意：**删掉它们不会影响下次启动**——启动校验的基准来自发布目录里的
   `Safe.data`，与本机这些数据无关（见[设计取舍](设计取舍.md)第 14 条）。

程序不写系统目录、不注册服务、不安装系统服务，删除目录即完成卸载。

## 九、故障排查

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 双击 `Prt.App.dll` 无反应 | DLL 不是可执行体（接入模式 A 下这是刻意的） | 改为双击 `Perisc.Safety.SafeGuard.exe` |
| 「安全系统启动中」的界面显示多久 | **至少 800 ms**。它只负责启动器这一段（校验 → 启动主程序 → 等待接入）：启动器先把界面显示满 800 ms，**再**启动主程序（故这段时间内没有第二个窗口能盖住它），主程序接入后界面淡出。2026-09-26 实测：界面 1.11 s 出现、2.49 s 消失（可见 1.38 s），阅读器自己的启动画面 2.59 s 接上。见[设计取舍](设计取舍.md)第 11 条 |
| 双击后完全没有出现「安全系统启动中」的界面 | 该界面是**观感增强**：它另起一条 STA 线程建窗口，失败时静默跳过（无桌面会话、WPF 初始化失败等），启动流程照常 | 只要能正常打开阅读器即无功能影响。若系统本身缺 `Microsoft.WindowsDesktop.App`，则主程序也起不来，按上面「无法找到 Microsoft.WindowsDesktop.App」处理 |
| 资源管理器里启动器图标空白或仍是旧图标 | Windows 图标缓存未刷新（替换文件后常见） | 重启资源管理器或清理图标缓存；确认双击的是 `Perisc.Safety.SafeGuard.exe` 而非旧的 `Prt.App.exe` |
| 弹窗提示「设置未能保存：程序所在文件夹不可写」 | 程序被放在只读目录（典型如 `Program Files`）；本程序自身的配置只写程序目录、不回退到别处 | 把整个程序目录复制到可写位置再运行。不要期待它写 `%APPDATA%`——那是本次改造刻意去掉的行为（见[设计取舍](设计取舍.md)第 13 条） |
| 升级后发现设置与会话回到默认值 | 程序目录里没有 `settings.json` / `session.json`，且旧位置也没有可迁移的文件（全新副本） | 属预期。若旧版本确实用过并且 `%APPDATA%` 下仍有对应目录，首启会自动迁移一次；迁移失败的原因见下方「迁移记录」 |
| 想知道旧位置迁移了哪些文件 | 迁移只在首次启动执行一次 | 迁移在程序目录**已有同名文件**时按跳过处理（不覆盖、不删除旧文件）；失败时保留旧文件。旧目录中的 `license.key` / `activations.json` 不读取、不删除 |
| 双击 `Perisc.Safety.SafeGuard.exe` 无反应、也没有任何弹窗 | 缺少 .NET 运行时，启动器自身就没跑起来 | 执行 `dotnet --list-runtimes` 检查；补装 .NET Desktop Runtime（x64） |
| 弹窗提示「未指定 --program，且无法自动推断主程序」 | 同目录里没有（或不止一个）带同名 `.runtimeconfig.json` 的 DLL——通常是 `Prt.App.dll` 被挪走了 | 把 `Prt.App.dll` 与 `Prt.App.runtimeconfig.json` 放回与启动器同一目录；目录里确实有多个应用时，用 `--program` 指明 |
| 提示「无法找到 Microsoft.WindowsDesktop.App」 | 运行时缺桌面部分（启动器能跑，主程序起不来） | 同上，补装运行时，或改用自包含发布版本 |
| 启动器报「主程序 DLL 不存在」 | 启动器与主程序不在同一个目录，或 `--program` 路径不对 | 把 `Perisc.Safety.SafeGuard.exe` 与 `Prt.App.dll` 放回同一目录，或给出正确路径 |
| 启动器报「拒绝启动：运行体哈希不一致（HASH-MISMATCH）」，退出码 3 | 只换了 `Prt.App.dll`、没换同一批的 `Safe.data`；或运行体被第三方改动 | 用**同一批发布**的整套文件替换（`Prt.App.dll` 与 `Safe.data` 必须同批，见下方「关于运行体完整性基准」）；确认运行体未被第三方修改。事件号与证据可在 `%LOCALAPPDATA%\Perisc\SafeGuard\events\` 中查到 |
| 启动器报「拒绝启动：缺少运行体完整性基准（BASELINE-MISSING）：Safe.data」，退出码 3 | 启动器同目录里没有 `Safe.data`（拷贝发布包时漏了、被杀毒软件隔离，或被手工删掉） | 从**同一批发布包**取回 `Safe.data` 放回启动器同目录。程序**不会**自行「重新登记」——基准不再写在本机，缺了就是缺了 |
| 启动器报「存储初始化失败」 | `%LOCALAPPDATA%\Perisc\SafeGuard\` 不可写（少见的权限/漫游配置问题） | 确认当前用户对 `%LOCALAPPDATA%` 有写权限；不要改为全机可写（PSS 6.2.1 要求仅当前用户可写） |
| 界面频繁弹出授权窗 | 默认拒绝策略下每次敏感行为都要用户答复 | 在弹窗中选择「本次会话内允许」；反复对**同一个对象**做同一件事本会命中许可缓存不再询问 |
| 提示「操作过于频繁」（`Limit`） | 申报频率撞上 2.1 的默认 10 次/秒，或审计待写队列有积压 | 稍候重试即可（这是背压信号，不是拒绝）。审计队列积压通常意味着磁盘繁忙或写满，见下 |
| 审计写不进去 / 待写队列持续积压 | 磁盘满、`%LOCALAPPDATA%` 不可写，或审计目录被外部改动 | 清理磁盘空间；在安全中心查看审计状态；按 3.6.2 判为永久不可用时模块会升级处置 |
| 界面显示方框 / 乱码 | 系统缺少中文字体 | 安装「Microsoft YaHei UI」或「微软雅黑」字体 |
| 文件关联打开无效 | 未建立关联，或关联指向了 `Prt.App.dll` | 把关联指向 `Perisc.Safety.SafeGuard.exe`，参数用 `-- "%1"`（`--program` 可省略，启动器会自行推断） |

| 诊断面板大量红色错误 | 当前处于强制严格模式，或文档语法确实不合规 | 取消「强制严格模式」观察是否为宽松降级；或按错误码修正文档 |

| 编译报 `NETSDK1045`（SDK 版本过低） | 未安装 .NET 8 SDK | 安装 .NET SDK 8.0.x |
| `build.ps1` 报「可维护性维度 C+，要求 ≥ B-」 | 新增代码引入了扣分项（门禁失败即构建失败，这是刻意设计） | 看 `docs\自评报告.md` 的逐项证据定位；**不要**下调脚本里的棘轮基线 |

### 关于运行体完整性基准

**基准是发布物，不是本机状态**：`阅读器\Safe.data`（纯文本，每行
`<运行体文件名> = sha256:<64 位十六进制>`，`#` 开头为注释）由 `build.ps1` 在发布时按刚发布的
`Prt.App.dll` 生成，与发布包一起分发。启动器启动前读它核对运行体；读出后**独占持有该文件到
进程退出**（共享模式 `FileShare.Read`：别的进程可以再读，但**写入、改名、删除一律失败**），
所以运行期间谁也不能替换这份基准——想换就得先让启动器退出，而它一退出就不再是裁决者。

为什么不像早先那样"首次启动在本机登记基准"：那份登记与包**不同源**。它记的是"上次在这台机器上
跑过的运行体"，于是重新编译之后启动器会拿旧基准去核新运行体、一律拒启——每次都要手工清掉本机
残留才能跑，而那份残留既不来自源码也不来自发布包。基准随包走之后，安装与升级都不需要任何
环境干预，本机也没有任何文件能左右校验结果（本机 `baseline.json` 就算被写成别的值也一样）。

**升级＝整对替换**：把 `阅读器\` 里的整套文件一起换（至少 `Prt.App.dll` 与 `Safe.data` 必须同批）。
只换 DLL 会被判 `HASH-MISMATCH`；漏掉 `Safe.data` 会被判 `BASELINE-MISSING`——两者都是退出码 3，
主程序不会启动。若确需临时放行，可用 `--hash <新哈希>` 显式声明一次（显式声明优先于基准文件），
新哈希用 `certutil -hashfile Prt.App.dll SHA256` 取得。

**启动器的事件与白名单仍按程序标识分组**（落在 `%LOCALAPPDATA%\Perisc\SafeGuard\`）：

| 内容 | 位置 | 分组方式 |
| --- | --- | --- |
| 运行体基准 | `阅读器\Safe.data`（程序目录，随包分发） | 按运行体文件名逐行声明；启动校验的来源（`--hash` 除外） |
| 运行期基准快照 | `%LOCALAPPDATA%\Perisc\SafeGuard\baseline.json` | 一个标识一项；**不参与**启动放行，只记录运行期被凭据确认过的基准变更（3.4 六） |
| 守护事件 | `%LOCALAPPDATA%\Perisc\SafeGuard\events\events-YYYYMMDD.jsonl` | 每行带 `programId` 字段 |
| 误报白名单 | `%LOCALAPPDATA%\Perisc\Safety\whitelist-<标识>.json` | 一个标识一个文件 |

标识由**启动器**给出并注入子进程（未指定 `--program-id` 时取主程序文件名 `Prt.App`），
所以同一次启动里，启动器侧与主程序侧用的是同一个值。**这一点必须保持一致**：双击启动时
命令行没有参数可传，两侧若各自取名，同一次启动就会被拆成两个审计分组、白名单也会互相看不见。

> 若历史上用过别的标识（例如更早的命令行写法 `--program-id prt.reader`），事件日志与
> `baseline.json` 里会并存两种身份的记录。这不影响启动——启动校验只认 `Safe.data`；
> 要归并到一种身份，删掉不再使用的那一项即可。
