# PRT 阅读器 安装说明

> 编写：软体程式部　　评议通过：专家委员会

本说明面向**普通使用者与批量部署者**，讲清「怎么拿到安装包、装上去会发生什么、怎么卸干净」。
阅读器本身的使用方式见[使用指南](使用指南.md)；源码与发布目录的构建口径见[部署文档](部署文档.md)。

---

## 一、安装包从哪来

| 形态 | 产物 | 适用 |
| --- | --- | --- |
| **安装器**（本文主题） | `publish\installer\PRT-Installer.exe`，**单个 exe** | 普通用户、批量部署 |
| 绿色免安装 | `publish\framework-dependent\阅读器\` 整个目录 | 需要零写入、多版本共存、可移动的场景 |

安装器是**自研 WPF 程序**，不是 NSIS / Inno Setup 之类通用打包器：阅读器、便携运行时、卸载器
全部**内嵌在 exe 里**，发布目录里除它之外不允许出现第二个文件。好处是分发与校验都只有一件事
要做——拿到那一个 exe 就能装，不存在"素材目录没跟着拷贝"导致的缺文件。

生成方式（在含 `build.ps1` 的解决方案目录下）：

```powershell
.\build.ps1 -Task installer                     # 自带便携运行时（默认）
.\build.ps1 -Task installer -InstallerRuntime none   # 不带运行时，需目标机已有 .NET 8 桌面运行时
```

> `-Task` 是**单个字符串**，要加引号：`-Task 'build,selftest'`。写成 `-Task build,selftest`
> 会被 PowerShell 解析成数组而报类型转换错误（已知遗留事项，见[部署文档](部署文档.md)第十节）。

## 二、安装条件

| 项 | 要求 |
| --- | --- |
| 系统 | Windows 10 版本 1607（内部版本 14393）或更高；Windows 11；Windows Server 2016 或更高 |
| 权限 | **不需要管理员**。一切写盘与注册表都在当前用户之下（HKCU / `%LOCALAPPDATA%`），不动系统目录 |
| 运行时 | 默认**自动判断**：系统已有 .NET 8 桌面运行时就复用；没有才随装便携运行时并写用户级 `DOTNET_ROOT` |
| 安装位置 | 需**可写**。程序自身的 `settings.json` / `license.key` 只写在程序目录，不回退到别处 |

`DOTNET_ROOT` 是实测下来的必要步骤：.NET 的 apphost 只认这一处自定义运行时定位方式——
装在旁边的 `dotnet\` 目录与用户级注册表 `InstallLocation` 都不生效。
副作用是它需要**刷新资源管理器**（注销重登，或重启 Explorer）之后，双击文件才会用到它；
从开始菜单 / 桌面快捷方式启动不受影响。

## 三、图形向导

双击 `PRT-Installer.exe` 即进向导，四步：

| 步骤 | 内容 |
| --- | --- |
| ① 欢迎 | 说明这次装什么 |
| ② 选项 | 选择安装位置；勾选组件与关联；选择运行时策略 |
| ③ 进度 | 逐条显示"释放阅读器文件 → 释放卸载器 → 释放 .NET 运行时 → 配置文件关联 → 创建快捷方式 → 安装完成"，失败会停在对应步骤 |
| ④ 完成 | 汇总装到哪、装了什么；若随装了便携运行时，提示刷新外壳 |

默认勾选：**桌面快捷方式**、**示例文档 + 帮助文档**、**右键菜单 /「打开方式」**、
**`.prt` / `.psr` / `.mdp` 三类文件关联**。

安装包里**不含激活码生成器**，这是有意的：阅读器在「无激活码」时本就按 Free 级运行，
包内若再放一个签发端，它唯一新增的能力就是签发付费码——等于把付费墙随包一并发货；
让它只签免费码又毫无意义（用户本来就是 Free）。需要 Standard / Professional 的用户，
由俱乐部用主私钥离线签发激活码后发给对方粘贴即可。

## 四、静默安装（批量部署用）

```powershell
PRT-Installer.exe /install /dir="D:\Tools\PRT" /log="D:\logs\prt-install.log"
```

全程**不弹窗口、不创建任何界面**（Application 没有 Window 也照常跑；弹一个"正在安装"的假窗
再自动关掉，只会让远程机器上多一次莫名其妙的闪窗）。结束以退出码表示结果，并把逐条动作写进
`/log=` 指定的日志，末行是 `RESULT: OK <安装目录>` 或 `RESULT: FAIL <原因>`——
"装完到底成不成"因此是可机器判定的，不必靠人回忆。

| 开关 | 取值 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `/dir=` | 路径 | 无（必填，否则装到哪说不清） | 安装位置 |
| `/log=` | 路径 | `%TEMP%\prt-installer.log` | 安装日志；父目录不存在时自动创建 |
| `/associate=` | `true` / `false` / `1` | `true` | 是否关联三类文件 |
| `/shellmenus=` | 同上 | `true` | 是否加右键菜单与「打开方式」 |
| `/desktop=` | 同上 | `true` | 是否建桌面快捷方式 |
| `/samples=` | 同上 | `true` | 是否带示例文档与帮助文档 |
| `/runtime=` | `automatic` / `portable` / `system` | `automatic` | 运行时策略 |

不认识的参数**不会**被静默忽略，会写进日志的「未识别的参数」一行——静默忽略会让
"我明明加了参数怎么没生效"变成最难查的一类故障。`PRT-Installer.exe /uninstall` 可直达卸载页
（重装前想先卸干净的入口）。

## 五、装上去之后是什么样

```
<D:\Tools\PRT>\
├─ Perisc.Safety.SafeGuard.exe   ← 唯一入口（宿主启动器，PSS 模块三）
├─ Perisc.Safety.SafeGuard.dll / .deps.json / .runtimeconfig.json
├─ Prt.App.dll / .deps.json / .runtimeconfig.json   ← 主程序（DLL，双击无效，由启动器加载）
├─ Prt.Core.dll / Perisc.Safety.dll / Safe.data
├─ samples\sample.prt            ← 「打开示例文档」
├─ 帮助\PRT-作者指南.md            ← 作者指南 / 教程
├─ 安全\行为清单.md                ← 安全侧行为清单
├─ uninstall.exe                 ← 卸载器（常驻）
└─ dotnet\                       ← 仅当随装了便携运行时
```

随装的文档只有作者指南与教程两册（它们在 `帮助\` 下）；本仓库的
[使用指南](使用指南.md) / [部署文档](部署文档.md) / 本说明属于**开发者与运维文档**，
不随程序分发。

- **双击 `Perisc.Safety.SafeGuard.exe`** 就是启动本程序（无参数），**不会出现控制台窗口**。
  启动器先校验 `Prt.App.dll` 的运行体哈希（基准取同目录的 `Safe.data`），通过后才加载主程序。
  因此升级必须**整对替换**——`Safe.data` 与 `Prt.App.dll` 必须同批，只换一个会被拒启。
- **文件关联**：`.prt` / `.psr` / `.mdp` 三类。关联指向的是启动器（可双击的那一个），
  **不要**指向 `Prt.App.dll`——它无法被直接启动。注册表写在 `HKEY_CURRENT_USER\Software\Classes`
  下，卸载时会精确回滚。
- **开始菜单**里有两项：「PRT 阅读器」与「卸载 PRT 阅读器」。
- **登记信息**写在 `HKCU\Software\PRT Reader`（`InstallDir` / `Version` / `InstalledAt` 及各组件开关），
  卸载器只读这一处。
- **「设置 → 应用」里能查到本程序**（`HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall`），
  条目带卸载命令、版本、发布者与体积，点「卸载」即走卸载器。按用户安装，故标记为
  `InstallationType=User`，不需要管理员；条目在卸载时连同注册表一起清掉。

## 六、卸载

三条入口，任选其一：开始菜单「卸载 PRT 阅读器」、安装目录下的 `uninstall.exe`、
`PRT-Installer.exe /uninstall`。

卸载器会做：删除安装目录（对正在被占用的文件重试后跳过并记账）、**回滚自己写入的文件关联与
右键菜单**（注册表只写 HKCU，删完不留残键）、删除开始菜单项与桌面快捷方式、清除
「设置 → 应用」里的条目（顺序是先清条目再删目录，否则会剩一个点不动的残项）。
超过 32 KB 的 `uninstall.exe` 在删除自身前会先尝试自删——这是 Windows 上唯一能删掉自己的办法。

可选清理（不删也不影响重装）：`%LOCALAPPDATA%\Perisc\Safety\`（审计、许可白名单）与
`%LOCALAPPDATA%\Perisc\SafeGuard\`（启动器事件、运行期基准快照）。

## 七、重装与升级

- **升级**：把新版 `PRT-Installer.exe` 再跑一遍，装到同一目录即可（覆盖同名文件）。
  覆盖前会先整棵删掉上次的 `dotnet\`——留着旧版本的多余运行时，apphost 会在多个版本间挑错。
- **换目录重装**：直接装到新位置即可；旧目录若还想用，按上一节的卸载方式清掉。
- **覆盖安装时若旧登记的组件开关与新勾选不一致**（例如上次没勾桌面快捷方式、这次勾了），
  以本次勾选为准。

## 八、故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 双击安装包立刻消失，事件查看器里只有"代码执行异常" | 安装器自身的启动阶段失败。诊断日志写在 `%TEMP%\prt-installer-crash.log`（跨次追加，每次都带时间戳与完整栈） |
| 静默安装日志末行 `RESULT: FAIL 内嵌素材缺失：…` | 打包流程的问题：素材没按相对路径嵌进 exe。重跑 `.\build.ps1 -Task installer`；若在 Debug 下直接 `dotnet build` 安装器工程，则没有 `content\` 素材区，必然报这一条——**验证安装包必须走 build.ps1** |
| `日志目录不存在`导致失败没留下证据 | 已在 `/log=` 指向的父目录不存在时自动创建，不必先建目录 |
| 装完双击 `.prt` 打开的是别的程序 | 关联没生效或被别的程序抢先。到「设置 → 应用 → 默认应用」里把 `.prt` / `.psr` / `.mdp` 改回 PRT 阅读器；或重装时勾选文件关联 |
| 提示「装了便携运行时，需要刷新一次外壳」 | 双击文件用的是系统 apphost，`DOTNET_ROOT` 要刷新资源管理器（注销重登或重启 Explorer）才生效。从开始菜单 / 桌面快捷方式启动不受影响 |
| 卸载后资源管理器里还留着打开方式 | 外壳缓存未刷新；注销重登即可。注册表项本身已由卸载器删掉 |
| 装完「打开示例文档」是内置内容 | `samples\sample.prt` 缺失或被移动；放回启动器同级的 `samples\` |
| 双击 `Prt.App.dll` 无反应 | 这是刻意的（接入模式 A，主程序编译为 DLL）。要双击的是 `Perisc.Safety.SafeGuard.exe` |
| 启动器报 `HASH-MISMATCH` / `BASELINE-MISSING`（退出码 3） | 升级没整对替换，或 `Safe.data` 缺失。按同一批发布整套文件替换，见[部署文档](部署文档.md)第九节 |

## 九、与绿色免安装的关系

两套形态共用同一份素材，任选其一即可，不互相依赖：

| | 安装器 | 绿色免安装 |
| --- | --- | --- |
| 产物 | 单个 exe | 一个目录 |
| 写注册表 | 是（HKCU 文件关联与卸载登记） | 否 |
| 带卸载器 | 是 | 否（手工删目录） |
| 运行时 | 自动判断，可随装 | 需自行准备或整目录自包含 |
| 适用 | 普通用户、批量部署 | 便携 U 盘、多版本共存、只读位置 |

两者的运行时定位都依赖 `DOTNET_ROOT`（随装便携运行时时）——这条是 apphost 的实现约束，
不是本程序的取舍，详见[设计取舍](设计取舍.md)。
