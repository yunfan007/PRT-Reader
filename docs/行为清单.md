## 一、接入模式

**接入模式 A（原生全接入）**，四层齐备、无降级：

| 层 | 本程序的形态 | 落点 |
| --- | --- | --- |
| **ARM 模块一**（申报与裁决） | 进程内 `Perisc.Safety.SafetyClient` | `Services/SafetyBridge.Initialize()` |
| **IM 模块二**（拦截层） | 进程内 `Perisc.Safety.InterceptClient`，拦截范围默认覆盖 4.6 全部 63 项 | 同上（`InterceptClient.Register`） |
| **SafeGuard 模块三**（宿主启动器） | 独立进程 `Perisc.Safety.SafeGuard.exe`，**本程序的唯一启动入口** | 发布目录 `阅读器\` |
| **SRT 模块四**（安全运行时） | 进程内 `Perisc.Safety.SafeRuntime` 类型族，**本程序的敏感行为收口层** | `Perisc.Safety/SafeRuntime*.cs` |

**启动方式（唯一）**：双击 `Perisc.Safety.SafeGuard.exe`。

主程序是 DLL，自身没有可执行的入口；启动器是**唯一启动入口**，也是唯一可双击的对象。
不带参数运行时，启动器在自身目录内推断主程序（判据：除启动器自身以外，唯一同时存在同名
`.runtimeconfig.json` 的 DLL——那是「可由 dotnet 宿主直接启动的应用」的标志，类库不产出它），
用户不必记命令行。候选不唯一时不猜，直接报错要求显式 `--program`。

需要显式控制时用命令行形式（`--program` 可省略，省略即走同目录推断）：

```
Perisc.Safety.SafeGuard.exe [--program Prt.App.dll] [--program-id <标识>] -- <主程序参数…>
```

**程序标识由启动器给出**：启动器把它采用的标识注入子进程（环境变量
`PERISC_SAFEGUARD_PROGRAM_ID`），主程序只读取、不自行取名。双击时命令行没有 `--program-id`
可传，若两侧各自取名，同一次启动就会在守护事件与审计里留下两种标识、白名单分组随之分叉。
未显式指定时取主程序文件名 `Prt.App`。

**双击时不产生控制台窗口**：启动器是 **GUI 子系统**程序（`WinExe`），系统不会为它建控制台，
因此双击时屏幕上既没有黑框、也没有终端标签页——这是**不产生**，不是"产生了再藏起来"。
早先用"控制台子系统 + 隐藏自建窗口"的做法在 **Windows Terminal 作默认终端**时天生无效
（窗口归 `WindowsTerminal.exe` 所有，进程内 `GetConsoleWindow()` 只是自己的一个 0×0 消息窗），
2026-09-26 已改为子系统级根除。**黑框有两个来源，两个都压住**：启动器自己的（GUI 子系统，
系统不建）与 dotnet 宿主子进程的——宿主 `dotnet.exe` 是控制台子系统程序，双击路径上它的父进程
（启动器）没有控制台，系统会替它新建一个可见控制台；故图形路径下 `GuardLauncher.Launch`
对宿主设 `CreateNoWindow`，宿主与它的后代都不出现窗口。命令行用法照旧：启动时附加回
**父进程**的控制台并重接标准流（此时不给宿主设 `CreateNoWindow`，让它继承同一控制台），
输出与交互不变；调用方重定向（`2> 日志.txt`、管道）时那个落点会被保留，不会被控制台顶掉。
这一条只影响"窗口与输出往哪去"，**不改变任何安全行为**。
图形路径下启动失败（如 `HASH-MISMATCH`）改由系统弹窗告知，不会无声退出。

**双击时的图形启动界面**：同一条件下（无参数、且**没有可附的控制台**——即双击）启动器另外显示一个
「安全系统启动中」的原生 WPF 窗口（`GuardSplash` / `GuardSplashWindow`）。界面上显示的是
**真实阶段**——校验运行体完整性 → 启动主程序 → 等待主程序接入——**至少显示 800 ms**
（满 800 ms 之后才启动主程序，故这段时间内屏幕上没有第二个窗口能盖住它），主程序接入后淡出，
由主程序自己的启动画面接上。该界面的性质与边界如下：

| 项 | 说明 |
| --- | --- |
| 是否参与裁决 | **不参与**。它不显示假进度、不拦截操作、不改变任何判定；在或不在，哈希校验、作业对象、管道监听与终止规则（3.4 / 6.2）完全一致 |
| 出现条件 | **仅双击**（无参数 + 没有可附的控制台）。从 cmd / PowerShell 启动、经启动器跑自检时**一律不显示**，命令行输出与脚本调用不受影响 |
| 置顶 | **不置顶**。「至少显示 800 ms」由「显示期间不启动主程序」保证，不靠置顶。实测（2026-09-26，双击等价、对发布产物）：界面 0.61 s 首次可见、2.20 s 最后可见，阅读器启动画面 2.32 s 才出现——「被别的窗口盖住」比「首次可见」晚 **1.71 s ≥ 0.80 s**。置顶会反过来压住阅读器启动画面与需要用户操作的授权弹窗（见[设计取舍](设计取舍.md)第 11 条） |
| 最短显示 | **800 ms**。界面显示满 800 ms 之后**才**启动主程序（`GuardSplash.EnsureMinimumVisibleAsync`）：显示期间主程序尚未创建，故这段时长是**用户确实看得见**的时长。取值与阅读器启动画面的最短显示时长一致 |
| 最长显示 | 20 s 兜底后自行淡出。它是启动界面而**不是拦截层**：拦截层从不自行消失，启动界面绝不长期压在用户可用界面之上 |
| 失败处置 | 创建失败（无桌面会话、WPF 初始化失败）时静默跳过，启动流程照常（失败原因写一行到 stderr 备查；双击时没有控制台，那一行落不到任何地方）——观感增强不得升级成启动失败 |

启动器在加载 `Prt.App.dll` **之前**核对运行体哈希：基准取自程序目录下的 `Safe.data`
（**随发布包分发的出厂声明**，由 `build.ps1` 在发布时生成；`--hash` 可当场显式声明，优先级最高）。
启动器一打开它就以 `FileShare.Read` **独占持有句柄到进程退出**——别的进程只能再读，
**写入与删除一律失败**，故运行期间谁也不能替换这份基准。三档处置：

| 情形 | 处置 |
| --- | --- |
| 基准与运行体一致 | 正常启动主程序 |
| 基准与运行体**不一致** | 记 `HASH-MISMATCH`，拒绝启动，退出码 3 |
| **拿不到基准**（文件缺失 / 读不出 / 里面没有该运行体） | 记 `BASELINE-MISSING`，拒绝启动，退出码 3 |

"拿不到基准"与"不一致"分开记录：前者排查发布包是否完整，后者排查运行体是否被改动或升级时
只换了 DLL。两档都**不启动主程序**（PSS 3.4 二），双击时以系统弹窗告知，不会无声退出。
**没有"首次登记后放行"这一档**：基准随包走之后它既无必要也无好处，而它等于"删掉本机文件即可绕过校验"。
启动器与主程序以**同一用户权限**运行，终止权来自父子进程关系，不安装系统服务、不需要管理员权限（3.4 一）。

**子进程侧主动上报**（3.4 三）：连接、心跳（`StartHeartbeatAsync`，默认 5 秒）与拦截事件
全部由本程序发起；守护侧不轮询、不扫描。

**模式**：`IntegrationMode.Native`，在行为清单与符合性声明中一致声明（3.7）。

## 二、申报点与拦截点合一（本程序的收口方式）

PSS 3.2 末条与 3.3 允许两种落地：申报点与拦截点分开，或**合一**。本程序取合一：

- **收口层**＝模块四 SRT（`SafeRuntime` 类型族）。程序里凡属 4.6 九类的动作，
  一律经 SRT 的函数执行——**调用 SRT 的函数即完成「申报 → 裁决 → 执行 → 审计」四步**（3.8 ②）。
- 因此本程序**不再有**「先申报、再裸调语言标准库（BCL）」的手写正门。
  这样的正门每少一处，「漏报」（3.3）与「绕道」（4.4）就同时少一处。
- 模块二仍是第二道：它管的是**逃过收口层**的调用点（理论上不该有），命中即阻断并补记
  `Undeclared` 审计。
- **3.9 授权关系**：SRT 与模块二**共用同一份模块一客户端**（`SafeRuntime.SetClient(_client)`），
  即同一个许可池。SRT 不自带许可存储、不自行签发许可、不给出与模块一不同的结论；
  对同一次行为两者的表态来自同一次模块一裁决。

## 三、实际触发点（申报口径）

| 用户可见动作 | 收口函数（SRT） | 行为编号 |
| --- | --- | --- |
| 打开文档（菜单 / 拖放 / 命令行 / 示例） | `SafeRuntime.File.ReadText` / `ReadLines` / `Exists` | `PRIV-01` |
| 重新载入文档 | `SafeRuntime.File.ReadText` | `PRIV-01` |
| 从 HTML 导入（读取源文件） | `SafeRuntime.File.ReadText` | `PRIV-01` |
| 保存 / 另存为（用户目录内） | `SafeRuntime.File.WriteText` ＋ `CreateDirectory` | `FS-02`（＋`FS-01`） |
| 保存 / 另存为（程序目录以外的地方） | 同上 | `FS-03`（＋`FS-01`） |
| 落点是可执行文件或脚本（`.exe` `.dll` `.ps1` `.js` … ） | `SafeRuntime.File.WriteText` | `FS-06` |
| 导出为 HTML / Markdown / 纯文本 | `SafeRuntime.File.WriteText` | `FS-02` / `FS-03` |
| 复制所选内容到剪贴板 | `SafeRuntime.Device.SetClipboardText` | `DEV-05` |
| 粘贴剪贴板文本（正文区、激活窗口） | `SafeRuntime.Device.GetClipboardText` | `DEV-04` |
| 打印当前文档 | `SafetyBridge.EnsureAllowedAsync`（SRT 未提供打印等效函数，见第五节） | `DEV-07` |
| 界面设置 / 会话 / 自定义启动图 / 授权文件的读写 | `SettingsStore` / `SessionService` / `Activation` / `DeviceActivation` → `PortableStorage` | **不申报**（不属 63 项，见第五节） |
| 异常诊断日志落盘（`prt-app-exception.log`） | `PortableStorage.TryAppendText` | **不申报**（同上） |
| 自检报告落盘 | `SafeRuntime.File.AppendText` / `WriteText` | `FS-01` / `FS-02` |
| 示例文档定位（唯一候选＝程序目录下 `samples\sample.prt`） | `SafeRuntime.File.Exists` | `PRIV-01` |

编号的选择规则（4.2）：判定看这次调用**落在哪个行为编号上**，不看用了哪个类。
写入按落点选号（可执行扩展名 → `FS-06`；用户目录内 → `FS-02`；程序自身目录内 → `FS-01`；其余 → `FS-03`），
见 `SafeFile.ClassifyWrite`。读取类动作落在 `PRIV-01`（4.6 的 FS 九项只管改动类动作），
且「读」与「写」在同一处收口（`SafeFile`），较原先分散在各业务类里更不易漏。

**唯一的例外**是本程序自己写在程序目录里的运行期数据（上表前三行）——它们既不落在读侧的
`PRIV-01` / `PRIV-06`，也不落在写侧的 `FS-02` / `FS-03`（`FS-03` 明文限定「程序自身目录
**以外**的地方」），故按 3.6「编号不得自造」不在申报范围内。理由与实测教训见第五节。

每次已执行的行为都在同一调用栈内写入一条 `Allow` 审计（PSS 5.5）。

## 四、SRT 覆盖情况（5.4 ② 类别级对照表）

按 5.4 ② 的表逐类核对。**该表是下限**：表内列出的方向每一个都必须真实存在且可调用。

| 类别（4.6） | 5.4 ② 要求的方向 | 本实现的等效函数 | 判定 |
| --- | --- | --- | --- |
| `FS` 文件系统 | 创建 / 写入 / 删除 / 改名与移动 / 目录枚举 / 符号链接创建 | `SafeFile`：`CreateDirectory`、`WriteText`、`AppendText`、`WriteBytes`、`Delete`、`DeleteDirectory`、`Move`、`Copy`、`EnumerateFiles`、`CreateSymbolicLink` | **已覆盖** |
| `NET` 网络 | 出站连接 / 监听 / 上传 / 下载 / 代理与隧道 | **未提供** | **未覆盖**（见第五节） |
| `PROC` 进程与系统 | 起子进程 / 结束进程 / 加载原生库 / 计划任务与自启 | `SafeProcess`：`Start`、`Kill`、`KillByName`、`LoadNativeLibrary`、`CreateScheduledTask`、`SetStartupRun` | **已覆盖** |
| `CFG` 配置与注册表 | 写系统配置 / 注册表 / 文件关联 / 环境变量 | `SafeConfig`：`SetRegistryValue`、`SetFileAssociation`、`SetEnvironmentVariable` | **已覆盖** |
| `DEV` 外设与媒体 | 摄像头 / 麦克风 / 截屏 / 剪贴板 / 位置 | `SafeDevice`：`GetClipboardText`、`SetClipboardText`、`ClipboardContainsText`；摄像头 / 麦克风 / 截屏 / 位置**未提供** | **部分覆盖**（见第五节） |
| `CRED` 凭据与密钥 | 读凭据存储 / 读写私钥 / 加解密用户数据 | `SafeCredential`：`ReadPrivateKey`、`ReadPrivateKeyBytes`、`GenerateKeyPair`、`EncryptUserData`、`DecryptUserData` | **已覆盖** |
| `CODE` 代码执行与反射 | 动态编译 / 反射非公开成员 / 反序列化 / 加载程序集 | `SafeCode`：`LoadAssembly`、`InvokeNonPublic`、`DeserializeJson` | **已覆盖** |
| `PRIV` 用户数据与隐私 | 读文档与媒体库 / 通讯录与日历 / 浏览器数据 / 上报 | `SafePrivacy`：`EnumerateUserLibrary`、`ReadUserDocument`、`ReportTelemetry`；通讯录 / 日历 / 浏览器数据**未提供** | **部分覆盖**（见第五节） |
| `RES` 资源占用 | 后台常驻 / 密集计算 | `SafeResource`：`BeginBackgroundResidency`、`BeginIntensiveCompute` | **已覆盖** |

覆盖判定的三条（5.4 ② 末）：① 表列方向都有对应函数；② 函数**公开可调用**（`public`，
不是模块内部私有）；③ 调用它们即完成四步，不把执行留给调用方去接 BCL。
上表「已覆盖」的七类三条全满足；`DEV`、`PRIV` 两类缺表列方向，按 5.4 ② 末条判为**该类别未覆盖**
——未覆盖的类别用 BCL **不触发** 10.4.4 的封顶，但仍受 4.4 的申报义务约束。

## 五、SRT 未覆盖而仍直接用语言标准库（BCL）的类别与理由（5.4 ③ 举证）

这一段是 **12.4 第 1 条要求写的「SRT 未覆盖的类别与理由」**。写了才不触发 10.4.4 的封顶。

最后一行与其余各行的情形略有不同：不是「SRT 没提供等效函数」，而是「**这一类动作不在 63 项内**，
按 3.6 与 3.8 本就不该申报」。放在同一张表，是因为 5.4 ③ 问的都是「为什么有用 BCL 的地方」，
处置口径相同——如实登记并给出理由。

| 类别 | SRT 未提供什么 | 本程序怎么处理 | 是否仍经收口层申报 |
| --- | --- | --- | --- |
| `NET` | 出站连接 / 监听 / 上传 / 下载 / 代理与隧道（整类） | **本程序不带任何网络功能**：无更新检查、无遥测、无远程资源加载（远程图片只显示占位符，不联网）；源码内无 `HttpClient` / `Socket` / `TcpClient` 调用点 | 无动作，无须申报 |
| `DEV` | 摄像头 / 麦克风 / 截屏 / 位置 | 本程序不涉及这些能力 | 无动作，无须申报 |
| `DEV` | 打印（`DEV-07`） | 打印**不在** 5.4 ② 的 DEV 行内（该行只列摄像头 / 麦克风 / 截屏 / 剪贴板 / 位置），故 SRT 未提供等效函数；此处经 `SafetyBridge.EnsureAllowedAsync("DEV-07", …)` **先申报再调 BCL**，是 SRT 之外唯一的收口点 | **是**（经模块一显式申报） |
| `PRIV` | 通讯录 / 日历 / 浏览器数据 | 本程序不涉及 | 无动作，无须申报 |
| （非 4.6 项） | 不适用——63 项里没有这一类 | 本程序**自己**的运行期数据：界面设置、会话、自定义启动图、授权文件、异常诊断日志（统一经 `PortableStorage`）。读不在 `PRIV-01`（文档 / 图片 / 音乐**库**），也不在 `PRIV-06`（**其它程序**的数据目录）；写不在 `FS-02`（用户目录），也不在 `FS-03`（程序自身目录**以外**）——它只碰程序自己在程序目录里写出的数据 | **否**（不属 63 项，无须申报） |

**其他未收口的调用点（有意保留，逐条给理由）**：

| 位置 | 为什么不经 SRT |
| --- | --- |
| 目录遍历（`Directory.EnumerateFiles` 的少量只读枚举） | `SafeFile.EnumerateFiles` 已提供等效函数；残留在渲染路径上的枚举按 5.4 ③「全量比对按源码调用点数」逐处登记，属 10.4.4 封顶的**触发判据内**，已在自评（12.4 第 9 条）中给分母 |
| 图片解码（`PreviewBuilder` 的 WPF 成像栈） | 5.4 ② 表内无对应方向（`BitmapImage` 的解码不落在 FS / PRIV / DEV 任何既有编号上），不属该门槛范围；解码所需的字节读取本身经 `SafeRuntime.File.ReadBytes` |
| 渲染期只读探测 | 已全部剔除（改用 SRT 的 `Exists` / `DirectoryExists`，由读取本身回答存在性），不留 `File.Exists` 直调 |

**分母（11.4 要求写明）**：SRT 调用点与 BCL 回退点的逐处清单与分母见
[自评报告](自评报告.md)「SRT 使用情况」一节。

## 六、申报参数（2.1 / 3.6）

| 参数 | 本程序的取值 | 说明 |
| --- | --- | --- |
| **申报超时** | **2 分钟**（非默认值） | 标准默认 5 秒。本程序的申报属**用户交互型**（授权弹窗需要用户阅读行为、对象与理由），故显式声明较长的答复窗口；超时一律按 `Deny + Timeout` 处理（fail-closed，4.3 第 3 条） |
| **审计失败策略** | **`Buffer`**（默认值） | 审计写不下时记录进入待写队列（内存＋落盘 `audit-buffer.jsonl`），行为继续执行，恢复后按原顺序补写；**待写队列未清空前不再接受新的许可申请**（返回 `PssCode.Limit`，3.6.1 的闸门） |
| **申报频率** | **10 次/秒**（默认值） | 2.1 默认 10、硬上限 100。真实运行路径保持默认：申报节拍由用户逐条答复决定，本来到不了上限。**自检框架例外**（`Prt.App.selftest`）：它以机器速度扮演用户，显式声明到硬上限 100 次/秒 |
| **终止通知窗口** | **200 ms**（默认值） | 实际生效值取 `min(程序声明值, 宿主策略值, 2000 ms)`；窗口内只做提示，不安排任何需要超过 2000 ms 的收尾动作（6.2.4 三） |
| **心跳间隔** | **5 秒**（默认值） | 上限 30 秒。由子进程侧主动发起 |
| **许可有效期 / 可用次数** | 授权弹窗提供「允许一次」与「本次会话内允许」 | 会话内允许 → `Ttl` 24 小时（2.1 上限）、`MaxUses` 1000（2.1 上限） |

**收到 `PssCode.Limit` 时的处置**：`Limit` 是背压信号（"报得太密"），不是安全裁决。
本程序**不**在 SRT 里阻塞退让重报——那会把同步 API 变成会阻塞调用线程的 API
（打开文档、保存、粘贴都在界面线程上调用 SRT，一次退让就是一次界面冻结；
审计队列积压时更会持续冻结）。处置改为：按 3.8 ③ 一律不执行并返回可识别结果，
由调用方当场给出可读提示（如「操作过于频繁，请稍后重试」）。
反复做同一件事本就不会撞上限：4.3 第 4 条的许可缓存在频控之前判定，缓存命中不消耗限额。

## 七、审计、许可与事件存储

本程序自己的**配置类**数据（界面设置、会话记录、自定义启动图、异常日志）一律落在
**程序所在文件夹**；安全模块的**审计与守护数据**按 PSS 规范落 `%LOCALAPPDATA%`——两组落点
各有依据，不要相互套用（理由见[设计取舍 第 13 条](设计取舍.md)）。

这些文件的读写在代码里经 `PortableStorage` **直接落盘、不经 SRT 申报**（它们不属 4.6 的 63 项，
理由见第五节）。这同时是启动期的硬要求：安全模块要到 `SafetyBridge.Initialize` 才接入，
而界面设置、会话、授权的读取与旧配置迁移都发生在它**之前**——经 SRT 只会被 fail-closed 一律拒绝
（2026-09-26 实测的审计记录即为此形态），而把接入提前到一切读写之前，又会让每次启动都要用户
先点一次授权窗。两条都不可接受，故这一类必须在 SRT 之外。

**程序所在文件夹内**（便携；同机多份副本互不可见）：

| 文件 | 内容 |
| --- | --- |
| `settings.json` | 界面配色、预览主题、视图模式、语言、缩放、启动界面开关等界面选项 |
| `session.json` | 上次打开的文档路径与当前标签序号 |
| `resources\splash.*` | 用户自选的启动界面图片（从原位置复制进来，原文件删掉也不影响） |
| `prt-app-exception.log` | 未处理异常的诊断日志（**不**写临时目录） |
| `license.key` / `activations.json` | 授权与激活计数（见[部署文档 5.1](部署文档.md)） |

**`%LOCALAPPDATA%` 内**（安全模块；规范钉死的落点）：

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 审计记录 | `%LOCALAPPDATA%\Perisc\Safety\audit\` | 按日分片 `audit-YYYYMMDD.jsonl` ＋校验文件；只追加；保留至少 90 天（2.1：90 天是**下限**，不是自动删除线，只在用户主动删除时消失）。落点由 PSS 6.1.6 规定 |
| 待写队列 | 同目录 `audit-buffer.jsonl` | 进程崩溃不丢；下次启动由 `AuditStore.Initialize` 接管补写 |
| 会话内许可 | 模块内权威计数（内存） | 可在安全中心逐条或全部撤销 |
| 误报白名单 | `%LOCALAPPDATA%\Perisc\Safety\whitelist-Prt.App.json` | 条目语法（6.1.5）：`<匹配模式> <对象文本>`，匹配模式取 `exact` / `pathPrefix` / `hostSuffix` / `hostPortRange`；上限 64 条 |
| 宿主启动器存储 | `%LOCALAPPDATA%\Perisc\SafeGuard\` | 白名单（本机接入程序的申报条目，按 `programId` 分组）与 `events\events-YYYYMMDD.jsonl`（终止与升级事件）、`baseline.json`（**运行期**基准变更快照，不参与启动放行，见下）、`exemptions.json`（本地豁免）；6.2.1 要求**仅当前用户可写、可读，不得放宽为全机可写**，故**不**随程序目录存放 |

> **启动校验用的基准不在上表里**：它是程序目录下的 `Safe.data`（出厂声明，随发布包分发、
> 由 `build.ps1` 生成），因为校验基准必须与同批发布的运行体**同源**——
> 本机登记值记的是"上次在这台机器上跑过的运行体"，以它为准等于把校验权的来源放在本机文件上。
> 上表里的 `baseline.json` 只记录运行期被凭据确认过的基准变更（3.4 六），**不参与**启动放行。

便携性说明：本程序**自己的配置**随程序目录走（整目录拷走即带走）；审计、误报白名单与守护数据
属**用户数据 / 规范落点**，落 `%LOCALAPPDATA%`，不随程序目录移动。两者互不影响。
程序目录**不可写**时（例如装到 `Program Files`），配置与启动图按失败处理并明确提示用户，
**不**改写 `%APPDATA%` 等其它位置。

> 历史版本的配置曾写在 `%APPDATA%\{PRT 阅读器, PRT 工具, PSR 工具, MDP 工具}\`。首次启动时
> 程序会把其中的 `settings.json` / `session.json` / `resources\` **一次性**搬进程序目录
> （先写入并校验一致，才删除旧文件），此后不再读写 `%APPDATA%`。文本项按内容比对、
> **启动图按字节比对**——二进制内容不经文本通道搬运（否则 JPEG 会被写坏，见《设计取舍》第 13 条）。
> 旧目录中的授权凭据（`license.key` / `activations.json`）自始就不被读取，迁移**不**触碰、也**不**删除它们。

## 九、已知取舍（自查时按此对照）

| 事项 | 本实现的取舍 | 理由 |
| --- | --- | --- |
| 申报超时 2 分钟 | 非默认值，已在第六节与本清单列明并给出理由（3.4 五要求） | 用户交互型申报需要阅读时间 |
| 打印无 SRT 等效函数 | 经模块一显式申报后再调 BCL（SRT 之外唯一的收口点） | 5.4 ② 的 DEV 行未列打印方向，不属该门槛范围，但仍受 4.4 申报义务约束 |
| 不带上限流退让 | 见第六节末尾 | 避免把同步 API 变成会冻结界面的 API |

| 配置类数据（设置 / 会话 / 启动图 / 授权 / 异常日志）不经 SRT 申报 | 由 `PortableStorage` 直接用 BCL 读写 | 4.6 的 63 项里没有「读写程序自身运行期数据」这一类；且这些读写发生在启动期，那时安全模块尚未接入，经 SRT 必被 fail-closed 拒绝（2026-09-26 实测，审计记录为 `deny / 用户拒绝或未决定`） |
| 图片解码不经 SRT | 见第五节 | 5.4 ② 表内无对应方向 |
